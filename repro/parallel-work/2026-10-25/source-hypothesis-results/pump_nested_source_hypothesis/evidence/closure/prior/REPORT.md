## Walk contract and local precedence

The following applies after control reaches `0x18678`, with valid ordinary AccountInfo storage. It does not replace validation performed earlier by the context or handler.

1. `0x18688`: fewer than four remaining accounts takes the bounds/panic path at `0x19c98`. Exactly four takes the unsupported-quote construction at `0x19980`, numeric 6063 at `0x19b08`. These are distinct paths. At least five selects immediate parent account index 4 by advancing 4*48 bytes (`0x186d8..0x18730`). The initial expected mint is account 0's key.
2. The curve parser runs first. Its order is derived PDA/key comparison (`0x19ff8..0x1a010`), Pump owner comparison (`0x1a040..0x1a058`), data borrow (`0x1a2f8`), then the inherited discriminator/length-selected decoder (`0x1a378`). A failure precedes all depth and record checks. Constructor/object formatting remains opaque.
3. Immediate-parent depth d is loaded at decoded +0x98. The gate checks narrowing of d+1 before the `min(Global decoded +0x430,5)` limit (`0x60a88..0x60ae0`); numeric construction sites are 6024 at `0x60d38` and 6105 at `0x60e30`. The gate returns n=d+1. On success 1<=n<=5 and 0<=d<=4. Only then is the immediate parent's eligibility byte tested (`0x18808..0x18818`); its rejection construction is 6100. No Mayhem execution path is extended here.
4. The record buffer is 5*56 bytes. n*56 is the termination span; d*56 is the final-record position (`0x18a20..0x18b88`). The first iteration reuses the already parsed parent. Subsequent iterations copy the prior decoded quote_mint as expected mint; exhaustion before a required ancestor invokes the inherited 6109 constructor (`0x18e50..0x18f00`, helper `0x19cc0..0x19ec8`). Otherwise the same curve parser runs and its error returns immediately.
5. At position d, **before selecting Curve versus Pool**, the walk borrows account index 3 (the original prefix's quote-control slot) at `0x18fd8`. Even on the native-root branch, this borrow can fail before reserve or complete checks. A successful borrow supplies data pointer/length to root selector `0x60ee0`. For zero quote_mint, `0x60f68 -> 0x61070` returns Global.initial_virtual_sol_reserves without a quote-control data lookup. The borrow is released at `0x19078..0x19088`. Native-root membership is the scoped input condition here; this selector is not a general assertion that the terminal record must have zero quote_mint.
6. Four zero reserves select Pool, regardless of complete (`0x190b0..0x190e8 -> 0x191c0`). Any nonzero reserve selects Curve: complete must be false (6107 at `0x19728`); then token_total_supply must be at least Global.initial_real_token_reserves (6024 at `0x19c10`). Thus complete failure precedes supply underflow. Pool skips both checks. Pricing is not called until every selected group has succeeded.

The older packages already recover reserve fields, decoder defaults and arithmetic; this publication consumes those conclusions. In particular, the parser's length-compatible defaults cannot be replaced by an assumed full-length Rust deserialize. No new field layout or pricing formula is proposed.

## Ancestor depth and account consumption

The walk uses **only the immediate parent's stored depth** to determine n and the final-record position. After the ancestor copy at `0x18f28..0x18f68`, the continuation restores the saved positional counters (`0x18f88..0x18fa8`); it does not read that ancestor's depth to compare it with d-i. The curve parser validates address, owner, borrow and decoding; it has no positional-depth argument or comparison. There is likewise no repeated ancestor eligibility test in this walk. This closes the local question as an absence of those checks, not a protocol-wide proof that inconsistent ancestry is reachable or acceptable.

At each successful Curve group, the cursor advances one 48-byte AccountInfo and count decreases by one (`0x19460..0x19478`). At each successful Pool group, count must exceed three including the curve (`0x191c0`); pool/base vault/quote vault are cursor+48/+96/+144, and success advances four AccountInfos and subtracts four (`0x18cd0..0x18d88`). Inadequate Pool groups take numeric 6101 at `0x19808`, after the terminal borrow when this is the last record. No optional consumption is inferred from complete alone.

For n records and m Pool variants, successful group consumption is n+3m accounts after the four-account prefix. Total local consumption is **4+n+3m**. This is bookkeeping derived from the exact cursor updates, not a generated fixture. The append at `0x18d98..0x18df0` uses the current 56-byte position; `0x18e08` exits when the incremented position equals n*56. It checks that before another ancestor/exhaustion test. `0x18e28` also retains the five-record stop. The success path calls pricing and returns without testing the leftover account count. Excess trailing accounts are therefore not rejected **by this walk**. Full-handler acceptance of excess accounts still requires earlier context/handler and later exit admission; this package does not generalize the local result.

Records are stored nearest-parent first and root last. Within one record, emitted store order is offsets +48,+40,+32,+24,+16,+8,+0 (tag last). The active field meanings remain those in `inputs/types/result.json`; carried Pool tail storage is inactive under the inherited pricing contract. Pricing consumes records last-to-first (`0x63978..0x63a20`). After successful pricing, the walk writes output depth byte +16, reserve seed +8, and success tag +0 (`0x18ac0..0x18ad0`). This internal return record is not the persisted curve or emitted event; their prior source evidence is retained separately.

## Pool precedence refinement

The typed package gives the accepted Pool/vault schemas. The caller order now matters explicitly: after group-length and PDA derivation, `0x65eb0..0x65ff0` borrows pool, base vault, then quote vault, stopping on the first failure. Only after all three borrows succeed does `0x66110` invoke `0x65238`. Therefore a vault borrow failure can precede a wrong pool address error.

Within the validator: pool address comparison (`0x65298`) precedes AMM owner (`0x652e8`), which precedes Pool decoding (`0x65590`). Base vault key comparison (`0x65640`) precedes quote vault key comparison (`0x65bc0`), both before base token data validation (`0x65d78`) and quote token data validation (`0x65dd0`). Signed quote adjustment (`0x65e18`) follows both. Existing schema checks and inactive fields are consumed unchanged. This is ordinary create-linked acceptance only; it does not add vault mint/authority checks absent from the inherited contract, nor certify error-object bytes or allocation paths.
