## Event bytes

`wire-layout.json` enumerates all 36 fields, their in-memory offsets, ordinary wire offsets/sizes, load/store sites and byte producers. Multi-byte scalars are written little-endian; public keys are copied as 32 bytes, with no alignment padding on wire. The successful ordinary payload is **401 bytes**, including the 8-byte discriminator `bddb7fd34ee661ee` written at `0x162578..0x162590`.

The field sequence agrees with frozen declaration lines 57–92. In-memory ordering differs substantially: the string lives at E+0/E+8/E+16, shareholder vector at E+24/E+32/E+40, and the three booleans at E+0x1a0/+0x1a1/+0x1a2. The serializer returns `(capacity,pointer,length)` at out+0/+8/+16 (`0x163938..0x163968`). These are not the source declaration order or serialized offsets.

The route fixes string length 14 and bytes `multi_hop_swap` (`0x5e5c0..0x5e5d8`, `0x5e668`). The producer copies them at `0x8bec0..0x8bed8` and sets E+0x10=14 at `0x8c148`. Serializer `0x163008..0x163130` emits a u32 length followed by the 14 bytes. It checks length<=u32::MAX before appending, a guard impossible to fail for this fixed route string. E+0x28 is zero (`0x8c208`); `0x163358..0x163400` emits the zero u32 shareholder count and skips the element loop. Therefore the otherwise variable wire offsets are fixed for this producer. No shareholder semantics or excluded mode implementation is inferred from the unused generic loop.

Notable producer bindings:

- E+0x30 is the base mint key, E+0x60 the context user key, and E+0xa8 is 32 zero bytes (`0x8c098..0x8c0b8`). This route does not put a selected recipient key in the `fee_recipient` field.
- Native SOL amount/reserve slots are masked to zero for nonzero quote mint; the later quote fields retain quote amount and reserves without that mask (`0x8bf80..0x8c048`, `0x8c290..0x8c2c0`).
- E+0xc8/+0xd0 are first rate/fee amount; E+0xf8/+0x100 second rate/fee amount. E+0x138 is the configuration buyback rate under the producer's state-byte gate; E+0x140 is adapted total buyback minus adapted second-leg buyback. These remain distinct from the final u64.
- Track-volume and its four value slots are zero from the caller's zero context and producer stores. Cashback slots and shareholder count are zero. The state flag bytes are copied or tested only as shown; no excluded-mode body is interpreted.
- E+0x190 comes from decoded curve+0x70 after accrual (`0x8bf18`, `0x8c278`), corresponding to the reconstructed `creator_fee_unclaimed`. The next field E+0x198 has the separate arithmetic provenance below.

Capacity starts at 256 (`0x1624c0..0x162578`). Ordinary serialization requires one growth to 512 before crossing that capacity. `0xded0..0xe018` checks used+additional overflow, selects max(2*capacity,required,8), calls `0xd878..0xdbf8`, then updates capacity/pointer. For nonzero existing capacity and alignment1, grow allocates from the downward bump heap, copies the old capacity bytes through `sol_memcpy_`, and preserves the used prefix (`0xd8c8..0xd9e8`). Allocation failure is possible; this is not an infallible event-emission claim. Exceptional formatting calls are explicit residual boundaries below.

## Log, self-CPI and failure order

The exact successful sequence is:

1. Event construction `0x5e6a8 -> 0x8bbd0`; first serialization `0x5e6c8 -> 0x1624b0`.
2. `0x5e6d0..0x5e708` builds one `(pointer,length)` slice from that vector, then calls `0x1a04f8`. Its only call is the relocation-bound **sol_log_data**, followed by exit at `0x1a0500`. The log input starts with the TradeEvent discriminator, with no self-CPI prefix. Runtime textual rendering/base64 is outside these bytes.
3. Clone context+0x60 at `0x5e740`; serialize the same event object again at `0x5e760`. Thus logging precedes possible clone abort or second-allocation failure.
4. Prefix construction `0x5e768..0x5e800` supplies the eight bytes at `0x1b64bf..0x1b64c7` and the second event vector to `0x12ae8..0x12f80`. That iterator concatenator copies its second slice (the prefix) first at `0x12db8..0x12e10`, then its first slice (event) at `0x12e10..0x12e60`. Payload is exactly **e445a52e51cb9a1d || bddb7fd34ee661ee || serialized fields**, 409 bytes. It is not event||prefix.
5. `0x5e820..0x5e898` allocates 34 bytes and copies the cloned account key into its first32. The halfword store 1 at +32 means signer byte1 and writable byte0. One meta is supplied. `0x1a78e0..0x1a7a40` copies the data and writes the instruction: meta vector+0..24, data vector+24..48, program key+48..80. The constant at `0x1b79df..0x1b79ff` is the Pump program ID (raw bytes sealed). Allocator `0x156fe8..0x1570b8` is a bump allocator, not a program invocation.
6. `0x5e900..0x5e918` copies the 48-byte cloned AccountInfo into a one-element account-info slice. Seeds at `0x5e920..0x5e9e0` are one signer group with two slices: `__event_authority` (17 bytes at `0x1b6807..0x1b6818`) and one byte from the original route r3 saved at fp-0xa58. That account's key is the sole readonly signer meta. The byte is a supplied bump argument; this package does not prove upstream PDA validation or derive a numerical bump from it.
7. `0x1a0530..0x1a08a0` compares each meta key to AccountInfo keys with the relocation-bound memcmp wrapper. For this matching readonly meta, it attempts the **lamports shared borrow first**, releases it, then attempts the **data shared borrow**, releases it. `0x1a2ba0..0x1a2c30` and `0x1a2ca8..0x1a2d38` reject borrow word>0x7ffffffffffffffe, otherwise increment the borrow word, returning success sentinel0x800000000000001a. Failure tag is0x800000000000000b. Borrow failure returns before any invocation, through `0x1a0738..0x1a0768` or `0x1a0870..0x1a08a0`; it is not an invocation error. Writable-borrow callees were not followed because this meta has writable0.
8. On successful borrow checks, `0x1a0860 -> 0x1a1d70` duplicates the meta/data vectors and forwards the same program key, AccountInfo slice and signer groups to **sol_invoke_signed_rust**, relocation at `0x1a2068`. Return0 writes the success sentinel; nonzero goes to error converter `0x1a3a88` at `0x1a20b0`. Deallocation calls at `0x1a20e0/0x1a2108` target `0x1570b8`, a single exit. No extra data transformation is performed by that cleanup.
9. Caller `0x5e9e8..0x5ea10` tests that sentinel. Failure reaches `0x5ebc0 -> 0x19bbb8` before shared route error forwarding. Success releases the temporary clone references, checks noncompletion, selects the return vault, and clones it at `0x5f500`.

All program, prefix, seed and instruction-name bytes are sealed separately. Syscall names are bound to raw relocation/symbol/string records, not inferred from nearby `custom_panic` annotations. Their host/runtime implementations are not re-proved or executed. The log call precedes the CPI, so it does not certify successful invocation or committed settlement. No failure is claimed to commit intermediate account stores.

## clone0x10c78 and returned vault

`0x10c78..0x10d80` is an AccountInfo shallow clone under the caller-established layout. It increments the strong reference count at ***(src+8)**, stores the increment, then increments ***(src+16)** and stores that increment. If either wraps to zero, control reaches original relocation-bound `abort` at `0x10cc0`; first-counter failure precedes the second increment. There are no allocations or account-data copies and no recoverable Result tag.

On normal return it copies five words at offsets0,8,16,24,32 and bytes40,41,42 into the destination (`0x10d10..0x10d80`). The two reference cells remain shared. The final five bytes of the 48-byte ABI footprint are padding not initialized by this helper; no deterministic padding-byte equality is asserted. This is why copying the containing 48-byte record is not proof that clone writes every byte or deep-copies balances/data.

The account-provenance package identifies the successful noncompleting return as **base mint/base curve vault for buy; quote mint/quote curve vault for sell**. The pointer selected at `0x5f4d8..0x5f4e8` is cloned, then copied to result+0x30..0x60 (`0x5f570..0x5f590`). Result+0..32 is output mint; +32 is output amount; +40 is total adapted buyback. The returned AccountInfo remains a curve vault even on the final leg; it is not the user's destination. This closes clone effects for those previously established identities, not the upstream parser's remaining validation obligations.

## Final residual u64

The producer/consumer chain is exact: route r8 -> outgoing -0xfc8 at `0x5e5d8`; load `0x8bcd0`; preserve `0x8beb0`; reload/store `0x8c260..0x8c270` to E+0x198; serializer load `0x1638d8`, append `0x163920`. The fixed ordinary wire position is **393..401**, or **401..409** within self-CPI data.

For ordinary sell, pre-adapter net quote is saved in r8 at `0x5d010..0x5d020`, passed to amount adapter at `0x5d050`, and returned amount is stored in fp-0xa70 at `0x5d070..0x5d080`. At `0x5d7e8..0x5d7f8`, r8 subtracts that returned amount. For ordinary buy, original quote input is fp-0xa78; `0x5cc88..0x5ccc8` calls the same adapter and compares its returned amount; `0x5cd80` retains that adapted amount in r9. `0x5e0c8..0x5e0d8` computes original input minus r9 before fp-0xa78 is reused for the base output at `0x5e118..0x5e128`. Both differences are dominated by their no-underflow comparisons. Nonzero output-transfer paths return to these same arithmetic continuations on success; their transfer effects are inherited, not re-audited.

Thus a justified descriptive meaning is **quote-side amount removed by the amount adapter** (buy input or sell output). The settlement package proves that adapter is identity for the admitted Tokenkeg record-tag-zero path, hence this field is zero there. Naming it definitively `transfer_fee`, inferring extension economics, or asserting a historical Rust name would exceed the evidence. The earlier `pump_event` report established immediate zero stores for three legacy producers and explicitly left general semantics open. This route's nonconstant dataflow refines that bounded attribution without contradicting it or reopening those bodies. `unparsed_trailing_field` remains the frozen reconstructed source name.
