# Conditional composition of the relay record sort

The three local ledgers compose into a **manual conditional stable-permutation contract** for the frozen relay sort. The dependency order is small leaves → eager scheduler → partition by decreasing length → general scheduler → allocating wrapper. This removes the scheduler/partition cycle without assuming that fallback scratch capacity equals a fresh allocation formula. All algorithmic composition prerequisites in that scope close under the external premises below. This is neither a formal machine proof nor a runtime/security or handler-admission result. No source was changed; the mathematical fragment is review material, not integrated or historical source.

All instruction ranges here are decimal half-open ELF file offsets. Window numbers are inferred inventory windows, not established historical function identities. The input checkpoint is `517d77db988d8c63b6cf476f0be138c5a4f3128a`; ELF SHA256 is `367f07a62e3f74d358187d175cf3228848e81a56c781a9a75b9df7fed1268563`, Git blob `ee966e35883678341e4c964741f512e7fb7bc320`. `provenance.json` records full hashes, sizes, source paths and Git identities of frozen inputs, and exact seal provenance (without invented Git identities) of the four root-reviewed packages. Original reports, qualifications and seals are unchanged in `evidence/`. `result.json` records the proof dependency graph, imports, corrections and hashed byte ranges.

## Contract and explicit external premises

A record is three u64 words: payload/index at +0, key low at +8, key high at +16. Define K=2^64*high+low. Comparisons consume only bytes [8,24); all moves carry [0,24). The contract is a permutation of complete record occurrences, sorted by decreasing unsigned K, with original occurrence order retained on equality. Original index is not a comparator tiebreaker. No account key or weight is read by these sort windows. Distinct occurrence labels in the proof are mathematical, not an extra field.

For scheduler T(B,n,S,C,e), require n>=21, 24*n<=2^63-8, C>=85, C>=floor(n/2), and valid nonwrapping 8-aligned record and scratch extents [B,B+24n), [S,S+24C). These extents are disjoint. B,S>=24 permits actual base-minus-record arithmetic. Require usable, separate VM call frames and ancestor witness storage; stack scratch may reside in its allocating ancestor frame but is disjoint from that frame's other live control/spill regions and all callee frames. Scratch contents initially are arbitrary. Nothing requires C to equal a function of this n, nor C<=n. A represented scratch extent must itself be valid; an arbitrary huge integer C does not establish memory validity.

For partition Q(B,k,S,C,d,U), require C>=85 and k<=C, the corresponding valid subrange of input, the same scratch/frame separation, and U either null or a live immutable record outside the write extents with every input key <=K(U). Initial scheduler calls use U=null. For k<=32 the base proof needs only C>=k+16 when k>=2; k=0 or1 returns directly. Depth values originating here are d=2*floor(log2(k)) or their nonnegative decrements, or zero for eager leaves. No arbitrary forged metadata contract is asserted.

External premises retained explicitly:

* Valid live allocations and a coherent descending heap cursor; size multiplication helper 752688 has the unsigned wide-multiply contract used by the wrapper. The allocation analysis is inherited from relay_large_sort, not a new proof of the helper or global heap ownership. Successful allocation and valid cursor/frame ownership imply the separation described below. Failure semantics are not erased.
* CALL 743376 performs nonoverlapping byte copy, including zero length, preserves ABI, and has no other writes. Its syscall/runtime implementation is not established here.
* The decoded instruction semantics and VM ABI hold: u64 modular arithmetic, unsigned branch predicates, r6..r9 and live caller frames preserved across calls except specified outgoing argument slots. Enough stack, call-depth and execution budget exists; logical termination does not guarantee runtime budget acceptance. Ancestor frames remain live while their pivot witnesses are used.
* Caller supplies initialized records and valid extents. Handler admission, account checks, allowed weight/count domains and external effects remain outside this theorem. These are not implied by the heap constants or hashes.

No claim is made about failure-path output, resource-equivalence of a library sort, historical source identity, byte-identical rebuilding, or any of the four original whole-file comparisons (all remain false).

## Capacity inequalities and sizing, including inherited fallback

Use F(N)=max(floor(N/2),min(N,333333)) for wrapper allocation; use M(n) for the scheduler's minimum-run sizing. They are different quantities.

At [36192,36800), N in 21..85 yields C=85 and separate stack scratch [wrapper_fp-2048,wrapper_fp-8). N>=86 yields C=F(N)>=86 after checked allocation of 24*F(N). F(N)<=N, F(N)>=floor(N/2). Specifically F=N for 86..333333; F=333333 for 333334..666667; F=floor(N/2) thereafter. The temporary max(F,48) cannot change the heap branch. Thus every wrapper success satisfies C>=85 and C>=floor(N/2). We do not infer feasibility for all these mathematical counts.

At [36872,36976), n<=4096 gives M=min(ceil(n/2),64), hence 1<=M<=64<=C. At [730072,730488), spread/complement/popcount produces c=clz64(n); b=(64-c)>>1=floor(bit_length(n)/2), and M=floor((2^b+floor(n/2^b))/2). For n>4096, b>=6 and n>=2^(2b-1). Consequently 2^b<=floor(n/2) and floor(n/2^b)<=floor(n/2), so 1<=M<=floor(n/2)<=C. Under n<2^59, b<=29 and the sizing sum fits u64. This verifies the previously imported sizing consequence independently of C's exact origin.

The reusable scheduler premises are therefore C>=85 and C>=floor(n/2), together with valid extents; M<=C is a derived fact. The stronger uniform C>=85 is convenient for this graph, not advertised as minimal. Every small call k<=32 has C>=85>=48>=k+16. Every deferred call has k<=C, giving Q's stronger C>=max(k,85), rather than relying on the insufficient isolated condition k<=C for small leaves.

A partition fallback occurs only for current k>=33 at [47200,47248). Incoming Q already has k<=C; every strict child, strict continuation and >= suffix has smaller length and retains the same S,C. Hence fallbackC=C>=85 and C>=k>=floor(k/2), and its extents remain disjoint. Apply the generalized eager theorem with these inequalities. **There is no allocation in this fallback and no equation fallbackC=F(k) or fallbackC=85.** Larger inherited capacity is harmless: eager mode never creates deferred runs, and all memory accesses are bounded by run lengths or the smaller merged run, not by blindly filling C records.

## Leaf and seed review: no scheduler premise

[44800,44944) returns for k<2, checks k+16<=C otherwise, splits m=floor(k/2), h=k-m, and forms adjacent scratch halves. For 2..7, [47256,47360) copies one record into each half. For 8..32, both halves have at least four records and [44944,46072), [46080,47192) initialize four-record stable seeds. Source and scratch remain disjoint.

The seed selector was reviewed as an algebraic ordering argument, not accepted because the old verifier passed. Stable pair(a,b) orders descending with strict swap only. Write (Ah,Al)=pair(a,b), (Bh,Bl)=pair(c,d), x=[Ah<Bh], y=[Al<Bl]. The first is x?Bh:Ah; last is y?Al:Bl. The central candidates are respectively (Al,Bh), (Bh,Bl), (Ah,Al), (Ah,Bl) for (x,y)=00,01,10,11, followed by stable pair. In every case all four occurrences are distinct and used exactly once; the selected first dominates both central candidates and both dominate last. Same-pair central candidates retain stable pair order; cross-pair candidates put A before B on equality. First prefers A on equality, last prefers B, so equality with extremes is also stable. The pointer selections [45552,45872) and their second-half counterpart [46608,46984), plus whole-record stores, implement these equations. No equality order depends on comparing payload.

The insertion halves [47424,47984) and [47984,48728) use a saved whole record and a hole that decreases only across strictly smaller predecessors. At each outer step i, initialized scratch [0,i) is the stable sorted permutation of the immutable source prefix. The saved payload plus occupied cells preserve every occurrence during shifts. The index-zero check precedes any predecessor-before-base load. Equal predecessor stops the shift, so insertion is stable. The second half's modular offsets 24(kseed-i+s) cancel against 24*kseed before addressing; these offsets are not interpreted as independent pointers. Each store is inside its half. The capacity slot fp-144 is reused in the leaf after its guard; it need not remain a capacity on return, because caller capacity is stored in a different live frame and a leaf never resumes large partitioning within this frame.

For the dual-ended merge [48392,49760), define T as the unique stable merge of the two immutable scratch halves of lengths m and h=m+e, e in {0,1}. Before paired step t<m, front consumption a+c=t and back consumption u+v=t. Each individual count <=t<m<=h, so all four candidate pointers are inside initialized halves. Front-alone stable merge yields T[t]; back-alone stable merge yields T[k-1-t]. These independent inductions need no assumption that combined front/back remaining counts are both positive. Their ranks are distinct because t<k-1-t. Therefore the selections do not duplicate any occurrence, even if another traversal has inspected an already selected element. Writes to input cannot alter scratch candidates.

After m pairs, remaining counts l=m-a-u and r=h-c-v are nonnegative with l+r=e. For odd k, [49528,49728) selects LF iff LF<LB+24 (l=1), otherwise RF, and advances exactly that front cursor. Both parity cases end with LF=LB+24 and RF=RB+24, precisely the assertions [49728,49760), not necessarily the original half endpoints. All k output positions are distinct and filled; all moves are three-word moves. This discharges merge exhaustion, permutation, stability and memory bounds. Logical variants are finite insertion indices/hole positions and m-t. Thus L, the <=32 leaf contract, is independent of Q for large lengths and independent of scheduler T.

## Eager scheduler first

Review of [39664,41152) closes the imported discovery premise: EOF emits the empty odd sentinel; otherwise remaining count is positive. If the short-run path is selected with eager set, [39800,39864) calls Q on min(remaining,32)>0 with depth=0, U=null and unchanged S,C; by L it returns sorted. The tag becomes 2*k+1. Natural discovery reads adjacent keys inside the remaining extent, continues a non-increasing run or a strictly increasing run, and reverses only the latter at [40880,41120). Equal records therefore are never reversed. A too-short recognized run is routed through [40592,40752) to eager leaf emission; its eager-false alternative emits min(M,remaining) as an even tag without moving data. Each route consumes a positive bounded prefix and terminates.

All eager tags are odd, starting with sentinel 1. At [37752,37792), deferred concatenation requires both tags even; it is unreachable. The optional large sorts at 38336 and 38864 are gated by an even tag; final 42144 is likewise gated at 41704. They are unreachable in eager mode. M is still computed, but no large Q contract is imported. The only Q call is the leaf at 39864, already proved.

The run-stack invariant then applies using only discovery, leaves and inline one-ended merges. Stored real runs and current cover exactly the processed prefix as disjoint adjacent stable intervals; tags encode 2*length+sorted. Saved next run remains outside each collapse. Before merging a,b, min(a,b)<=floor((a+b)/2)<=floor(n/2)<=C. Copying the smaller run into scratch gives the forward gap R-O=remaining_scratch or backward gap Oend-L=remaining_scratch; while scratch remains, writes cannot destroy unread in-place source. Exhaustion is checked before another comparison. Equality takes left forward and right backward, yielding the same stable union. These merges [37104,37488), [38920,39608) import only memcpy/ABI, not Q.

At [41152,41616), let x be processed length, u=2x-Lcurrent, v=2x+Lnext, q=ceil(2^62/n). For a nonterminal boundary 0<=u<v<=2n. Since n<2^59, q*2n<2^63+2n<2^64; no multiplication wraps, qu!=qv, and priority clz64(qu XOR qv) is in [0,63]. The initialization sum n+2^62-1 also fits. Pop removes every priority >=p before pushing; stored real priorities are strictly increasing. At most 64 exist, so E indices 0..64 occupy [fp-600,fp-80), P indices 0..64 occupy [fp-66,fp-1). A transient count h=65 must pop before another push and is never an array index. Spills/outgoing slots remain separate under the frame premise. No optimal-tree assumption is needed.

Discovery increases x toward n; each pop decreases stored run count. At EOF priority 0 collapses all real entries into the current run covering [0,n), and its odd tag returns at 41712. Eager T therefore terminates and returns a stable permutation using only L, with the generalized capacities above. This is the first scheduler theorem, obtained before any large-Q theorem.

## Partition induction, then general scheduler

Now prove Q by strong induction on current length k. For k<=32 use L. For k>=33 with exhausted low32 depth, [47200,47248) calls eager T on this exact current extent with inherited S,C and returns; the preceding theorem applies without invoking Q at this large length.

All base selections return one candidate pointer, only local stack is written, and q decreases. Thus the pivot is a live original record; median quality is unnecessary. Saved pivot triple [42944,43032) remains in parent frame fp-72 while a child uses it as U.

The strict partition [43160,43856) maintains after t inputs, ktrue true records in encounter order at scratch front and t-ktrue false records in reverse encounter order at scratch back; stores target unused indices ktrue or n-(t-ktrue)-1. The original pivot is processed at its original position, exactly once. Copy front forward and back backward restores order within each group. The pivot is false, hence ktrue<n. If ktrue>0, the suffix child at43960 has length n-ktrue<n and bound U'=saved pivot; the prefix continuation has length ktrue<n and retains prior U. Both retain S,C and are disjoint from each other and U. Their induction hypotheses apply.

If strict ktrue=0, double reversal restored the entire original sequence exactly, so the original pivot index remains valid and all keys<=pivot. Alternatively the direct bound branch [43032,43160) combines pivot membership p<=U with its p>=U test to give p=U and again all keys<=pivot. Thus either entry to >= partition [43992,44680) has an all-equal true prefix. This partition is stable by the same scan argument; pivot is true, so prefix length>=1. The skipped prefix is already sorted; the remaining suffix has smaller length and U cleared. Neither branch splits equal keys between groups. Strong induction therefore supplies stable global order and complete permutation. Length decreases on every recursive or tail subproblem; depth also decreases without low32 underflow and bounds recursion along actual root calls. Scratch capacity and all ancestor bounds survive. Q is now proved without assuming a general scheduler theorem.

Finally rerun the scheduler induction for arbitrary eager flag. Deferred discovery emits length<=M<=C.
