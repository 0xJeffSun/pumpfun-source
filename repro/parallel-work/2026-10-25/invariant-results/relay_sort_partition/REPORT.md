## Contract and representation

Write Q(B,n,S,c,d,U) for the call at42160: r1=B, r2=n, r3=S, r4=c, and r5 points to a live caller frame with d at[r5-4096] and U at[r5-4088]. At[42160,42232), these become B=r9, n=r8, S=r6 and[fp-80], c=[fp-144], d=r7, U=[fp-136] (d and U are read only when n>=33). A record is exactly24 bytes: opaque payload/index at+0, unsigned key low limb at+8, high limb at+16. K(x)=2^64*hi+lo. No index comparison occurs in the assigned partition.

Required memory preconditions: valid aligned input [B,B+24n), writable scratch [S,S+24c), disjoint from each other and active stack frames; endpoint arithmetic does not wrap; U is null or points to a live immutable readable record disjoint from those writes. When U is nonnull, forall x in input, K(x)<=K(U). U is a bound witness; it need not point to the physically preceding element. The stronger sufficient capacity condition c>=max(n,48) covers both partition n<=c and the later small-leaf n+16<=c test for2<=n<=32. This is a precondition of the conditional theorem, not a fact deduced from a sort name or heap size. Standard call-frame separation, r6..r9 preservation, and ordinary nonoverlapping byte-copy semantics for743376 are imported ABI/primitive assumptions.

Local postcondition, assuming called leaves/fallback return as stable permutations on their supplied extents: Q returns a stable descending permutation, modifies no records outside its extent, and consequently preserves every external upper bound. The proof below discharges the partition step of that induction. It does not discharge the leaf/merge base or the scheduler premise.

## Pivot membership, lifetime, and exact partition proof

For inline selection, 0<=4q<7q<n for n>=33. For window57, interpret its fourth argument q as the sampling span. If q<8, [35208,35648) selects one of its three input pointers and writes only its own stack. Otherwise q'=floor(q/8); recursive triples based at each of the original three candidates add offsets0,4q',7q' records ([34952,35208)). A selected pointer from a span q lies within that candidate's q-record block: the largest offset7q' plus a recursive offset at most q'-1 is <=8q'-1<q. Induction on q gives membership and termination; q'<q. At the top B+7q plus at most q-1 is below B+n because8q<=n. No median-quality assumption is needed for this proof. [42888,42944) therefore computes exact j in[0,n), without rounding a foreign pointer into the array.

For either partition predicate, after t consumed records let k be the true count and f=t-k. The cursor r1 is S+24(n-t). For the next false record, the decrement followed by +24k targets index n-t-1+k=n-f-1; for true it targets index k. Until t=n these are unused slots: the remaining gap has size n-t. Every store copies all three words ([43448,43480), [44280,44312)); pivot stores do too. The two scanning segments [0,j), pivot j, [j+1,n) cover each record once. Counts satisfy0<=k<=t<=n, so stores remain within n scratch records. The pivot stays untouched because scratch is disjoint. The explicit pivot copy avoids classifying it with a potentially changed scan cursor and respects its original position.

At t=n the front and back regions abut and cover scratch exactly. The front copy and backward walk over the reverse false subsequence restore encounter order in each group. Their destinations are disjoint and exhaust input. Loops terminate: each scan advances one record toward its fixed stop, and each reverse copy advances its counter to the fixed false count. A zero false count skips the loop. The strict pivot guarantees k<n; the >= pivot guarantees k>0. No probabilistic pivot balance or runtime experiment is used.

For strict k=0, the first partition produces the exact original sequence, not merely a permutation: it reverses all records into scratch and reverses them back. Thus reusing j and B+24j in the second partition is justified. Moreover every key<=p, so its >= front group consists entirely of equals. For the U branch, pivot membership gives p<=U, the branch gives p>=U, hence p=U and again every key<=p. These are the two independent justifications for the skipped group. Without either justification, >= would collect unequal keys and skipping it would be unjustified.

The strict child’s U pointer is **fp-72**, not B+24j and not the eventual boundary element. [42960,42992) stores index, low, high there before copying. During child execution, its ancestor frame remains live and its own frame is separate; its input and scratch cannot overwrite the bound witness. After return, the parent may overwrite its pivot copy on the next iteration because that child is finished. The parent's inherited U at[fp-136] is not overwritten in the strict continuation. The >= suffix explicitly clears U at44752. Every remaining subsequence still satisfies any prior numeric upper bound because a permutation changes no keys.

Equal keys never straddle a strict > / <= boundary or >= / < boundary. Stable recursive results therefore compose with stable partitions into a stable permutation. The >= skipped prefix is already sorted because it is all equal. Sorting it would be unnecessary. This proves the partition composition step conditional on the base/fallback contract.
