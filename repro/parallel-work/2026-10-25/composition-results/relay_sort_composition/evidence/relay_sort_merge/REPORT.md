## Contract and consumed bytes

Let D be the original record array, S the scratch array, n the leaf count, m=floor(n/2), h=n-m, B=S+24m, and E=D+24m. A record is (payload index, low limb, high limb), each an unsigned 64-bit word. Its key is 2^64*high+low; numeric comparisons never consume payload. Comparator reads are record+[8,24), whole moves record+[0,24). Stable ordering means descending key, retaining input occurrence order on equal keys. Occurrence tags used in this proof are mathematical labels, not additional machine fields or comparator inputs.

For 2<=n<=32 require D+[0,24n) readable/writable, S+[0,24C) readable/writable, C>=n+16, and these intervals mutually disjoint and disjoint from live frame/control storage. Pointers are 8-aligned; extents and cursor arithmetic must not wrap the u64 address space. S-24 may be formed as a terminal pointer but is never dereferenced; assume S>=24 (actual stack/heap mappings satisfy this). Source/scratch aliasing, including D=S, is NOT supported by this proof. Insertion intentionally shifts overlapping adjacent records *inside* scratch, using individual u64 loads/stores; it is not memcpy with an overlap assumption.

## Exhaustion, disjoint selection, memory bounds and permutation proof

Let A and R be the two sorted scratch sequences, lengths m and h=m+e, e in {0,1}. Define T as their unique stable merge, using original occurrence position to distinguish equal values. This order is only a proof device. Front selection takes the earliest equal candidate (left before right); back selection takes the latest equal candidate (right before left). Within each run front/back traversal respects the same occurrence order.

After t complete pairs define a,c front consumptions from A,R and u,v back consumptions from A,R. Then a+c=t, u+v=t. Header pointers are LF=S+24a, RF=B+24c, LB=S+24(m-1-u), RB=B+24(h-1-v); OF=D+24t, OB=D+24(n-1-t).

For every iteration t<m, individually a,c,u,v<=t<m<=h. Therefore all FOUR candidate reads are in their own initialized scratch halves, even if one run has already had all its occurrences selected between the two ends. Front alone cannot exhaust a run before its m-th choice: fewer than m previous front choices, each run initially has >=m. The same is true for back alone. Hence ordinary two-sequence merge induction applies separately to front and back without sentinels: front choice at iteration t is T[t]; back choice is T[n-1-t]. The independent proofs may inspect a record previously selected by the other traversal; inspection is safe and does not imply reselection.

Since t<m and n=2m+e, t<n-1-t. All front ranks [0,m) and back ranks [n-m,n) are disjoint. Thus no occurrence is selected twice, including ties, and all selected words belong to one preserved occurrence. This simultaneously proves a+u<=m and c+v<=h. Combining traversal counts gives remaining counts l=m-a-u>=0 and r=h-c-v>=0, with l+r=n-2t. This rank argument, rather than an incorrect assertion that each side always has an unconsumed candidate, handles combined exhaustion.

OF and OB writes are distinct and within D+[0,24n) for t<m. Source S is immutable during merge because D and S are disjoint; the early front write cannot change a later back candidate. Selection only copies complete records; payload and both limbs travel together. Front/back cursors may become one-past or one-before after the LAST pair, but no further four-candidate read occurs. Before every candidate read the individual traversal bounds above hold. No record is dropped because after paired output only e occurrences remain and the central logic below consumes exactly those.
