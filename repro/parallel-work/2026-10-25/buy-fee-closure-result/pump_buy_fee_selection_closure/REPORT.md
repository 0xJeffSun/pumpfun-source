# Ordinary BuyV3 fee selection closure

**Conditional fee-body/source closure; not unconditional handler acceptance.** The ordinary BuyV3 caller reaches the same selector and arithmetic as the published route contract. Its threshold uses **actual base-mint supply**, its quote classification uses three exact nonzero constants plus zero, and its creator override is a gated **u64**. `proposed/buy_v3_fee.rs` implements the complete numeric decode/selection/fee fragment. `minimal.diff` corrects only BuyV3 in the sealed partial proposal and carries forward the event report's accrual correction. `after-event.diff` is the alternative delta when the event proposal is already applied. Apply one delta, not both. Both target the same `proposed/trade.rs`; place the helper beside it. No legacy/general-route/nested source is modified.

Fixed checkpoint **476ecf0d31a8dae66dc6e2fb0a97f19d4f163e40** was read with `git show`, including both boundary documents, original ELF and assembly. The pending publications are separately sealed inputs, not misrepresented as this checkpoint's source. Original ELF SHA256: `7a19affaa2c6187e04a5fe0ea298cee81fa5eb8c24cfcc30d85f615e89f7b02d`, size 10,485,715. Inferred windows are descriptive intervals, not historical function identities. All addresses below are half-open ELF file/virtual offsets; signed encoded call/branch operands govern over displaced annotations.

## Independent identity and actual caller composition

Wrapper [0x1286c8,0x128c28) loads literal [0x1b7dd3,0x1b7de5), exactly `Instruction: BuyV3`, at 0x1286f0 and length18 at 0x128700. Call 0x128808 resolves to parser 0x102578. After parsing, 0x1288f8..0x128930 supplies the context, amount, max and optional flag to **0x147ba0**, not an adjacent inferred body. The body ends at 0x1489f8, with common return 0x148600..0x148620. Source `lib.rs:100` at the fixed checkpoint independently routes `buy_v3` to `trade::buy`; the corresponding baseline source interval is lines114–181. This is not legacy buy.

Define K as body r9, loaded from outer context+8 at 0x147bc8. K+0 is Global wrapper, K+8 is base-mint wrapper, K+0x28 is curve wrapper, K+0x40 is user AccountInfo, K+0x60 is FeeConfig wrapper. Ordinary means nonwhitelisted user, non-Mayhem, noncashback and admitted ordinary Tokenkeg base/quote (or admitted native quote relation). Amount and reserve validation, optional-fill selection, quote pricing and settlement remain the inherited proposal's domain, not newly certified acceptance.

The first quote return low word becomes r7 at 0x148278; its high-word/narrowing checks precede fees. At 0x1482f8 r2=K, 0x148300 r3=r7, then **0x148308 -> 0x7fde8**. On success the four u64 words copied at 0x148350..0x148380 are F1=(protocol amount,creator amount,protocol rate,creator rate). No curve write has occurred.

For crossing, **0x148480 -> 0x82af8**, with r2=the same K at 0x148470. The callee saves it at fp-0x160 (0x82b18), prices/narrows residual quote into r9, restores K into r2 at 0x82fe0, passes r9 as r3 at 0x82fe8, then **0x82ff0 -> 0x7fde8**. Success copies the second four words to residual-record +8,+16,+24,+32 at 0x83020..0x83078. This is F2, followed by residual base/quote and pool reserves. The body does not enter settlement 0x83c00 until 0x1488c0; the inherited settlement/store ledger places reserve writes there. Both fee calls therefore see pretrade reserves, mint supply, curve quote/creator/override, Global permission and FeeConfig. The proposed helper explicitly receives one immutable `Pretrade` and decoded config on both calls; it recalculates threshold/selection for F2 rather than charging the aggregate quote.

Within 0x7fde8, user-key bytes are compared against Global wrapper+0x288 (0x7fe08..0x7fe98). Encoded equality goes to 0x800f0, which returns all four fee words zero. We exclude that branch. The normal branch loads FeeConfig from K+0x60 and its AccountInfo from wrapper+0x88 (0x7fea8..0x7feb8). It clones reference-counted handles, obtains serialized data length through **0x7fff8 -> 0x1a2a68**, and computes the threshold through **0x80028 -> 0xa08f8**. A failing threshold forwards an existing error before selection. On success, outgoing -0x1000=L, -0xff8/-0xff0=threshold low/high, -0xfe8=quote amount. r2=Global wrapper+8, r3=curve wrapper+8, r4=FeeConfig wrapper itself; **0x80180 -> 0x89ec8**. FeeConfig has no extra +8 wrapper adjustment. The length helper returns AccountInfo data RefCell+0x20 after checking borrow state; it does not return vector capacity or reconstructed serialized prefix length. Borrow-conflict panic/reference-count overflow are bounded runtime premises, not silently reclassified as fee errors.

## Mint supply and FeeConfig decode provenance

BuyV3's parser calls **0x102738 -> 0x288**, allocates/copies 0x80 bytes, saves the result at fp-0xa60, and publishes it at K+8 (0x105b58..0x105b68). Its error label at 0x102810 is `base_mint`. Thus the third argument of 0xa08f8 is the actual base-mint wrapper. The ordinary decoder chain is 0x330 -> 0x32d8, 0x3508 -> 0x1862f0, 0x186348 -> 0x1940c0. Wire supply at +36 is loaded 0x1941d0 and stored at result+40 at 0x194338. The staging/ordinary 82-byte success path and wrapper copy preserve it at mint wrapper+0x28. Only the published ordinary decoder windows are consumed; the extension gap is excluded.

At 0xa0900 the threshold helper loads decoded curve+0x40 (virtual base X), rejecting X=0 via 6026 at 0xa0b68. At 0xa0910 it selects mint wrapper+0x28. The mode byte at decoded curve+0x9a is zero in scope, so the encoded branch at 0xa0920 skips the alternate curve+0x60 pointer. It loads supply S at 0xa0938 and virtual quote Y at 0xa0940. Multiply 0xa0978 -> 0x1b55c8 uses zero high limbs; divide 0xa09b0 -> 0x1b4088 divides by (X,0). Thus **T=floor(S*Y/X)**, unsigned u128, with both limbs forwarded. There is no equality requirement between S and curve.token_total_supply, and no threshold narrowing to u64. The partial proposal's curve-supply shortcut is removed only in the ordinary branch.

FeeConfig parser composition is independently different at its outermost step but converges: **0x103010 -> 0x3cc8 -> (0x3ce0) 0x133e0 -> (0x13498) 0x92d0 -> (0x9560) 0x1156f0 -> (0x1159c8) 0x1159d8**. The boxing helper copies the 0x90-byte result without shifting decoded fields. Parser fp-0xaa8 at 0x103038 is reloaded at 0x105ab0 and stored K+0x60 at 0x105ab8. The error label is `fee_config` at 0x1030c8. This proves actual same-callee applicability of the published decoder; it is not a name-based import from the route.

Complete numeric decoding contract (allocation/opaque error-object premises below):

| Wire bytes, including discriminator | Meaning / order |
|---|---|
| 0..8 | exact `8f3492bbdb7b4c9b`; length<8 ->3001, mismatch ->3002 |
| 8..9,9..41 | bump byte, admin32; combined 33-byte prefix required |
| 41..49,49..57,57..65 | flat LP/protocol/creator, each LE u64 |

Each record is LE threshold u128 followed by LP/protocol/creator u64. Minimum parsed prefix is **97+40(n+m)**, with arbitrary trailing bytes accepted. Every short payload/count/record/exotic-tail path maps to 3003. Neither vector may be omitted/defaulted simply because a quote won't select it. Count zero succeeds. Initial capacity min(n,102) is not a count limit. Records retain order; no rate cap, threshold sort, monotonicity check or 2512/4072/4096 decoder gate exists. Allocation/growth uses the separate runtime dependency, not a fabricated numeric decode error.

The account reader additionally requires an account (3005), one of two exact owner-key comparisons (otherwise3007), and the original account-state predicate on the first-owner branch (false3012); borrowing/conversion failures retain their own paths. These account checks are retained in `prior/fee-REPORT.md` and `evidence/fee_account.asm`; `decode` accepts an **already admitted** byte slice and is not an owner/PDA/executable/alias validator. BuyV3 parser has further PDA/context checks outside the consumed slices. The helper is not a replacement for them.

Decoded first vector is cap/pointer/len at +0/+8/+16, second +24/+32/+40, admin+0x30, flat+0x50/+0x58/+0x60, exotic+0x68/+0x70/+0x78, bump+0x80, AccountInfo+0x88. Do not confuse wire offsets with decoded offsets or account length with the parsed prefix.

## Selector and arithmetic order

After threshold production, selector 0x89ec8 first tests **L>=2512** (otherwise6097 at 0x8a268). Then compare **stored curve quote key** (decoded+0x20), not an external `is_sol` boolean:

| Quote key | Selected record |
|---|---|
| zero, exact ELF key at0x1b5cc8, or exact key at0x1b5a88 | first vector |
| exact key at0x1b5d28 | second vector if L>4072; otherwise forced empty ->6096 |
| all other keys | exotic iff L>4096 and any of its LP/protocol/creator words nonzero; otherwise flat |

`proposed/buy_v3_fee.rs` contains the exact three 32-byte constants, verified against the ELF. The first is WSOL under the inherited key correspondence; names for the other keys are unnecessary to the contract. All nonnative quotes are **not** second-table quotes. At L=4072 the second-table branch errors even if the decoded vector is nonempty; at L=4096 an exotic record is ignored. LP alone can enable exotic, although this selector only charges/returns protocol and creator.

Table helper **0x8a310 -> 0x89b48** rejects empty6096. If T<first.threshold it immediately selects first. Otherwise it scans backwards and returns the last record whose threshold<=T, default first. Unsigned u128 comparisons inspect high limb then low on equality. This differs from largest-threshold selection on unsorted input. Equality and duplicate thresholds have the original reverse-scan behavior. Flat/exotic selection does not require a nonempty vector.

For every successful record selection, 0x8a378 loads a **byte** at Global decoded+0x436. Zero branches to 0x8a3a8. Otherwise 0x8a390 loads **eight bytes** at curve decoded+0x68; nonzero replaces creator rate C at 0x8a3a0. There is no rate maximum here. This is the event report's gate, applied once inside `ordinary_leg`; the prior unconditional ordinary override is removed, not applied again outside the helper.

Protocol amount Fp=ceil(q*P/10000) is computed first at **0x8a3c8 -> 0x88f90**. The helper performs exact u64-by-u64 multiplication into u128, then **0x89000 -> 0x88908** checked ceiling, then high-word narrowing. For u64 inputs, `(2^64-1)^2+10000<2^128`; the generic ceiling's add/subtract/divide failures cannot occur. A result>=2^64 enters6025. Only after protocol success does 0x8a430 compare creator bytes to zero. Zero gives Fc=0 with no creator fee call; nonzero calls the same helper at0x8a480. **C is preserved even when creator is zero**, including TradeEvent and PostCompleteBuyEvent rates. There is no rate-sum cap, u16 truncation or rate-zeroing substitute.

Success ABI: `(tag0,Fp,Fc,P,C)` at offsets0,8,16,24,32. Selection/threshold failures and helper failures forward existing payload words under their caller's error tag; numeric codes do not determine original error-object layout/log strings. F1 and F2 are each this four-u64 tuple, not wire-event field order. Error order within each call is threshold division, length6097, selected-table6096, override, protocol narrowing6025, creator-zero comparison, optional creator narrowing6025. F1 precedes residual pool/pricing/narrowing; F2 occurs only after those succeed. Combined cost/max and all settlement follow both. No fee is computed on q1+q2. This preserves per-leg ceilings and independent rates, even though successful deterministic pretrade selection implies P1=P2,C1=C2.

## Source application and bounded premises

`minimal.diff` is against `prior/partial-trade.rs` (whole SHA e531dedf…), not the checkpoint's earlier implementation. `after-event.diff` is against sealed `prior/event-trade.rs`. Both preserve all source outside `pub fn buy` byte-for-byte. The source uses actual `a.base_mint.supply`, actual serialized length, exact stored quote-key comparisons, complete mandatory decode, threshold's u128 result, correct table rule, and two `ordinary_leg` calls. F2's event explicitly reads F2 rates. Creator-zero suppression affects amounts only. The event proposal's final post-both-legs creator accrual remains preserved. No event metadata is silently filled in by this task.

The minimal correction is **not ready for unconditional root application**:

1. Original FeeConfig decoding occurs during context parsing, before body checks. The preserved `SellV3` proposal context is not replaced here; the local helper decodes at the fee-use point. The numeric decode contract is complete under its runtime premises, but malformed-account/error precedence across handler checks is not equivalent until the context owner invokes it at original admission. For the stated source domain, FeeConfig is already original-admissible and decodable. This is an explicit application precondition, not a success stub or permission to accept invalid accounts.
2. The source maps numeric constructor arguments to `ProgramError::Custom` through a visible adapter. It preserves the numeric decision order but **does not reproduce Anchor error diagnostics, origin coordinates, payload object layout or allocator/destructor failures**. Root must integrate the actual error representation before claiming diagnostic equivalence. No invented checks or padding/locations are supplied.
3. AccountInfo reference counts and length reads require ordinary readable accounts, nonconflicting data borrows and successful bounded allocation/copy/comparison. The mint is an admitted ordinary82-byte mint with a trusted decoded supply; excluded extension paths are not imported. The chosen Rust Vec allocator need not reproduce failure/growth traces; those are bounded framework/runtime premises. Both fee calls see identical config bytes/length and pretrade fields; no intervening mutation/CPI is inserted.
4. The wider proposal still needs volume admission/initialization and live metadata, native settlement/reload/alias/zero-transfer reconciliation, remaining context/PDA checks, and event report's late residual arithmetic order correction. This patch intentionally leaves those visible. Unconditional handler equivalence, unsupported modes/quote admission, security sign-off, historical source identity and whole-program equivalence remain unclaimed. Positive-denominator and ordinary pricing/settlement premises from the partial proposal still apply; the helper separately expresses zero-threshold-divisor6026 without asserting the whole handler can reach it after every preceding quote check.

No build/typecheck, SBF execution, target/runtime probe, transaction fixture, network call, signature/history change, binary edit, parent edit, staging, commit or push was performed. No handler/completion count changes are proposed. Root must review and separately test an actual integrated implementation.
