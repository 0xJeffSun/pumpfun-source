### Authority, account relationships and CPI identity

Existing-state admin paths use a typed mutable GlobalParams PDA with `has_one=admin` and a signer; trades and trader sweeps use the corresponding trader relation. `CheckedSystemProgram::try_from` checks ID before delegating executable validation. Client helper metas are readonly nonsigners. Its empty duplicate-key list is specific to this readonly wrapper, not a program-wide alias exclusion.

Trade state is derived from the supplied mint; there is no independent `has_one=mint` on the stored state field. The ordinary PDA contract and excluded lifecycle history must not be conflated. Burn is permissionless after its deadline, with state, curve and custody constraints; it is not evidence of an unrestricted mint authority.

The six candidate trade CPIs are recorded account-by-account in `cpi-contracts.json`: legacy Pump buy/sell use 18/16 accounts; Pump v2 uses 27/26; AMM uses 25/23. Fixed destinations are the source's PUMP_ID and AMM_ID. The sol-vault PDA is the fixed signer. AMM's final two buyback metas inherit actual outer signer/writable flags; the extra Mayhem-derived `pool_v2` context account is not forwarded. No trade forwards `ctx.remaining_accounts`. Legacy sell propagates Pump errors; other Pump trade callers map them to 6008, AMM callers to 6010. These are candidate source vectors, not a fresh proof of the captured target implementations.

Pump fee/global/creator/volume relationships and AMM pool/mint/vault/fee relationships are incompletely checked locally and delegated to fixed external programs. Typed ownership is not a canonical relationship proof. Wrong or aliased input failure may occur at different stages. Anchor duplicate handling, runtime privilege unions and downstream checks were not expanded or exhaustively proved. The quote withdrawal interface accepts Token/Token2022 types but calls the legacy token helper; the retained recovery document reports Token2022 MissingAccount failure. This review does not infer actual helper target behavior solely from the passed interface key.

### Arithmetic and ordering

For the sizing formulas with `vt>0`, nonnegative u64 `vs` and u64 vault tokens `t`, `vs*t` fits u128, `vt+t` fits u128, and `vs*10^15` fits u128. The initial integer output `floor(vs*t/(vt+t))` is strictly below `vs` when `vs>0`; successful caps can only reduce it. Consequently the sell `vs-output` divisor is positive in this domain and its solved token input is at most `t`. Buy's `vs+output` divisor is also positive. This narrows the division concern to missing premises such as zero quote reserves rather than labeling every unwrap unsafe. AMM first converts checked signed effective reserves to u64, rejecting negatives/overflow. `reference*tolerance_bps` and price-band endpoints use checked arithmetic; arbitrary reference values still produce bounded rejection paths. A retained bps value above 10000 aborts under the declared release overflow checks.

The sweep invariant starts `total=0` and bounds each token/native increment by `limit-total`, so a successful iteration retains `total<=limit`. This does not protect `previous + total - before_total`: left association can overflow at `previous+total`, even if the final increment would fit. Rent subtraction and destination lamport addition also retain their own checked-failure premises. These are source-level arithmetic facts; verifier execution does not run the target or prove state reachability.

Contexts can create ATAs before body guards. Trade timestamp/status writes precede price/CPI; buys enforce risk after actual transfer/reload. Withdrawals set time before transfer. Sweeps explicitly serialize each recipient after transfers. Burn emits before setting Ended. Every later rejection depends on normal transaction rollback to undo earlier state/CPI effects. Log emission itself can remain visible in a failed transaction and must not be read as a committed event. Retained finite rollback receipts support only the states actually covered.
