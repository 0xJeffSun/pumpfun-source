## Authority, account identity and CPI review

Typed `Account<GlobalConfig/Pool>` declares program ownership/discriminator decoding. It is not itself a canonical PDA assertion. Several admin/trade/liquidity/creator consumers omit config seeds; current create_config only initializes the canonical singleton, and raw extend only grows preexisting supported program-owned data. Thus a singleton argument needs initial-state, historical upgrade and exclusive-write premises. The fixed administrator must also sign; neither address equality alone nor a synthetic account assignment supplies that signature.

Admin updates use signer plus has_one; new admin/boost authority may be arbitrary or zero without new-authority acceptance. Those are privileged policy/liveness possibilities, not unauthorized takeover findings. Reserved recipients are nonzero but may repeat and are searched by membership; normal protocol recipients are strictly sorted/unique and used by binary search in sweep. Buyback lists are unique but need not sort. Creator fee maximum is a privileged u64 without a global cap, while the three standard fees each cap at1000 and buyback caps at10000. Downstream fee sums/denominators cannot be certified for arbitrary injected state merely from those setter guards.

Pool has_one checks bind mint/vault keys; creation binds ATAs, LP mint and pool seeds. Many downstream token authority/mint/owner checks occur in `transfer_checked`, mint/burn or ATA CPI rather than redundant local checks. A zero-amount early return can skip such a CPI; do not claim it proves token validity. The reviewed self-transfer checks require source token authority matching the chosen signer, rather than forbidding equal accounts. Remaining aliases (including cross-role aliases) require state provenance and dependency semantics, not a blanket “alias-safe” conclusion.

CPI targets are fixed typed System/ATA/self/Pump/Fees identities or Tokenkeg/Token2022 interface choices. Legacy fee query data is the eight-byte discriminator, canonical bool, u128 market cap and quote Pubkey, with readonly FeeConfig and AMM program metas. The consumer ignores return producer; its conditional safe-composition argument is inherited, not upgraded into unconditional original evidence. Multi-hop instead requires Pump return producer and exactly16 bytes. It forwards contiguous five-account curve groups, signer/writable flags, endpoint fee bits, canonical AMM config signature and, when needed, previous pool authority seeds. No arbitrary program substitution follows from the caller supplying unchecked Pump config/event accounts; their validation is delegated to the fixed callee and remains a boundary.

Native Pump route endpoints skip selected token-delta checks. Ordinary endpoints incorporate source/destination/buyback aliases in expected balance calculations. Those checks do not prove all native settlement, routing or producer behavior. Newly composed Pump/Fees/Relay implementations are outside this review; source applicability cannot be transferred to them automatically.

## Arithmetic, serialization and error order

Fee helpers compute a u64*u64 product plus9999 in u128, then checked narrow; even the maximal product leaves enough u128 headroom for9999. Pool creation square-root search keeps mid<2^64, so mid*mid is representable in u128. Checked arithmetic, explicit conversions and Cargo release `overflow-checks=true` prevent many silent wraps; they can instead abort. Exact-quote formulas have ordinary `/` with denominators depending on pricing reserves, and incentive functions contain signed arithmetic, conversions and array access. Valid-state induction remains necessary to prove panic freedom.

Liquidity uses real quote less both accrued buckets and deposit-ceiling/withdraw-floor scaling. Quote transfer fees use direct/inverse epoch calculations, while base-side amounts often remain gross. Creation admits only the two metadata extension kinds for Token2022. Unsupported extension behavior in injected pools is not thereby a reachable user-controlled attack. External mint history, frozen/delegate/extension semantics and arbitrary alias composition remain unproved.

GlobalConfig decoding selects907/940/949 total bytes; Pool selects211/243/244/245/261/270/271/287. Selected prefixes are copied into zero-padded current layouts; intermediate/extra bytes are deliberately ignored. Serialization writes the full current discriminator+fields (949/287) and propagates short-write errors. Custom external decoders require their checked callers to supply at least8 bytes; their unchecked variants are not standalone safe APIs for arbitrary short buffers. Borsh vector allocation and external macro behavior are delegated premises. OptionBool treats missing trailing data as false; OptionU64 zero-fills short scalar data. This preserves a permissive wire contract, not standard Option<T> encoding.

Account initialization may happen before handler guards; realloc/topup and token transfers can precede later account checks, fee arithmetic, event CPI or serialization. In particular legacy payouts validate some remaining accounts after earlier transfers; liquidity does supply/virtual checks after token CPIs; boost burn harvest/close follows events; multi-hop applies final slippage after intermediate effects. Errors propagate with `?` or panic abort. Atomic transaction rollback under normal runtime semantics is required; emitted logs are not proof of committed balances. This worker executed none of these paths and does not claim dynamic rollback verification.
