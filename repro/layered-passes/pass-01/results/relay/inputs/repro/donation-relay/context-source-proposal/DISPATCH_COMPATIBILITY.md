# Native dispatch compatibility

Use `source/lib.rs` module wiring, the unchanged copied `dispatch.rs` and `dispatch_interfaces.rs`, and `admission::Contexts`. Provide a runtime implementing **both** `dispatch_interfaces::DispatchRuntime` and `admission::ContextRuntime`. The call remains `dispatch::dispatch(&mut runtime, &mut Contexts, checked_program, original_accounts, full_instruction_data)`; the stable dispatch checks the program before passing it into admission. Do not expose Contexts as a separate unvalidated entrypoint.

All seven Admission method signatures, associated frame categories, decoded-argument parameters and complete raw suffix parameters are unchanged. Their concrete associated types are Donation, Epoch, After, NonSwap, Just, Combined and WhitelistFrameData. Five DonationVariant values cover five contexts. Do not call generated exits inside admission/body; native dispatch owns125/130/141/145/147/149/153/155/158. Copied dispatch and interfaces are hash-identical to the two permitted inputs.

The necessary type/API adjustment is `Runtime: AccountRuntime<A=Account>`. Account is a copyable invocation-arena capability; the actual AccountInfo backing is retained once by the loader and all copied handles preserve aliases. Key/signer/writable fields are trusted loader metadata. Owner in an interface snapshot is cached. `AccountRuntime::owner` always reads the live backing. The loader must not admit caller-fabricated Account structs. Arena lifetime includes the entire body/event/exit/error path. The older exit comment requiring exact Rc clones is narrowed to ordinary non-overflowing resources; exact Rc destruction/overflow equivalence is not asserted by this adapter.

Added Runtime primitives are panicking immutable `with_mint_data`, fallible immutable `with_account_data`, SPL `unpack_token/unpack_mint`, and `mint_decode_error`. Runtime token/mint methods now have concrete owner/admission/borrow defaults. ContextRuntime declares rent operations, immutable try-borrow, data-length ordinary borrow, executable metadata, canonical/stored PDA syscalls and Token2022 required-account-extension sizing. These operations contain no relay business decision. Its find_pda and DispatchRuntime.find_program_address must call the same authentic syscall semantics under their explicitly supplied program IDs.

CPI instruction encodings and metas are concrete in admission/runtime. `invoke_signed` must resolve the supplied capabilities through the original invocation account arena; program-account resolution must use the authentic runtime context, not synthesize a program AccountInfo. ATA's canonical meta must match an actual supplied capability. No privilege elevation is permitted from instruction meta bits alone. Runtime effects must be visible through the exit handles.

Typed frames own one decoded value per framework wrapper. Their body and exit methods borrow that exact field. Do not replace them with default values, second decodes, global deduplicated program-value caches, or post-body snapshots. Program state mutated in the body persists from the same field; token reloads use live account bytes. Cached interface owners remain separately available after a body closes a token account.

Inherited codec public functions remain available. Additional `_mode(data,checked)` functions implement unchecked account initialization without bypassing owner/borrow/payload decoding. They do not impose exact-size constraints generally. Full IDL is retained; source argument decoder keeps trailing-byte acceptance. Whitelist vector limit remains body-owned.

Rich errors need a separate integration patch by the owner: the inherited Failure/FrameworkFailure representation cannot carry every historical diagnostic object, ProgramError name attachment or owner-list comparison. Numeric-code matching is insufficient. The proposal neither supplies a fake complete conversion nor turns this gap into successful execution. Keep `Failure::Unrecovered` for reserved IDL170 distinct from actual program errors and never lower it to success.

No build/typecheck was performed. This is the concrete source proposal for review, not a claim that the native worker's executable entrypoint has been completed or accepted.
