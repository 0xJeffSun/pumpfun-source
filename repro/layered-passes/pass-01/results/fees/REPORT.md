## Reproduction, seal and limits

Run `python -B verify.py` inside any separate copy of this publication. It reads only local package files, checks the exact manifest file set and hashes, verifies all frozen Git-blob identities, checks all 26 archived source inputs, recomputes every generated ledger and compares deterministic serialized outputs. It launches no target, compiler, VM, network operation or transaction. It writes nothing. The manifest binds the code that performs verification; the external manifest digest remains the trust anchor and does not authenticate Git authorship by itself.

`input-origins.json` gives the immutable Git path, blob identity, size and hash of each acquired input. The original comes from the **public frozen** borrowed-account proposal's original-byte copy, not a scratch directory. The acquisition script is included only as provenance and is not needed by the portable verifier. `inventory_next.py ORIGINAL CANDIDATE SYMBOLS NEW_OUTPUT_DIRECTORY` provides a reusable static entry point for later accepted pairs; it creates a new artifact directory and leaves this frozen seal unchanged. It does not import this snapshot's source interpretations into new bytes.

The separate-copy verifier result and manifest digest are recorded outside the sealed package in the worker's `verification.json` and `result.json`. Verification checks byte facts and reproducibility, **not the truth of every semantic hypothesis, unique historical source, exhaustive behavior, or security sign-off**.
