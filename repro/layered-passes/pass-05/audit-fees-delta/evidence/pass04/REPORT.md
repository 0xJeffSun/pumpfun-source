## Account authority and trust boundaries

Configuration reads are permissionless but require typed Fees ownership and a stored-bump namespace PDA. Setters additionally authenticate the stored admin. The initializer authenticates the fixed admin; arbitrary namespace keys are intentionally not proved to be executable authorized programs. `update_admin` permits zero/nonsigner replacement, while `set_authority` rejects zero. These distinct documented policies are preserved.

FeeProgramGlobal initialization reads a typed Pump-owned canonical Global and its authority. Setters require the typed Fees global and stored signer relation. Buyback creation is permissionless but does not make the payer authority; updates require the global role and sweeps require the stored vault role. Index checks occur after context parsing/init. No signer or PDA bypass is introduced.

Sharing creation uses a real-token-reserve graduation decision, unlike the four-reserve conjunction in the current update branches and the any-nonzero donation selection. It authenticates the selected creator before explicitly serializing intermediate sharing state visible to Pump/AMM. The privileged reset requires **both** the canonical Pump pool-authority PDA signer and the configured Global admin signer. Its lack of local settlement is a trust/policy boundary, not proof that an outsider can replace holders.

Donation creation authenticates a typed canonical Curve, or validates Pool owner/decode/base/creator-derived PDA in the all-zero branch. Sharing authorization is owner/mint/admin, then revocation, then Active. A config identifier is not relay-config ownership/consent. Existing version returns without replacing the route. Crank delegates several raw accounts to a **fixed executable** relay; that validates identity, not its internal whitelist/debouncer policy or upgrade history. Creation accepting an interface base mint/raw quote does not imply the legacy-token-only crank supports every such asset.

Social creation stores user/platform and counters but no payer-chosen beneficiary. Claims use the configured social signer with arbitrary recipient. The new ATA helper validates address, creation permission, exact supplied token owner and mint. It does not itself compare decoded token authority; source transfer authorization is delegated to the token processor, while destination authority/lifecycle policy and supported extensions need separate proof. Neither a canonical address nor an Interface type proves every extension safe. The readonly funding boundary inF3 remains.

Referral withdrawals bind the user signer to a canonical System-owned vault; optional token accounts bind token authority/mint/program but are not required to be ATAs. Optional constraints can fail during context parsing before the handler's missing-argument error. Native rent is computed for zero data; successful System transfer requirements remain external.

No universal alias prohibition exists. Typed ownership/PDA relations eliminate some impossible aliases under ordinary signature/address assumptions; arbitrary recipients and trailing accounts retain specific alias questions. Social native simultaneous RefCell borrows and buyback sequential statements must not be collapsed into the same behavior. Account borrow failure is distinct from unauthorized transfer or persistent mutation.

## CPI, arithmetic, serialization and failure ordering

`cpi.json` lists each explicit local CPI site or builder call with its frozen span, account order/flags, data and trust boundary. Sharing helper flag/info lengths agree at all current literal callsites (5/5/5/4 for creation;10/7/12/12 for updates); `zip` itself does not enforce this for hypothetical new callers. The update helper forwards effective remaining privileges unchanged and neither proves their owners nor removes aliases. Invoke cannot manufacture absent signer/writable privileges under the runtime model; that model is a premise, not a new runtime test.

The release profile enables overflow checks and abort panics. Fee-total checked-add unwrap aborts precede InvalidFeeTotal; u16 share accumulation can return overflow before duplicate detection. Signed buyback elapsed subtraction can overflow; negative/zero limits retain their source rules. Social timestamps cast to u64 with saturating elapsed subtraction; these are different cooldown contracts. No unchecked-arithmetic safety theorem is inferred from typical timestamps.

Rent boundaries are deliberately distinct: buyback actual allocation, donation218, social179, referral0, and extension rent-minimum delta versus exotic top-up balance deficit. Native destination additions rely on checked arithmetic/runtime conservation; no infinite balance model is assumed. Counter overflow after a successful CPI still requires the enclosing transaction to fail atomically.

FeeConfig uses the full allocation length, not the serialized vector end, to select fields. Its checked decoder verifies the discriminator; unchecked still requires2512. Full serializer writes all fields. Social maximum20-byte ID yields179 bytes; Donation218, Global338, Buyback208; SharingConfig with10 holders needs420 within1024. These are field-width calculations, not generated-code identity proofs. External IDL Global/Curve/Pool field order and addresses are bound; raw curve quote83..115 goes beyond the ordinary historical typed Curve fields and retains its explicit length/caller-provenance condition.

Contexts parse and may initialize accounts before handler guards. Deprecated body rejection does not mean every malformed payload reaches6023. Successful `emit!` logs before a failing self-CPI/exit do not certify committed state. Sharing deliberately exits state before dependent CPIs; generated final exit must not overwrite foreign account snapshots, relying on correct Owner-aware framework behavior. Full generated parser/exit/event implementations and library source are not expanded here. Unchecked event-program fields in social, buyback and withdrawal, and fixed/typed ones elsewhere, are retained separately; no blanket event-CPI identity proof is claimed from the `emit_cpi!` spelling.
