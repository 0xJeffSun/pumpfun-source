# V2 fee-share payout ownership and branch contract

No source patch is proposed. Static evidence establishes a material control-flow and ownership boundary missing from the current generic-CPI formulation, but does not yet support an exact natural replacement. No build, target execution, fixture, network access or main-tree edit was performed. Whole original/candidate ELF equality remains false; no accepted handler or comparison count changes.

## Zero-quote payout preparation `[199072,204080)`

This helper prepares owned data; it does not itself call Pump or a transfer syscall. It allocates an AccountInfo vector (48-byte elements) and a Shareholder vector (34-byte elements). Every existing shareholder first requires an available corresponding account (199888), then compares that account key against the shareholder key (`200024 -> memcmp`, length 32). Only after successful key equality does 200080 load AccountInfo byte 42, the executable flag in this retained layout. Executable entries are skipped; non-executable entries copy the shareholder and clone both AccountInfo Rc fields (200376–200520). Refcount overflow goes to the retained abort at 201592.

Insufficient accounts produce 6013 at 202600 with the original source path and line 186. Key mismatch produces 6020 at 202824, original line 188; the path through `203080 -> 1008` augments compared keys. Allocation failure, index-overflow and bounds panic remain distinct from ordinary errors. Error cleanup releases accumulated AccountInfo references in 203152–203344.

If no shareholder is removed, 201128–201152 select the unchanged case. The helper returns a copied shareholder vector and clones the entire supplied account slice, including any trailing entries. Its flag is false at 201992. Dropping trailing entries would not preserve this branch.

If entries are removed and none remain, 203560–203616 return an empty replacement vector, true flag and empty account vector. Otherwise it rescales retained basis points. The accumulation saturates at 65535 (201024–201072). For nonzero accumulated weight, each retained weight becomes `min(floor(weight * 10000 / sum),10000)` (203472–203512), with a saturating accumulated normalized total. For zero sum it writes zero weights (203632–203696). Residual `max(10000 - normalized_sum,0)` is saturating-added to the first strictly greatest original retained weight (selection 200944–201112; correction 203744–203864). Strict greater-than preserves the earlier maximum on ties. The changed branch moves the filtered account vector into the returned aggregate at 203928–204040 rather than dropping it there.

These observations establish why the outer caller can serialize a modified current shareholder set before invoking Pump and why the zero-recipient case bypasses that CPI. They do not certify arbitrary malformed vector invariants or prove a unique original Rust implementation.

## Actual CPI and common update/event body

The nonempty branch uses `236240 -> 548160`, not the candidate generic helper at 74088. The complete original generated CPI body is `[548160,552776)`. At 548352 it loads discriminator bytes `ff cb 13 4f f4 44 08 9f`; 548344 stores the argument byte supplied as 1 at 237400. Length is nine at 548696. This agrees with the candidate source payload `[255,203,19,79,244,68,8,159,1]`.

Its complete fixed-meta builder `[568848,571320)` constructs twelve 34-byte metas from twelve 48-byte AccountInfos. Flag words are `[257,0,0,0,256,0,0,0,256,0,0,0]`: first signer+writable, fifth and ninth writable, others readonly/non-signer. This agrees with the candidate's fixed privilege pattern. The twelve key sources still require a complete parser/context-field binding to certify named-account identity; positional privilege agreement alone is insufficient.

The original calls the separate complete account-info builder `[564232,567376)`, appends remaining metas/infos, obtains its program key through its context and passes signer-seed fields to `550512 -> 724336` (`invoke_signed`). The caller-side remaining accounts are the prepared owned vector, not automatically `ctx.remaining_accounts`. The candidate generic helper constructs metas from supplied flags and passes `ctx.remaining_accounts` to ordinary `invoke`; its full body is retained for comparison. Exact program-key derivation, empty seed provenance, remaining-meta privileges and every cleanup/error path still require full correspondence, even if ordinary invoke ultimately delegates to invoke_signed with empty seeds.

The common original body `[225920,231576)` contains share validation, vector replacement, admin revocation (229616), clock read (`229640 -> 725232`), two event-data calls (`230392/230528 -> 500928`), log emission and event self-CPI (`231160 -> 724336`). Current V2 inlines this work and calls `526760 -> 70560` for validation, updates state, then uses `527296/527456 -> 271472` for event data. Complete serializer normalization correspondence is retained in the witness, separately from raw bytes, actual call sites and relocated data. It does not prove the full common-body contract or all event field provenance. The original early account exit before Pump CPI cannot be replaced by assuming the final framework exit is equivalent.
