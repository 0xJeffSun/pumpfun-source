# Independent review of the interrupted legacy sharing proposal

The corrected proposal is sufficiently grounded for **one isolated build with the unchanged accepted recipe**, followed by original-byte review and the unchanged existing regression corpus. It is not accepted source or a proven equivalent executable. No compiler, VM, transaction, fixture, or main-tree source was run or changed during this review.

Only `programs/pump-fees/src/sharing_update.rs` changes. `proposal/source.patch` applies to the exact accepted 8ff12 baseline; `proposal/review-corrections.patch` shows the additional corrections to the interrupted CLI draft. The complete V2 function, original shared helpers, event declaration, both account contexts, other 25 recorded inputs, IDLs, dependencies and profile remain byte-identical to the accepted baseline. The proposal uses no fabricated source locations, binary edits, manual reference counts, extra signer authority, or alternate compiler flags.

## Corrections found

1. **Use the existing generated CPI clients.** The draft's generic `legacy_cpi` creates a heap vector of fixed AccountInfos, clones that vector, and allocates only the eight discriminator bytes late in the call. The original generated bodies `[544192,548160)` and `[582624,586976)` allocate a **256-byte data buffer first**, then build fixed metas, append a separately collected remaining-meta vector, build fixed account infos, append remaining infos and the program info, and call `invoke_signed`. The fixed account structs have no heap vector of their own. The existing locked `anchor-attribute-program 0.31.2` generator, `anchor-syn 0.31.2` CPI account generator, and `anchor-lang 0.31.1` CpiContext implement that natural construction directly. The proposed typed clients avoid reproducing framework machinery by hand. Authentic crate archives, their lockfile checksums, and exact consumed source members are included.
2. **Preserve ownership across the AMM skip branch.** The original legacy caller clones the fixed AMM accounts before `198256 -> 237464`. The adapter owns and drops them on the reserve/owner skip branch; it only clones the additional CPI program info on the executing branch. The interrupted draft put the guard before these clones. The correction constructs the typed fixed-account aggregate before a small owning adapter, evaluates the same reserve/owner guard inside that adapter, and clones its program account only when calling the generated client. This is ordinary typed ownership, not manual ABI emulation.
3. **Preserve payout loop operation order.** Original `200128–200856` appends the retained shareholder and cloned AccountInfo before `200864–201112` updates maximum selection and saturating weight sum. The draft calculated those scalars first. The correction pushes first, then selects `retained.len() - 1` only after a successful push, preserving the first strictly greater maximum. Values are unchanged for valid inputs; allocation/refcount-abort ordering is no longer knowingly reversed.

These corrections do not establish a unique historical Rust spelling, exact inlining, allocator code generation, complete helper closure, or equal compute use. Their actual generated shapes must be reviewed after the single build. The original inferred windows, every included instruction and immediate dependency remain in `interrupted/static-evidence.json`; the interrupted seal and reports are preserved unchanged.

## Legacy caller and admission

## Complete authorization `[234096,235304)`

At 234232 the authority key is compared against state+56, the decoded admin. Mismatch constructs 6016 (`NotAuthorized`) with original source origin line 97 and **no compared-key payload**. On equality, byte89 (`admin_revoked`) is tested before byte88 (`status`). Revoked uses direct FeeError ordinal9 conversion at 234304, with no additional source origin. Paused constructs 6018 (`SharingConfigNotActive`) with source origin line99; active returns success. The fixed decoded enum is Paused0/Active1; invalid forged enum discriminants are not valid Rust inputs.

The draft's plain `require!(authority == state.admin, ...)`, direct `.into()` for revoked, and plain active-status `require!` preserve these diagnostic forms and precedence. No authorization correction is needed. Original path/line coordinates naturally differ in the proposed source and are not spoofed.

## Complete payout preparation `[199072,204080)`

The first allocation is an AccountInfo vector with capacity `remaining.len()` (48-byte elements), followed by a shareholder vector with capacity `shareholders.len()` (34-byte elements). Each existing shareholder checks corresponding-account availability first, then key equality, then the executable flag. Missing account produces 6013 (original line186); wrong key produces 6020 (line188) with actual account key first, expected shareholder key second through `203080 -> 1008`. No owner, lamport, signer or writable filter is introduced.

Executable entries are skipped. Non-executable entries retain the shareholder and clone the two AccountInfo Rc fields. Original overflow/abort paths remain distinct from ordinary errors. Only after those pushes does maximum selection and saturating-u16 accumulation occur. Strict `>` retains the first maximum on ties. Source `retained.len() - 1` is guarded by the preceding push and is not evaluated for a skipped entry.

If none is removed, the helper returns the copied shareholders, false flag, and a clone of the **entire** input account slice, including trailing accounts; the accumulated filtered AccountInfo vector is dropped. If all are removed, it returns empty replacement/true/empty accounts and releases the accumulated account vector. Otherwise each retained weight is `min(floor(weight * 10000 / sum),10000)`; zero sum writes zero weights. The normalized total saturates, and `max(10000 - total,0)` is saturating-added to the first greatest original retained weight. The source reproduces these arithmetic widths and all three branches. It does not claim correctness for forged Vec/slice invariants.

## Complete legacy adapter `[204080,205768)`

The adapter calls preparation at 204160. On an unchanged result, it clones the original full slice a second time before dropping the helper's temporary account vector. This apparently redundant allocation is retained. On a changed result, replacement shareholders are moved into SharingConfig, then `205424 -> 19528` serializes the account **before** any Pump CPI. Serialization failure propagates and drops prepared account infos. On success, the prepared account vector is returned. Ordinary partial-move/drop semantics are used; no raw struct layout is prescribed.

The caller tests that returned vector, skips Pump CPI when empty, and still reaches final new-share validation/update. A nonempty vector is passed by ownership to the Pump adapter. Preparation/serialization/CPI errors precede final new-share validation. The proposal does not validate new shares prematurely or replace early exit with the framework's eventual exit.

## Complete final validation/update `[205768,211408)`

The observed sequence is empty (6010), at most ten (6011), allocate a key vector, then for each share require nonzero weight (6017), checked-u16 sum (direct ordinal15 conversion on overflow), and append its key. Keys are sorted and deduplicated **before** the total comparison. `208424–208472` checks total 10000 (6014) before duplicate count (6012). The two checks therefore retain their observed error precedence even when both would fail. There are no added Left/Right diagnostic values. The existing source enum and original error stores, rather than an error name guess, bind these codes.

After validation, the new shareholder vector is cloned into state, admin_revoked is set at209448, and Clock is read at209472. Event fields are timestamp, mint, sharing-config key, admin, new shareholders and version. Event serialization runs twice at210216/210360 for log and self-CPI. The self-CPI uses the retained event authority and its standard seed/bump, at210992. This account context and event declaration remain byte-identical. The source's separate validator plus existing update/event tail implements the observed sequence; inlining and complete event/framework-byte equality still require the build.
