## Completed nonzero preparation source contract

`fragments/v2-payout.rs` implements the previously missing natural owned paired preparation, without a placeholder rejection or fake success. Allocate first-account capacity n, partner capacity n, then shareholder capacity n. For each index i: check first availability; compute j=n+i; check partner availability; compare first key to shareholder; only then inspect the first executable flag. No partner key, executable, owner, mint or balance check is invented. Retain both account clones and shareholder, then track saturated u16 sum and first strictly greatest original weight.

Unchanged returns a clone of the complete supplied slice, including trailing accounts; allocate that clone before dropping partner then first-account temporaries. Empty n also follows unchanged. Changed-empty returns empty shareholders/accounts. Changed-nonempty rescales using saturated sum, floor(weight*10000/sum) capped at10000, zero-sum zeros, then saturating residual assigned to the earliest maximum; append moves partner elements after all first elements. No extra AccountInfo clones are introduced by append. On ordinary error, Rust locals drop partner before first vector; no manual Rc layout or forged niche is used. Abort/panic/allocation behavior still depends on genuine compiler/runtime attribution. Valid Rust slices bound n+i; overflow behavior for fabricated invalid vector invariants is not claimed.

The missing comparison API contract is narrowed concretely: packaged Anchor `Error::with_values((actual, expected))` dispatches over AnchorError/ProgramError and formats each key with ToString into `ComparedValues::Values`. This matches the complete original1008 helper's two possible tag arms and the reachable AnchorError conversion, unlike `with_pubkeys`. `bindings/anchor-error.rs` is extracted byte-for-byte from the sealed framework crate. The public package now contains an implementable typed source expression for this named missing contract; it does not claim unique historical syntax or a normalized1008 match. Source locations remain natural, not spoofed original lines234/237/239 or186/188.

The two V2 preparation fragments share only their arithmetic as a new source factoring hypothesis. That factoring, allocation details and error formatting may produce different code. No original symbol/function boundary is asserted for `v2_rescale_retained`.
