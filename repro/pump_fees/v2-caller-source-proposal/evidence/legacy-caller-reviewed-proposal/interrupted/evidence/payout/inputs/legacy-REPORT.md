# Legacy sharing quote admission: uncompiled source proposal

The original legacy sharing-update body admits only a stored zero quote key before checking SharingConfig version. The accepted `5cf8` source omits that check. This package proposes only that missing admission, preserving ordinary AccountInfo ownership, infallible borrow behavior, short-data handling and error order. It does not change either AMM sweep predicate, V2 payout, remaining-account preprocessing, contexts, dependencies or compiler settings.

The proposed helper takes `&AccountInfo`, returns `Result<bool>`, and is called with a temporary `to_account_info()` in a separate `let` statement. That temporary is dropped before `require!(quote_is_zero, FeeError::UnsupportedQuoteMint)`. The existing version check remains immediately afterward. The descriptive helper name and syntax are a natural source hypothesis, not a recovered historical spelling or a promise of identical compiler output.

Two independently bound one-file proposals are included: `proposal/base5cf8/` against the accepted 26-input map, and `proposal/after_parallel/` against the separate worker's exact 26-input map containing only its two AMM predicate edits and donation quote helper. This preserves composability without mixing that worker's unaccepted executable or runtime results into this evidence. Each directory has its full resulting sharing file, exact patch and resulting input map. The maps and current source fingerprints are in `proposal.json`.

## Error order and compared values

The complete wrapper identifies the original legacy body by the retained `UpdateFeeShares` instruction evidence and actual `641320 → 193400` edge. `193744 → 75880` precedes the first version load at `193920`. A false quote result branches at `193912` to the UnsupportedQuoteMint construction. The original stores error **6031** at `194680`; the version-equals-one arm instead stores **6024** at `195208`. Both call the same `Error::from(AnchorError)` body at `709232`. A nonzero quote therefore fails first even when version is already one, subject to earlier account-parser admission and borrow panic.

Both constructions store the same source-origin and no-compared-values layout. Relative to the AnchorError stack base, the source discriminator is at +0, filename at +8, filename length at +16, line at +24, `compared_values=None` discriminator at +80, and error code at +152. The original source path is `programs/pump-fees/src/instructions/fee_sharing/update_fee_shares.rs` (68 bytes), with lines 129 and 130 respectively. `static-evidence.json` compares these exact stores to the current known plain `require!` version-error construction at `[505104,505616)` and its genuine conversion target. This supports a plain Boolean `require!`, not a `require_keys_eq!` adding Left/Right keys and not a raw origin-free conversion.

The pinned framework sources are copied from Cargo-checksum-verified archives: `anchor-lang 0.31.1`, `anchor-attribute-error 0.31.2`, and `solana-account-info 2.3.0`. The actual `require!` expands through `error!`; the actual error macro builds `ErrorOrigin::Source` and `compared_values: None`. `ToAccountInfo` clones the existing AccountInfo. The source enum and captured upstream error-number meaning remain unchanged. Formatter/allocation transitive equivalence is not claimed merely because the error type and fields agree.

## Limits and verification

This is a static source proposal only: no compilation, typecheck, runtime, fixtures, signatures or target transactions were run. It adds no accepted handlers or comparisons. Parser admission may reject a malformed account before this helper; short-length behavior is the helper contract, not a parser bypass. The original borrow panic classes, bounds checks, cleanup boundaries and comparison data are preserved by ordinary APIs, but exact generated code remains a future build question. No compiler/layout search or fake source origin is proposed.

Run `python3 -B /path/to/fees-legacy-quote-admission/verify.py` from any directory. It checks the full seal, source archives and both versioned patches, copied package/previous-input bindings, authenticated framework sources, and regenerates the complete static witnesses. It never uses the original work directory or executes an ELF. The acceptance gate for future work is review of this source/ownership/error hypothesis followed by one authorized fixed-recipe build and separately owned validation; neither is claimed here.
