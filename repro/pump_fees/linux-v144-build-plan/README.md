# Controlled Linux Fees build

The manual `core-linux-v144.yml` workflow performs one unchanged-source Fees compilation on Linux x86_64, using official platform-tools v1.44 and CLI 2.1.21. It freezes all 22 compiler/workspace/IDL/README inputs at commit `4ffe8bd88761059693e481ae972443c10204f7af`; the lockfile, source, release profile and build arguments remain unchanged. The official Linux sysroot contains the allocator source path observed in the original executable. This motivates one controlled build but does not establish the historical recipe.

The [helper](../../../scripts/core_linux_v144_build.py) exports only source inputs into its fresh compiler workspace. It verifies the platform archive hash, source and dependency checksums, records all tool/environment identities, compiles once offline, then compares the emitted bytes with the captured original. A differing complete ELF is an honest result. No saved runtime receipts transfer to changed bytes. The CLI archive has an official asset ID/size and release metadata, but no prior independent archive checksum; its downloaded hash is recorded before execution.

The unchanged CLI's own default remapping remains part of the recipe. No extra flags, path transformations, binary edits, source padding or adaptive variants are used. The hosted environment is recorded, not claimed to reproduce the complete historical environment. Generated deployment keypair paths are excluded before retention reads and by the upload configuration. Seven synthetic retention tests verify this behavior.

`reviewed-plan.tar.gz` preserves the complete 26-file reviewed revision 2, including the untouched revision 1 proposal and the correction history. The revision-2 manifest SHA-256 is `cdc10336c25e4936269d11094b4559025b0fb3db820cd7a428dcb3ec9e42243c`. `installed-files-sha256.json` binds the four installed workflow/helper/pins/test files. No build result is contained in this planning package; each execution must retain its own attempt record, logs, complete candidate and comparison.
