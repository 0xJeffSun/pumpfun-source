## Substantive review

**Route context.** The report distinguishes thirteen sequential input slots, account-reader validation, later PDA/writable checks, and final aggregate stores. The Tokenkeg and mandatory Token-2022 program readers check exact key then executable; this does not certify the processors or token extensions. Signer privilege exists before the later AMM PDA comparison. Event authority is a cloned inline AccountInfo and the wrapper forwards its verified bump separately from per-curve bump and final-hop flag. The Global payload reader, error objects, allocation and runtime contracts remain explicit. Thus the phrase context-local closure must retain its stated imported-reader assumptions; it is not complete all-input instruction admission. Frozen candidate declarations are corroboration, not original layout proof.

**Native settlement.** The distinct source read/check/debit/release and later destination read/add/borrow order is retained, including zero amount, overflow, alias and failure qualifications. Direct lamports precede the three-account self invocation, which precedes one-account Tokenkeg SyncNative. The package does not prove the self callee's effect or use a guessed token processor. The rent top-up depends on the returned rent-helper word and recorded liabilities, with floating primitives, resource faults and short-account resizing unclosed. Its three source discrepancies—balance-check order, four source versus three original self-CPI AccountInfos, and fixed rent guard versus conditional original top-up—are concrete follow-up evidence, not safe-to-promote patches or exploit results.

There is one **cross-package wording caveat**: native settlement's first residual asks context admission to bind A+0x38 to an “accepted buyback token account.” The completed context report establishes only a present, writable raw AccountInfo for input slot 7/A+0x38. It explicitly establishes no local token-owner, mint or recipient-membership constraint. External SyncNative acceptance may still require a suitable token account; that obligation must not be retroactively inserted into the context parser. The independently completed context report also supplies some formerly pending signer/program/event-bump bindings. The native package remains an immutable record of its own narrower scope; neither report alone closes native-input r7 reaching definitions, all decoder behavior or downstream CPI effects.

**Fees missing branches.** The admitted original identity and full 13,800-byte body are separate from helper attributions. Raw instructions confirm disable-bit 4 before existing version, the two logs, the four-reserve OR selector, conditional raw data[83..115] extension read and zero-to-WSOL normalization, and shared authorization/event ordering. In particular, original payer/admin comparison at 175984 branches to revocation handling at 176968 only on equality; revocation is tested before status at 177240. The frozen source does revocation before payer. The original explicit empty-sharing-data rejection is also absent from that source. These are independently supported behavioral gaps in addition to the missing curve branch and logs. Decoder/error/borrow/PDA/event contracts and nested literal extents remain unclosed, so withholding a complete handler proposal is appropriate. The recently accepted AccountInfo field correction does not restore any of these missing business branches; the report's candidate 8cce and source checkpoint remain historical, clearly stated inputs.

**AMM F05.** The fixed target key and matching public IDL do not identify captured-original code. For the frozen candidate composition, however, the actual Fees getter returns a non-unit Fees value; the exact locked Anchor generator serializes and sets return data after successful handler return, then performs account exit. Both simple getter fields have no mut/close actions, so the generated exit is empty. Dispatch/entry add no later successful CPI, and AMM reads immediately after successful invocation. I rechecked that setter/exit order and the actual generator's mutable/composite-field distinction. The resulting conditional nonissue applies only to that candidate source under the stated compilation, deployment, destruction and syscall assumptions. It does not resolve the captured-original F05 prerequisite, certify fee policy, or imply all getter inputs succeed. No original getter admission was claimed or performed.

**Nested ordinary context.** The package carefully separates ordinary mode from the excluded Mayhem call, fixed account constraints from executing that call, local initialization CFGs from the unclosed CPI/decoder contracts, and wrapper remaining-slice plumbing from walk-local consumption. The ordinary handler passes the original remaining pointer/count to the nested walk and later uses only explicitly identified accounts; neither the wrapper nor local exit receives a consumed-tail value. This supports the bounded lack-of-tail-rejection statement at these callers, with opaque callees, aliases and resource behavior still excluded from an unconditional acceptance theorem. Token-2022 decoding and initializer effects remain opaque. Earlier manual arithmetic contracts are imported as manual evidence, not converted into automated proof.

## Independent evidence checks and limits

`rebind.py` checks the current captured Pump/Fees originals against the frozen full Git objects, then every newly retained code/data range in the route context, native, Fees branch and nested-context packages. It also rebinds literal/relocation records and the retained source excerpts, and validates exact Git commit-to-blob membership for complete provenance objects. This closes the portable packages' stated external full-object-membership limitation for this review snapshot. It does not turn mechanical normalization, CFG metadata, or source text into a semantic theorem. Existing package verifiers independently recheck their seals, instruction operands, imported subset seals, dependencies and selected anchors; manual prose and all transitive semantics are not machine-proved.

The public checkpoint's 25 candidate audit observations and global recovery counts are not reissued or upgraded. No recovered-handler count, unique-case count or exact-contract count changes. The two previous acceptance packages remain independent and immutable; central integration is not part of this review.

Two review-tool preparation mistakes are retained in `logs/rebind-attempt-01.log` and `02.log`: the first invocation omitted the publication directory level; the second used `_rel.bin` for native import records actually named `_reloc.bin`. The corrected third attempt passes all bindings. Neither was an evidence mismatch or required modifying an input package.

Run from any directory with a repository containing the frozen public Git objects:

```sh
python3 -B path/to/this-review/verify.py --repo /path/to/pumpfun-source
```
