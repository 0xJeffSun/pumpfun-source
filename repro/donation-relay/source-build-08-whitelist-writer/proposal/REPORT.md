# Whitelist serializer: restore the shared I/O error boundary

An isolated, uncompiled source proposal changes only `account_exit158` in `src/generated_exit.rs`. The reviewed build07 candidate is `019a9ea7cb7cb6eb40db49125474135564c0e864ee2fc6bdad33231f8eb5827b`. Original window158 is the complete 1,408-byte range 503808–505216. The published match ledger records **no complete raw or normalized candidate match**. The corresponding candidate source is inlined into wrapper99 (162616–175624, 13,008 bytes); that wrapper is not asserted to be an isolated serializer or a comparable whole-function match.

## Source improvement

Replace the whitelist's manual copying closure with the existing `BpfWriter`, producing `std::io::Result<()>` for its four operations: discriminator, bump, u32 vector length, then each 32-byte key. Convert length overflow into `std::io::Error::from(InvalidInput)`. At the single outside mapping, drop the I/O error and then construct the already-reviewed owned framework 3004 error. That mapping is still inside the mutable-borrow closure. Account-name decoration is still outside it.

This is the same natural writer/error pattern already used by the fixed serializers, and the authenticated Anchor BpfWriter source is included. No new dependencies, representation attributes, allocation implementation, source coordinates, or compiler settings are proposed. No runtime contract changes are made to owner checks, account ordering, mutable-borrow acquisition, or field data.

The old manual closure made an owned AnchorError immediately on short writes. It therefore skipped the original WriteZero `io::Error`, its String/boxed error allocation, and its destruction before the 3004 constructor. It also skipped the original simple I/O error intermediate for vector overflow. Success bytes and prefix writes were insufficient evidence for that boundary.
