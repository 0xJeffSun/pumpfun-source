# IDL header deserialization: owned3003 proposal

The precise correction is limited to `unchecked_header` and its already admitted three callers. Current Relay09 returns an integer-only `Cause::Framework(3003)` when its header payload is shorter than36bytes. Original W218 [610936,611424) constructs a real I/O failure, constructs owned `AccountDidNotDeserialize` through W297, destroys the I/O failure, then transfers the boxed framework error to its caller. The proposed two-file source change reproduces that owned boundary with sequential field reads and reuses the existing Owned decorator/logger/lowerer. It adds no dependency and does not generalize unrelated IDL validation or application failures.

## Whole decoder and error construction

Original W218 first rejects total lengths below8 by slice-panic call730592 at611416. Otherwise it removes8 from the remaining count. A remaining length below32 branches611048; after authority loads, `len & -4 == 32` also branches there, exactly the remaining32..35 lengths. The success branch loads32 authority bytes and the u32 at absolute offset40, writes the header fields, sets success tag0 at611368 and returns. No trailing bytes or stored data_len bound is checked. The full488byte body is retained, including panic and every return.

On either short-field branch,611048 supplies the static `failed to fill whole buffer` error descriptor772768 to705216 at611064. The descriptor contains its27byte message and kind37. Function705216 [705216,705560) reads the error kind, maps this EOF to704800, and handles destruction of any replaced dynamic input. Function704800 [704800,705088) allocates26 message bytes, materializes `Unexpected length of input` in immediate stores, allocates24bytes for its String value, then passes kind20 and that box to707248. The complete direct closure includes707248, its allocation/error paths and all deallocation calls. The retained Borsh0.10.4 `unexpected_eof_to_unexpected_length_of_input` source corroborates the natural `Error::new(ErrorKind::InvalidInput, ...)` operation; it is dependency evidence, not a claim of recovered original compiler/source provenance.

W218 preserves the resulting I/O error in r7, calls297 at611104 with r2=3003, saves the returned owned enum/pointer, then checks the I/O tagged representation and invokes its destructor at611208 when needed. Only after that does it write the saved framework error into output and set failure tag1. Thus the ordering is **I/O construction -> owned3003 construction -> I/O destruction -> caller guard destruction**. It is deliberately different from the preceding serialization proposal's I/O-drop-before3004 order.

The patch uses Read::read_exact for authority32 then length4, maps UnexpectedEof into the exact InvalidInput message, and has its outer map_err explicitly construct the owned3003 before `drop(error)`. The local closure owns only a slice cursor and two stack arrays. It preserves the <8 slice panic and does not add a data_len/capacity check. This is natural field deserialization source, not a compiler-layout constraint.

## Scope and acceptance

This is an uncompiled source proposal. No main source, existing checkpoint, build, target execution or fixture was changed. It does not claim original/candidate raw identity or exact historical Rust ABI. Source/type/backend acceptance is required before any runtime. A future authorized build must retain the same pinned recipe and compare complete emitted decode/caller/factory/decorator/log/lower/drop bodies, all original/candidate call/data ledgers and all byte residuals. Existing ordinary12 is the only proposed runtime preservation corpus; it does not cover all short-header or allocation-failure branches. No new short-header, source-origin or fixed-authority probe is proposed.

The old Framework3001/3002 and other validation codes, Program borrow errors, numeric2506 comparisons and their original origins remain explicitly incomplete. Success-return allocation timing for other callers and formatter/vtable behavior are not established by this patch. The69original/44candidate full direct-closure windows are retained as evidence; opaque rows stay opaque, including any transitive SDK body outside the analyzed IDL path. No excluded Pump/Mayhem/token-extension lane was analyzed.
