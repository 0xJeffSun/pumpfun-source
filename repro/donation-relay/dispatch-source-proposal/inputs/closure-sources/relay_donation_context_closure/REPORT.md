# Donation context source proposal

This completes a **static natural source proposal**, not an integrated or compiled implementation. The two source files replace the five unresolved donation context sketches with ordered admission, initialization and constraint adapters. Existing program-owned, fresh system-owned, prefunded system-owned, destination ATA and per-instruction native temporary-account paths are distinct. No accepted handler, completion, runtime case or exact-binary count changes.

The fixed input is `476ecf0d31a8dae66dc6e2fb0a97f19d4f163e40`. The original `deployed.so`, window metadata, IDL, dispatch, branch landmarks and project boundaries were extracted with `git show` at that revision. The continuation read the two boundary documents again with `git show`; it did not read moving source as checkpoint evidence. Whole-input SHA256 and byte lengths are in `input-manifest.json`. `consumed-code.json` supplies exact half-open ELF byte ranges and hashes; `consumed-literals.json` supplies literal ranges; `consumed-source.json` supplies conservative whole-input source/text ranges. `instruction-ledger.json` records raw signed call operands, indirect register operands, branches and immediate error loads for every consumed window. Ordinals identify inferred windows, not historical functions.

The earlier partial extraction and its frozen inputs are retained. The copied predecessor manifests are unchanged, and the verifier binds the four consumed predecessor source/tool/report files to those seals. This publication neither republishes local session telemetry nor includes stopped/private work. No source search, build, typecheck, SBF execution, runtime probe, transaction fixture, network contact, parent edit, staging, commit or push occurred.

Implementing that trait is required before application. `source/donation_contexts.rs` gives the corresponding five Anchor declaration hypotheses using the integrated proposal's state types. Macro expansion is **not** evidence of matching precedence; the manual adapter controls the proposed sequence.

## Ordered account admission

Before consuming accounts the actual parser also re-deserializes instruction data. In121 the prefix length guards are at160800–160896, string decoder74 is called at161000, and the error102 construction is at161192–161200. A trailing credited-to32-byte read follows the string. Equivalent blocks remain in all five retained parsers. The declaration proposal therefore includes all five arguments: amount u64, config32 (Pubkey or byte array), tip_bps u16, Borsh string, credited_to Pubkey. The adapter starts **after** this argument phase. It does not replace malformed-string/short-input behavior, prescribe an exhaustion check or remove the original repeated decode. Config bytes supplied to the adapter must be those decoded for this instruction; they cannot come from an unvalidated external selection.

Account order is epoch tracker, debouncer, destination ATA, mint, source ATA or native temporary handle, from, optional payer, whitelist, associated token program, token interface, system program, event authority, event program. Remaining accounts are retained. A missing required account is3005. The first three are raw handles awaiting initialization; mint is checked through1→9, ordinary source token through2→8, from through80→280 (3010 if unsigned), whitelist through85→27. The with-payer second signer call is338528 after from338256. Native source remains raw until its initialization helper.

Checked decoders must retain supported-owner validation, zero-lamport/system uninitialized checks, fallible data borrowing, discriminator/base-data and state-enum validation. They are not casts. Local owner/uninitialized error loads3007/3012 are present in9/27; decode failures propagate before later relationship constraints. Whitelist bump is read from its decoded state.

ATA and system program admission check fixed addresses and executable status; token interface accepts exactly Tokenkeg or Token2022 and checks executable status. Wrong ID is3008 and non-executable is3009. The proposal hardcodes the public ATA key, rather than accepting an arbitrary caller-supplied program constant. Event authority/program are unchecked handles at this phase; event authority is seed-checked later. No extra executable/address constraint is invented for the final event program handle. Rent is loaded after account-type admission and before any initialization (121 call164728 to669520); a rent-sysvar error must propagate.

## Initialization and later constraints

The sequence is epoch PDA and helper, epoch writable/rent, debouncer PDA and helper, debouncer writable/rent, destination ATA helper, destination writable/rent, then native temporary PDA/helper/writable/rent when applicable. Only then are mint and ordinary source/donor constraints evaluated. Numeric ordering of error blocks is not control-flow order:121 places source-owner2023 at171112 before the mint-owner2022 error block171168, but the success-path comparison170928 branches to mint-owner failure first. The adapter follows the branches.

Epoch seeds are `[b"epoch_tracker_v1", config32, mint]`; debouncer seeds are `[b"debouncer_v1", config32, mint]`. Each uses canonical `find_program_address` under the relay and supplies its bump to signed initialization. Address mismatch is2006. No epoch counter, payer or donor enters either seed list. Exact spaces are90 and82 including the eight-byte discriminator.

For122 (and its corresponding copies), owner unequal to SystemProgram selects checked state decoder25 at175376. Successful decode precedes exact data length90 (176232/176240), relay owner equality (176296), then rent-minimum computation and lamports comparison (181896,182192,182344). The length, owner and rent errors are2019,2004,2005. Debouncer uses checked23 and space82. This is concrete evidence for `init_if_needed`, rather than inferring it from the IDL. Decoded non-system accounts with the wrong owner fail typed admission; the later2004 check is still retained, not substituted for that decoder.

System-owned accounts split on lamports (122 at175688/175712). Zero lamports uses `create_account(minimum_balance(space), space, relay)` with the derived signer seeds. Nonzero lamports rejects payer key equal to target (4101), computes `max(minimum_balance(space),1).saturating_sub(current)`, transfers only a positive deficit, allocates exact space, assigns relay ownership, then unchecked-decodes the newly allocated state. Unchecked decode means skipping the account discriminator comparison at this new-account point, **not** ignoring owner, borrow or state decode failures. There is no unconditional reset of existing state here; business112 owns the later uninitialized-state transition. Post-helper writable2000 and current-data rent2005 remain separate.

Destination helper124 compares owner with SystemProgram at194376/194400. Non-system enters checked token decode8 at194432; system-owned invokes ATA creation225 at198576 and rejoins the same decode. It then checks token mint2014, token authority=debouncer2015, AccountInfo owner=selected token program2023, and canonical ATA address3014. ATA derivation uses `[debouncer, token_program, mint]` under the fixed associated token program. Creation is a real CPI with payer, target, debouncer, mint, system and selected token program, not a locally manufactured token state. Thus fresh and prefunded system accounts are delegated to real ATA creation semantics; already-token-owned accounts must satisfy decoding and all relationships. Outer mutable and rent checks follow. No custom local System top-up formula is substituted inside the ATA program.

Native temporary seeds are `[b"donate_native_wsol_tmp_v1", from, token_program]`, canonical under relay; this is not an ATA. Helpers129/134 **do not branch on token ownership to reuse an existing account**. They read lamports first (238776), use zero/prefunded split238800, then create or top-up/allocate/assign. The prefunded path rejects payer=target and uses the same positive deficit formula. An already-token-owned account is not silently accepted: genuine allocation/assignment or creation errors must propagate. The selected token program owns the new account, and InitializeAccount3's authority is from. Initialization228 at250624 is followed by checked token decode8 at250680;134 mirrors this at300912/300968. This is `init`, not `init_if_needed`.

Temporary length is165 for the ordinary legacy branch. The branch tests the **mint AccountInfo owner** for Token2022, before the later mint/program equality gate. On Token2022 it fallibly borrows and parses base/TLV mint data, derives required token-account extensions and their account size through33/29. The prefunded path recomputes this sizing for allocation after any transfer. `token2022_account_space` must preserve those results/errors; using165 universally or accepting malformed TLV is invalid. This is token-account sizing, not the separately owned mint-policy106 analysis. System, ATA and token program behavior and exact extension-size errors are bounded framework premises, not newly supplied token implementations.

## Post-init checks and access-control placement

Mint must be writable2000. Ordinary variants next require mint owner=token program2022, source AccountInfo owner=token program2023, source token authority=from2015, canonical source ATA `[from, token_program, mint]`2009, then source writable2000. No extra source mint equality is invented; canonical address derivation includes mint. From must be writable2000. With-payer additionally requires payer writable2000. Both were already admitted as signers. A distinct account position is not a universal payer!=from rule: those keys may alias. Only the observed prefunded payer/target inequality is added.

Native variants initialize temporary accounts **before** predicate103. In126, temp129 call215288 precedes predicate call216528. The latter receives mint key and token-program key, not mint owner. It returns true exactly for Tokenkeg/native mint or Token2022/native2022 mint on the bounded ordinary path. The two public native constants are assembled inline in103 at113584–113824. Unknown program takes an error29-construction/drop path and returns false; its resource/error-formatting effects are not modeled by the pure boolean adapter. False maps to error6006 at216560/216568. Then mint owner must equal the program (2022), followed by from writable, whitelist seeds, supported-program102 (6029), and event seeds. Moving predicate103 before initialization would change failure precedence and is not proposed. Supported-program102 is redundant under successful interface admission but is preserved in the ordered adapter.

Whitelist uses **stored bump**, with `create_program_address([b"mint_whitelist_v1", bump])`, not canonical bump search. Both derivation failure and wrong key yield2006. For126 the call to342 is216960, after stored bump load216880/216888. Event authority uses canonical `[b"__event_authority"]` and2006. No new signer/relayer requirement appears in these contexts. Amount, tip and message business checks, mint-policy/bypass behavior and state identity checks stay in the existing donation business path after context admission; these adapters cannot authorize a donation by themselves.

With-payer changes **initialization funding only**. Epoch/debouncer/ATA creation and top-ups take payer, while source ATA derivation and token transfer authority remain from. Native funding and temporary authority both remain from. Credited-to is an instruction argument used later in the event, not an account signer or replacement funding authority.

## Borrow, alias and error premises

Account handles must share the original AccountInfo/RefCell identity. Equal keys cannot be turned into independent mutable buffers. Ordinary lamport/data-length reads326/327 have panic paths for conflicting borrow state; the proposal leaves them non-Result to preserve that boundary. Current-data rent checking reads lamports first, then uses fallible data-length borrowing328 and rent325. Typed decoding uses fallible borrowing331. Implementations must release temporary borrows at the original operation boundaries, before subsequent CPIs; no borrow may be kept merely for adapter convenience.

CPIs must use real AccountInfos and normal privilege/owner/signature checks. The runtime enforces writability and borrowing during CPI, which can fail before the later explicit mutable constraint. Do not preflight those checks earlier and change precedence. No blanket distinct-account rejection is recovered; from/payer may alias, while prefunded payer=target is explicitly rejected. Reusing a temporary account with lamports follows allocation, not an artificial existing-account success path. Account cloning increments shared references; overflow/allocator/drop failures are outside the bounded successful-allocation premise. Transaction rollback is delegated to the real runtime, not emulated by locally undoing failed initialization.

The source Error struct records constraint code and field for review. A production binding must preserve full original Anchor/ProgramError variants, account-name decoration and compared-key/value payloads; this simplified struct is not a recovered error ABI. Immediate error loads in the ledger are evidence sites, not a proof every load is reachable or a total error-precedence list. The source establishes ordinary control flow subject to the explicit decode/borrow/CPI premises; it does not certify every invalid alias/resource case.

Keep business access controls, body, event and separately owned exits in their actual positions. The proposed Anchor declarations alone do not close this integration gap.

Bind `RelayError::NativeMintMismatch` to6006, not a newly appended enum ordinal. Native supported-program6029 is explicit in the adapter; declaration macro equivalence remains unverified.
4. A later authorized build/typecheck and root review must resolve macro ordering, feature/configuration requirements and Rust integration. None was run here. Genuine system/ATA/token execution and all runtime receipts remain absent; static evidence is not execution evidence. Mint-policy106 and generated exit implementations remain separately owned and untouched.
