# Relay build05 serializer review

Build05 makes the intended natural improvement: the four fixed account serializers write their fields directly into the borrowed destination rather than building a temporary vector. Their field order, four discriminator values and 23 copy sites agree with the recovered original stream. Their complete bodies do **not** match the original. The next justified source proposal replaces `Cursor` with the already-published Anchor `BpfWriter` implementation, whose one-copy `write_all` behavior agrees with original window281. This proposal is uncompiled and has no runtime receipts.

This review freezes the public inputs from aa98fb45f3f756d008ccb9940bcfd9a6e986ef77. Parent later added unrelated evidence in 347aec7; no current-tree identity is inferred. `input-provenance.json` binds each copied input to its public repository path. `source/` holds all21 actual build05 inputs, and `source-proposal/` holds those inputs with only `src/generated_exit.rs` changed and exact upstream `src/bpf_writer.rs` added. The root source and all prior packages remain unchanged.

## Proposed source correction

`source-proposal.patch` has exactly two paths. It changes the four fixed serializers from `Cursor::new(data)` to `BpfWriter::new(data)`, imports the private helper, and adds the exact1066-byte upstream writer implementation. It changes no whitelist logic, admission, ownership gates, borrowing, field order, close operations, events, authority, errors elsewhere, Cargo manifest, lock, profile or compiler flags. No inline attribute is added. The module path is the actual new source file, not a captured historical path.

The source comes from the public, previously retained `anchor-lang-0.31.1.crate`, checksum `e6bab117055905e930f762c196e08f861f8dfe7241b92cee46677a3b15561a0a`; its `src/bpf_writer.rs` SHA256 is `544511c105eb66783551f85ef85f4e60b13c86350de6d9f1441fff94937d8511`. `upstream/extraction.json` binds the bytes, archive and member. `upstream/ATTRIBUTION.md` records provenance and the upstream Apache-2.0 declaration. That release is an available matching **source family**, not proof of the unique historical Anchor version. No Anchor dependency is introduced. The already-selected solana-program2.2.1 archive exports `solana_program_memory as program_memory`; the unchanged lock selects solana-program-memory2.3.1. Typechecking and resulting machine-code behavior remain for a separately approved build.

The mutable slice borrow lasts through all writes; the helper contains only that borrowed slice and a u64 position. All copied fields come from separate typed state references, preserving the existing no-overlap premise for `sol_memcpy`. No destination growth or vector allocation is requested on successful writes. Short-write I/O errors may allocate and be dropped before the outer account error; this is a known resource-behavior distinction from build05 and closer to the original's explicit error-construction path. Modern standard-library error lowering is not presumed byte-identical.
