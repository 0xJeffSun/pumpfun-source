## Ordered admission and source decisions

All IDL logs occur **after** account admission. This differs from the eleven ordinary N09 wrappers, which log before decoding. All checked inputs are consumed sequentially; there is no global count preflight that would change which earlier typed error wins.

* **Create215:** consume raw from, raw to, raw base, typed System program, raw program. The System field checks key3008 and executable3009 during consumption. Then require from.signer2002, to.writable2000, base equal to `find_program_address([], executing_program)`2006 (actual left/derived right), and program.executable2007. From is not explicitly required writable; its writable System CPI meta is enforced by the genuine runtime. There is no invented precheck that to equals the eventual seeded address, nor an early program-key equality check.
* **CreateBuffer209:** consume raw buffer (initial missing error is unnamed3005), then authority Signer; fetch Rent before inspecting the buffer. Initial immutable-borrow failure is also unnamed. Slice first8 bytes (short input panics), require all eight zero2013 named buffer, perform unchecked typed owner/header decode while the first immutable borrow remains held, then release it. Check buffer writable2000; read lamports, fallibly read length, require rent exemption2005; finally require authority key nonzero2003. No existing authority equality is required.
* **Write/SetAuthority213:** checked idl, then Signer authority, then idl writable2000, stored authority equals signer key2001 (stored left, signer right), then nonzero signer key2003. There is no canonical-PDA/address restriction, new-authority signer requirement, authority writable test or payload-capacity guard here.
* **SetBuffer207:** checked buffer, checked idl, Signer authority; buffer writable2000; **stored buffer.authority == stored idl.authority** raw2003 named buffer without compared-key metadata; idl writable2000; idl has_one signer2001; signer key nonzero2003. There is no added buffer/idl inequality check. Aliasing can instead fail the later original borrow sequence.
* **Close205:** checked account, Signer authority, raw sol_destination; account writable2000; has_one2001; account key differs from destination2011 named account; signer nonzero2003; destination writable2000. Destination owner and authority writable checks are not added.
* **Resize211:** checked idl, Signer authority, typed System program; then idl writable2000, has_one2001, authority writable2000 and nonzero authority2003. This authority funds the ordinary System transfer and must be an actual signer.

## Bodies, CPI and exits

**Create171 `[521664,525280)`.** After its retained log, compare supplied program key with executing program (1001). Recompute the empty-seed PDA/bump. Derive the IDL address with `create_with_seed(base, b"anchor:idl", supplied_program)` and unwrap its failure. Check requested payload+44 for overflow, fetch Rent, cap actual allocated total space at10,000, and compute rent minimum. Constructor320 and serializer307 encode System instruction tag3, base32, u64 seed length10, seed bytes, lamports u64, space u64, owner32. Metas are payer writable+signer, derived target writable+nonsigner, base readonly+signer. CPI infos are **from, to, base, system**; one signer group has one seed, the canonical bump byte. The runtime must derive that PDA signature normally. The source does not inject signer flags. After successful real CPI, unchecked-decode the actual target data, replace authority with payer key while retaining decoded data_len, and stream header216 directly. A newly created System account has zeroed data; the source does not silently assume arbitrary preexisting data_len is zero.

**CreateBuffer174** logs, replaces cached authority and leaves cached data_len untouched. Exit210 serializes the header. **SetAuthority176** logs and replaces authority with all32 argument bytes, including zero; exit214 serializes it. This permits erasing authority, while future mutation contexts reject the zero signer key.

**Write175 `[527504,528184)`.** After log, check usize old_len+input_len, unwrap conversion of input length to u32, check u32 length addition, then update cached data_len **before** mutable data borrow. Borrow failure unwraps/panics. Slice payload at44 and old..new; insufficient storage panics rather than returning an invented capacity error. Copy bytes, release borrow, then exit214 streams the header. No clamp, tail clearing or rollback logic is inserted.

**SetBuffer177 `[528304,529520)`.** After log, copy buffer's cached data_len to destination cache **before** borrows. Borrow destination mutably and slice its payload; then borrow buffer immutably and slice exactly its declared length. Borrow failure or short/source-out-of-range data panics. Only after those source checks, insufficient destination capacity returns2506 with source origin `programs/contracts/src/lib.rs:36`, compared values destination capacity left and required length right (`529096/529104 ->529112 ->3`). Otherwise copy only that prefix. Drop source guard, then destination guard. Exit208 persists buffer header first, destination idl header second. It neither closes/clears the buffer nor erases the destination's unused tail.

**Resize172 `[525280,527336)`.** After log, nonzero cached data_len returns1002. Read live length twice. A requested total size smaller than current panics with retained `data_len should always be >= the current account space`; growth is capped to10,000 per call, with checked addition. A third live-length read skips Rent/transfer/realloc if no growth, but the generated header exit still follows. For growth, fetch Rent and minimum_balance(new_len), then **checked** subtract current lamports: an overfunded account panics; this is not `saturating_sub`. Invoke System Transfer tag2, authority to idl, even when amount is0. Transfer failure returns before realloc. Realloc332 `[690144,690592)` takes a mutable borrow; checks new size minus original entry size, saturating, against10,240; changes serialized and visible lengths and **zero-fills growth** via `sol_memset_` at690568. The earlier exploratory assumption “zero_init=false” was rejected after reading the whole helper; only zero-filling appears in this proposal. No compiler/source variant was tried. Exit212 then persists the header.

**Close173 and206.** Body173 `[527336,527376)` is only its log. Generated206 calls282: destination balance first, source balance second, checked sum, destination write, source write0, assign System owner, fallible resize0. Borrow operations on lamports panic; resize can return an ordinary error after the earlier effects. Errors are named account. There is no header serialization, and the actual adapter must preserve destination-before-source clone/release order. These intra-instruction effects remain subject to genuine runtime transaction rollback; no runtime was executed here.

**Header exits19/216.** Ordinary generated exits compare the type's relay owner to executing program, then skip closed accounts (live System owner AND empty data). They use a fallible mutable borrow and stream discriminator, authority, length in order. Short storage receives its available prefix before3004; no upfront length check or tail wipe is introduced. Create's direct216 serialization has no extra owner/closed gate. No IDL operation emits donation events, performs event self-CPI, serializes return data or clears prior return data. On an ordinary error N09's169-level reporter remains responsible for one error log before normal u64 lowering; the raw ABI is still a required adapter.

The runtime trait contains only genuine low-level effects: live owner/executable, Ref/RefMut account data, panicking lamport access, assign/realloc, Rent, seeded address derivation and raw invoke_signed. Valid allocation, 64-bit slice representation, exact soft-float helpers, original error heap/formatter representations, allocator/OOM and panic metadata remain unproved.
