# Ordinary Tokenkeg two-curve routing: static implementation boundary

The original supports the account and control-flow shape needed for the minimal same-direction route **SOL→A→B**, and its reverse **B→A→SOL**, without invoking a v3 trade instruction. A is the base of a native-root Pump curve, and B's Pump curve quotes A. The same genuine AMM caller can group both curves into one Pump CPI. A narrowly scoped source extension is therefore grounded enough to propose, but is **not implemented or runtime-validated here**. The current Pump instruction remains partial. Existing successful two-curve receipts use Token-2022 mints and cannot establish ordinary Tokenkeg parity.

This package contains only read-only analysis, source snapshots, and byte-bound disassembly excerpts. It performs no program execution, build, transaction construction, source mutation, initializer work, live interaction, or signer substitution. It does not retry the stopped sell_v2 transfer-fee, incentives, Mayhem initializer, or v3 extension lanes. The retained full per-curve body contains other branches as evidence; their presence in the excerpt is not analysis or acceptance of those branches.

## Minimal accounts and legitimate signing

Use distinct ordinary Tokenkeg mints A and B, 82-byte mint layouts, 165-byte initialized token accounts, and full 166-byte Pump BondingCurve accounts. Both curves must be incomplete, non-Mayhem, non-cashback, non-holder, adequately funded and backed by existing canonical vaults. Keep the native root's stored `quote_mint` **zero** and its supplied quote mint WSOL. The original branches on the stored zero quote at `0x5b7c8/0x5b800`; a stored-WSOL curve is not silently treated as that same native-payment branch by this proposed scope. Buy amounts must stay strictly below real-token-reserve exhaustion so that synthetic completion remains excluded.

The outer AMM instruction has 16 fixed accounts in captured-IDL order: user, user input token account, user output token account, AMM GlobalConfig, AMM FeeConfig, AMM user volume accumulator, buyback recipient token account, Tokenkeg program, Token-2022 program, System program, AMM event authority, AMM program, Pump program, Pump Global, Pump FeeConfig, Pump event authority. The user signs normally. The AMM volume account should already exist; no initializer behavior is part of this proposal. The Token-2022 program account remains a fixed interface requirement even though no token account or mint in this scope uses it.

The Pump CPI has 13 fixed accounts: Pump Global, Pump FeeConfig, AMM GlobalConfig, user, source authority, source token account, destination token account, buyback recipient, Tokenkeg, Token-2022, System, Pump event authority, Pump program. For an all-curve route, source authority is the outer user. AMM actually signs its canonical `[b"global_config", bump]` PDA through `invoke_signed`; there is no outer transaction signature for that PDA. The captured IDL requires both user and source authority to be signers. The recovered caller's behavior is corroborated by the saved actual original AMM→Pump CPIs, not by synthesizing signer flags directly.

Each curve contributes exactly five accounts: **base mint, quote mint, curve PDA, base vault, quote vault**. Let C_A = PDA(Pump, `bonding-curve`, A), C_B = PDA(Pump, `bonding-curve`, B), and ATA(C,M) be the Tokenkeg associated token address for authority C and mint M.

| Direction | Outer input/output accounts | First five-account group | Second five-account group | Pump flags |
| --- | --- | --- | --- | --- |
| Buy SOL→A→B | user WSOL account / user B account | A, WSOL, C_A, ATA(C_A,A), ATA(C_A,WSOL) | B, A, C_B, ATA(C_B,B), ATA(C_B,A) | `[1,2]` |
| Sell B→A→SOL | user B account / user WSOL account | B, A, C_B, ATA(C_B,B), ATA(C_B,A) | A, WSOL, C_A, ATA(C_A,A), ATA(C_A,WSOL) | `[2,1]` |

Native endpoint payment uses user lamports. The WSOL account still supplies the interface mint and caller balance metadata; it does not replace the ordinary user signature. The buyback recipient is the authorized recipient's canonical WSOL ATA. All transfer destinations and vault token authorities must be consistent with the relevant mint/curve; token-program checks still apply.

The caller preflight is already mapped at `0x3e0b0/0x3e110` (continuity), `0x3e318..0x3e3b8` (same direction), and `0x3ee18→0x45940` (curve-run preparation after preflight). Pump's parser is `0xdd700..0xde4b8`; it checks the curve PDA, quote relation, and writable accounts. Native base/quote vault address checks are `0x5bec8→0x58bf0` and `0x5c450→0x58bf0`. The non-native quote vault is checked through `0x5c0b8→0x14910`: ATA derivation/comparison is `0x149c8/0x14a40`; correct token-program owner takes `0x14b38→0x15158`, existing token data is parsed at `0x151f0`, mint comparison at `0x152d8`, success at `0x160a8`. The system-owned/missing-account branch can initialize a vault; the proposed scope requires it to exist and does not recover or exercise that branch.

## Intermediate ownership and exact run boundaries

Pump's handler is `0x567d8..0x57c38` (5,216 bytes), per-curve body `0x5b3b0..0x5fc48` (18,584 bytes). The handler computes last-hop status at `0x57328..0x57348`, supplies an optional previous-hop object at `0x57368..0x57370`, supplies the flag at `0x573a8`, and calls the per-curve body at `0x57438`. It retains the returned amount at `0x574f8`, serializes the current hop through `0x57570→0xde4b8`, then stores the next-hop context at `0x57590..0x57930`. Thus hop one is exited before hop two parses/runs; later failure still fails the enclosing transaction.

The previous-hop object has a 32-byte **previous curve base mint** at +0, a 48-byte **previous output vault AccountInfo** at +0x20, a 48-byte **previous curve authority AccountInfo** at +0x50, and the bump at +0x80. This is an in-memory layout, not account serialization. Its base mint is copied by `0x57670..0x576b8` and stored by `0x577d0..0x57808`; output vault comes from the per-curve result at +0x30 and is stored by `0x57810..0x578a0`; curve AccountInfo is cloned/stored by `0x57590..0x57668` and `0x578a8..0x57908`; bump store is `0x578d0`. These fields account for the signer and transfer source without inferring them from a string alone.

The transfer helper `0x5a260..0x5b3b0` branches at `0x5a2b0`: absent prior context uses the fixed source/source authority and calls the checked-token helper at `0x5aa40`; present prior context goes to `0x5aa60`. It compares the stored output-vault key with the requested input-vault key at `0x5ab20`. Equal keys return without transfer at `0x5ab48`; distinct keys construct `[b"bonding-curve", previous_base_mint, previous_bump]` at `0x5ab68..0x5abe8`, then call the same checked-token helper at `0x5b390` with the previous curve authority. The two minimal routes use distinct vaults and therefore require this signed transfer.

Per-curve return fields are next mint `[0..32)`, amount out +0x20, buyback +0x28, and output-vault AccountInfo +0x30, written at `0x5f508..0x5f588`. Buy return selects the base mint/base vault through `0x5eac0→0x5f470`, then `0x5f4c8..0x5f4d0`. Sell return selects the quote mint/quote vault through `0x5eac8..0x5eb30→0x5f4d0`. This output vault is deliberately retained for the following hop; it is not always the fixed user destination.

| --- | --- |

Last-hop=true selects `0x5e130`, then `0x5e1d0→0x93050`: transfer B from ATA(C_B,B) to the fixed user B destination, signed by C_B. |

| Sell A for native output | The next `0x5d360→0x5a260` transfers A from ATA(C_B,A) to ATA(C_A,A), signed with **B's** curve seeds and C_B authority (the prior curve, not the mint being transferred). C_A reserves update. Final native payout is guarded by stored-native quote, sell direction and last-hop status at `0x5e208..0x5e250`; payout helper `0x5e2b0→0x965b8` moves lamports to user. With protocol bit set, native buyback at `0x5eb68→0x58f58` precedes the same final payout checks. |

Ordinary arithmetic is reused only by independently tracing its original call sites: sell quote `0x5cbe8→0xa0538`; buy base `0x5d160→0xa0838` (strictly below reserve exhaustion); buy/sell reserve mutation as above; fee accrual `0x5d8b8→0xa1bd8`. Shared instruction helpers do not justify calling the stopped sell_v2 implementation. The original buy-completion branch reaches `0x57e40`; it remains excluded, and the limited extension must reject before that branch. Complete equality at reserve exhaustion is also excluded even if an individual original case would succeed.

## Fee flags, ordinary-token boundary and quote controls

AMM assigns protocol bit 0 only at the route's native/quote endpoint and creator bit 1 only at the far base endpoint. Thus the root A hop gets protocol fees only, while nested B gets creator fees only. On buys, A receives flag 1 and B flag 2; on sells, B receives flag 2 and A flag 1. Direct arbitrary flag combinations are not required to exercise this narrowly proposed route.

The original masks creator bit at `0x5b458` and protocol bit at `0x5c488`. Buy fee rates are initialized to zero and selectively loaded at `0x5cdd0..0x5ce18` before `0x5ce50→0x806c8`. Sell fee amounts are selectively retained at `0x5cf28..0x5cf78`, and event rates at `0x5cfc0..0x5cff0`, before reserve mutation. Suppressed fees must also have suppressed event rates; suppressing payouts alone is insufficient.

Fee selection is `0x89ec8..0x8a530`: length below 2,512 fails; zero quote and the two native keys select tiers through `0x8a088..0x8a120→0x8a2e0`; USDC selects its stable branch at `0x8a160→0x8a4f8`; an ordinary non-special A follows `0x8a168..0x8a1e8`. The exotic fee struct at +0x68 is used only with account length >4,096 and at least one of its three fields nonzero. Otherwise the flat fee struct at +0x50 is used. Protocol and creator rates are then loaded at +8/+16 of the chosen struct. These offsets describe the parsed in-memory FeeConfig, not offsets to patch in account bytes. Creator override is conditioned on Global's configurable flag and nonzero curve override at `0x8a370..0x8a3a0`; a zero creator suppresses the creator amount at `0x8a430..0x8a458`. The ordinary market-cap helper reads the base Mint supply at `0xa0910/0xa0938`; its separate mode branch must not be confused with an unconditional read of the curve's recorded supply. Ordinary A must not equal either native key or USDC for this exact exotic/flat scope. The current single-native module's unconditional tier selection is insufficient for B.

Only the **legacy early-exit boundary** of the transfer-fee reader is used: owner comparison `0x94938` against the exact Token-2022 program key branches at `0x94950` to `0x94b00` for a different owner. That block returns zero/absent transfer-fee metadata; the absent case at `0x94e28..0x94e50` returns fee zero. Independent token-program selection at `0x58668` still requires Tokenkeg or Token-2022, so the proposed route fixes Tokenkeg with ordinary lengths. No extension-dependent body or fee experiment was added or investigated.

No QuoteControl account is supplied to this route. All remaining accounts are consumed in validated five-account groups. Neither the two-curve account contract nor this bounded path needs to parse the separately owned `quote-control` PDA. Current recovered QuoteControl state and creation code describe eligibility/reserve selection when a curve is created; those are different instructions and are not reimplemented here. The route's ordinary fee selector compares its stored quote with fixed native/stable keys; it does not perform a live QuoteControl membership lookup. The inspected path does read Global's creator-fee configurability and buyback settings. This is not a claim that arbitrary synthetic C_B state had a legitimate historical creation, or that removing a quote from a list proves any creation policy can be ignored. Existing full curve state is a prerequisite. For any later synthetic fixture, that provenance must be explicit; no initializer is to be used as a workaround.

## Proposed independent extension and remaining acceptance work

A separately authorized implementation can extend only `multi_hop_curve.rs` to these two exact group orders, using its own independently traced previous-hop object, Tokenkeg transfers, zero-stored-native root handling, exotic/flat fee selection, and non-last output suppression. It must preserve all existing one-curve behavior, keep the instruction PARTIAL, use the genuine captured AMM caller, and reject all other route shapes. Pre-existing canonical accounts, ordinary mint/account lengths, two distinct curves, strict non-completion and no holder/cashback/Mayhem are explicit boundaries. No change to v3, sell_v2, incentives, quote-control handlers, AMM initialization or compiler settings is required.

The immediate blocker is **acceptance evidence**, not a missing signer route: no saved ordinary Tokenkeg two-curve positive comparison exists in the inspected corpus. The next stage would still need independent source review and explicitly authorized, bounded normally signed original-versus-candidate comparisons for both orders, exact intermediate vault amounts/authorities, flags/events, fee accrual, state/write ordering, rollback and endpoint balances. This report neither creates those fixtures nor claims their outcomes. The original native root with stored WSOL rather than zero, missing ATA/rent-reallocation paths, completion, longer/mixed routes, stable quotes, Token-2022, extensions, v3 and every stopped lane remain outside this proposal. Full ELF equality and the security audit remain incomplete.
