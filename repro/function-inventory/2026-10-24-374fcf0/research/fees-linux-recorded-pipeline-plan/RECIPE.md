# Fixed Fees Linux counterpart of the recorded Darwin pipeline

This is a reviewable proposal for **one Fees build at `4ffe8bd88761059693e481ae972443c10204f7af`: Linux v1.44 compilation followed by Linux v1.52 objcopy, using the exact recorded SDK sources**. No helper, installer, compiler, tracer or workflow has been executed. The prior proposals and failed attempts remain unchanged. The proposal does not claim the original historical recipe or predict ELF identity.

The 22 source inputs are frozen in `proposed_core_linux_v144_inputs.json` and bundled under `source/`. They agree with the accepted Darwin `readme-provenance-v144` build, SHA-256 `a9c4ea9e47356a91bf9bd97318746a7c207b873e32485d7786853f048d7d4afa`. The newer Fees social-layout source is deliberately outside this fixed baseline. Source paths, lock, profile, features and compiler arguments retain the existing helper's values.

`recorded-sdk/` contains all 53 exact SDK source files recorded in `work/fees-readme-provenance/main-build`. The helper must copy these frozen bytes; it must not generate a replacement installer. Compared with official Agave 2.1.21, 52 files are byte-identical, and the installer differs only in its already-existing `version=v1.43` → `version=v1.52` line. The recorded installer SHA is `a2ce4b4cd8266a5625ace5fda51a79de66e730134f4b89bfe1655f9a8698e9b2`; the official installer SHA is `72115529656e060c68b1a5498db99a8132fdd629036e37394f813d6d31b3b4aa`. `recorded-sdk.tar.gz` is a convenient exact-file export, hash-bound in `recipe.json`.

The recorded installer chooses Criterion v2.3.3 on Linux and v2.3.2 on Darwin. The root agent explicitly resolved the earlier v2.3.2 wording in favor of this unchanged Linux branch. No uname spoofing, branch modification or marker substitution is proposed. Criterion setup is an installer dependency after Rust compilation; the observed driver and strip command do not invoke or link Criterion into the SBF output. The eventual process trace must be retained to confirm the actual Linux phase behavior.

The intended sequence is:

1. Use a fresh Linux x86_64 runner and a separate checkout of exact revision `4ffe8bd…`. Export and hash only the frozen 22 source paths, preserving relative paths. Keep the root helper's separate `fetch-target` and `target` directories and its tested source/dependency drift checks. Reject existing owned platform/Criterion cache paths; leave HOME unchanged.
2. Download and verify the three official tool archives and Criterion binary archive before extracting. Extract the compiler and stripper into separate immutable directories. Extract Criterion's actual single archive root with the same one-component removal used by the installer. Populate only the corresponding real cache payload links: v1.44/platform-tools, v1.52/platform-tools and v2.3.3/criterion. Do not create SDK dependency links or completion markers.
3. Verify official SDK contents from Agave, compare them against the frozen recorded SDK, and require exactly the documented one-line difference. Copy the recorded SDK without any dependencies directory. Do not pre-run its installer: that would leave a v1.52 completion marker before the build driver selects v1.44, potentially allowing v1.44 stripping later.
4. Bootstrap the same pinned host Rust/rustup metadata/fetch environment. Verify the unchanged public lock and all crate archive/source bytes. Require the separate compiler target empty immediately before the sole build invocation. Preserve the same cargo-build-sbf command and its built-in empty-prefix remap; add no compiler flags, feature selection, profile overrides or source-path transformations.
5. Observe the one unchanged command using an external `strace` process, recording actual successful exec calls, process working-directory changes and link replacements. The proposed observer uses per-process logs and records its native executable hash, version, runner image and package manifest. It does not wrap or replace rustc, objcopy, SDK scripts or program code. No automatic tracer installation or untraced fallback is proposed. Root must review this observer and confirm the selected runner provides it and permits tracing before dispatch.
6. Let cargo-build-sbf naturally select v1.44 for compilation. After compilation, let strip.sh → env.sh → the unchanged recorded install.sh legitimately link Criterion v2.3.3 and platform-tools v1.52 from the verified caches, create its own completion markers and update the isolated solana alias. Then let its actual v1.52 objcopy perform stripping. Keep all raw logs and phase transitions; a final symlink alone is insufficient to establish the entire chronology.
7. Hash tools, source, SDK and dependency trees before and after. Require final SDK and solana links to select the verified v1.52 directory and Criterion to select its verified payload. Check the actual markers created by the installer. Compare emitted unstripped/stripped `.text` and all allocated runtime sections, including content and address/size/type/flags, without changing either ELF. Preserve the original comparison only after successful source compilation. Preserve every failed outcome and exclude generated keypair paths before any content read/hash/archive.
