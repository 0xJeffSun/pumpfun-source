# Retained Darwin SBF compilation and post-processing provenance

The current Fees and Pump retained build evidence supports **v1.44 selection for Rust compilation followed by v1.52 post-processing**. The accepted Mayhem build selects v1.52 in both phases. No new build, executable invocation, source change, runtime probe or generated-keypair read was performed for this review.

The saved command and `selected_toolchain` fields identify the requested compilation version. The official 2.1.21 driver selects and links that platform before invoking `cargo +solana build`. The `rustc_sha256` field is measured separately by the repository helper from the requested version's cache path after the build; it is not an audit of every compiler process. Current cached compiler bytes match the saved hashes: v1.44 `1f26338cc2cabd0a6057dcbd0528bba262b23ca1296d357a55304ee31d1d9e5a`, v1.52 `c58ec8ad482a40216152a4e4a6172f485be22a7f4482623e7e3cdf6c7085beb8`. The driver's version banner reporting its built-in v1.43 is likewise not the requested compilation version.

After compilation the driver invokes `sdk/scripts/strip.sh`. That script sources `sdk/env.sh`, which executes `sdk/scripts/install.sh` before running `sdk/dependencies/platform-tools/llvm/bin/llvm-objcopy --strip-all`. Each retained installer is SHA-256 `a2ce4b4cd8266a5625ace5fda51a79de66e730134f4b89bfe1655f9a8698e9b2`; its sole difference from the official installer is `version=v1.43` changed to `version=v1.52`. The existing build helper copies the SDK without its dependencies directory. With no completion marker, the installer's platform branch removes `platform-tools*`, links or downloads its selected v1.52 artifact, creates `platform-tools-v1.52.md`, and replaces the isolated rustup `solana` alias.

The retained logs show the installer trace after `Finished release`: Fees lines 214/215/222, Pump 369/370/377, and Mayhem 172/173/180 respectively identify build completion, installer rustc inspection and alias relinking. Each retained SDK currently has a `platform-tools-v1.52.md` marker and a platform-tools symlink resolving to `/Users/shawwalters/.cache/solana/v1.52/platform-tools`; each final rustup alias resolves through the same location. The selected `llvm-objcopy` bytes are snapshotted here, SHA-256 `12415dc01e08e4f606a1a4eac8c197d560c7883161d266312c821bf5db7bf8be`, 5,068,448 bytes. These observations strongly support the v1.52 stripping attribution, but no historical per-process executable hash was recorded. Current hashes and retained symlink state cannot substitute for such an audit trail.

Criterion is an installer dependency in this chain. On Darwin it selects v2.3.2, while on Linux it selects v2.3.3. The three retained Darwin SDKs contain the Criterion symlink and v2.3.2 completion marker. This setup happens after Rust compilation because stripping enters the installer. Neither the observed strip command nor the build driver invokes or links Criterion; its presence should not be reported as a Rust compilation input based on this chain alone.

The six saved ELF files are included for a direct raw-section comparison. Each stripped `.text` payload is exactly equal to its corresponding unstripped `.text`. Among shared file-backed sections, only `.shstrtab` differs. Thus this provenance correction does not invalidate function-body bytes already read from these particular outputs. It does not establish that v1.44 and v1.52 objcopy would produce the same whole file, and no alternative stripping experiment was run.

The official Linux SDK blocker remains separate. Its installer is unchanged and defaults to v1.43; the same strip chain can select v1.43 after a requested v1.44 or v1.52 compile. The already sealed Linux proposal records that issue and remains unready for dispatch. No installation marker was fabricated and no installer was edited by this review. Future evidence should record compiler selection and post-processing tool hashes as distinct phases, including SDK dependency link/marker state before and after each phase.

`observations.json` binds 39 snapshots to exact observed paths and current metadata. `analysis.json` records all section hashes, command/version relationships and the exact one-line installer diff. Run `python3 -B verify.py` from any directory; it verifies the package seal and rederives the static findings entirely from bundled files. The historical absolute paths are provenance strings only and are not accessed by the verifier. The archived driver source is the same official 2.1.21 source frozen in the Linux proposal; this review does not claim to rederive that compiled driver's executable identity from source.
