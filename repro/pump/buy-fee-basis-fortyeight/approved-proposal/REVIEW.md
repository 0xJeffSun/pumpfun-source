## Claim boundaries and exemption/decoding limitation

The correction establishes the cap expression for executions that reach the current cap sites. It does **not** establish whole-buy or full fee-wrapper equivalence. Original whitelist equality bypasses both cap calculation and tier selection after its typed admission. Current `fee_config` is unchecked data decoded later in each buy body; it is not the original already-decoded typed object. This patch deliberately does not add a whitelist exemption or skip decoding. Invalid FeeConfig and whitelist inputs can still have different failure/fee behavior. A later exemption change needs independent admission/ordering evidence; it cannot be justified by this helper alone.

Current `buy` calculates its quote before the cap and can reject a zero-base input earlier (for example, checked denominator subtraction). The new helper's zero-base6026 guard therefore does not restore original whole-handler error precedence. `buy_exact_quote` changes from its inline checked-div error to a natural guard using the same Pump code. The guard's source-origin bytes will naturally differ; no historical coordinates are synthesized. Equal supplies and Mayhem mode preserve the previous cap value, but this fact alone is not a general semantic-equivalence proof.

Missing whitelist reserve mutation/reload timing, common volume initialization, fee accrual timing and late event snapshots remain separate issues documented by the source-only parent review. None is activated or rearranged here. No sell mode selector is changed based on buy-only evidence.
