# BuyV3 B5: ordinary fee wrapper and mode contract

This is a source-only proposal against the **unaccepted** `buy-v3-authentic-partial-composition` fragments. It is not a replacement for current BuyV3. It adds the original fee-wrapper boundary around the unchanged ordinary borrowed selector, keeps its AccountInfo clone alive through the fallible computation, and expresses the BuyV3 complete/cashback preflight using ordinary Anchor errors with source origins. No build, transaction, fixture, main-source change or compatibility dispatch was performed.

Current baseline is the published Pump final-error-metadata checkpoint: candidate `2aa18c73e517d9f74063633ea5d5b15f187d63e4dd4c09678b852afdd588cbc3`, symbols `78cbc62e21a5df9f16ee346f0609441168f52088157bc601851d10e7e3cf757d`, with all 37 current source hashes. Current normalized helper matches are naming evidence only; this package does not compare a newly compiled proposal. The original SHA is `7a19affaa2c6187e04a5fe0ea298cee81fa5eb8c24cfcc30d85f615e89f7b02d`.

## Exact original boundaries and order

`closure-ledger.json` retains 11 complete/bounded instruction windows, every direct call in those windows, 22 complete immediate target windows, eight consumed data slices, and all direct callers of the five central helpers. Other direct callers are enumerated without interpreting their bodies; no SellV3, sell_v2, incentives or extension behavior is inferred from their use of a helper.

1. **Early checked FeeConfig is fixed, not lazy.** The typed parser calls `0x103010 -> 0x3cc8` before body entry. `[0x3cc8,0x3e38)` calls `[0x133e0,0x134a8)` and wraps its successful 144-byte account value in a Box with alignment eight. Its reader invokes the ordinary account reader `0x13498 -> 0x92d0`; failure propagates without constructing a successful Box. The accepted prior parser/type contract retains the foreign owner, discriminator, both vectors and mandatory exotic tuple. Nothing in the new fee wrapper re-deserializes or clones these vectors. Later parser code loads the **stored bump** from boxed value+128 at `0x1051f8`, stores the one-byte seed at `0x105248`, and calls address creation at `0x105300` with three seeds: `fee_config`, the captured Pump program ID, and that stored bump. No canonical bump or alternate account admission is substituted. Existing `fee_account.rs` and `buy_v3_context.rs` are unchanged.

2. **Mode is after curve preparation.** `0x147c08 -> 0x3cd50` must return the success tag before `0x147c50 -> 0x7e0b0`. The latter receives complete from curve wrapper+161, cashback from +163, and literal `r4=0`. `[0x7e0b0,0x7e490)` first branches on complete, yielding error6005. Only when complete is false does it test the allowance argument and cashback flag, yielding6094 if cashback is true and allowance is zero. Success is tag2. Therefore BuyV3's specialization is complete rejection first, then cashback rejection. Neither Mayhem nor token-program selection is inspected by this helper. The mode errors have no compared values; they carry `programs/pump/src/trade_v3.rs` lines149/150 in original data. Proposed `require!` preserves semantic error construction but naturally has different source coordinates; no old path/line is spoofed. Existing `.into()` calls in the draft discarded that origin metadata.

3. **Whitelist precedes the fee body, not account parsing.** `[0x7fde8,0x801f8)` takes return pointer, BuyV3 account context and quote amount. It copies the signer key and compares it with Global+648 (`whitelist_pda`) at `0x7fe80 -> 0x1b3678`. Equality at `0x7fe98` jumps to `0x800f0`: four result words at offsets8/16/24/32 and success discriminant at0 are zeroed. This returns zero protocol/creator amounts **and rates**, not merely zero charges. It skips AccountInfo cloning, length read, threshold and table selection. It does not bypass the earlier typed parser or PDA validation. The draft's surrounding whitelist fence remains: the source addition does not expand current acceptance and cannot claim a newly supported whitelist transaction.

4. **Borrow/lifetime and threshold order on the ordinary path.** Nonwhitelist loads the existing boxed FeeConfig at context+96, its AccountInfo reference at value+136, increments its two Rc strong counts, and forms the temporary AccountInfo. `0x7fff8 -> 0x1a2a68` reads its data length. Then `0x80028 -> 0xa08f8` computes the threshold. Error result is copied out before the two Rc releases at `0x80068..0x800e8`; success passes the previously read length, low/high threshold words and original quote amount to `0x80180 -> 0x89ec8`, then releases the same Rc references at `0x80188..0x801f8`. There is no account-state write, CPI, reload, vector clone or second deserialize in this wrapper. The copied AccountInfo is deliberately retained through the selector in `fee_mode.rs`, including its error return. Data-length RefCell borrowing and allocation-abort internals remain the locked framework contract, not an always-success assumption.

5. **Ordinary threshold is actual mint supply.** `[0xa08f8,0xa0bf0)` reads decoded curve virtual base+64 and rejects zero before reading supply. With mode byte+154 zero, it uses the decoded mint's u64 at+40; it multiplies that supply by curve virtual quote+72 through `0xa0978 -> 0x1b55c8` and divides the u128 result by virtual base through `0xa09b0 -> 0x1b4088`. The ordinary threshold is floor(actual_supply * virtual_quote / virtual_base), never curve total supply. Error6026 contains the original lib.rs line2481 origin. At nonzero mode, the source pointer instead becomes decoded curve+96. Its correspondence with the curve total-supply field is retained as an **excluded-mode input boundary only**; no Mayhem implementation, initializer, extension branch or new runtime coverage is supplied. The unchanged surrounding Mayhem fence is still required by this ordinary helper.

6. **Selector and pretrade legs stay fixed.** The borrowed selector `[0x89ec8,0x8a530)` remains the previously reviewed source: length gate2512, first/second/exotic selection, reverse tier search, enabled nonzero creator override, separate ceiling/narrowing per protocol and creator leg, creator-zero amount suppression without erasing the selected rate. The first fee caller is `0x148308`; the existing residual calculation calls the same wrapper at `0x82ff0`. Both still consume the pretrade context, with their own quote amount and fresh length read; the first fee result cannot update the second threshold. The proposal only replaces their ordinary selector call sites with the shared wrapper. Residual pricing and settlement are unchanged and remain with their separate owners.

## Source delta and remaining limits

`proposal/fee-mode-only.patch` adds `fee_mode.rs`, includes it, replaces the two inline mode checks, and replaces the two selector call sites. `make_proposal.py` deterministically reproduces these exact three output files from the retained parent source. `fee_selection.rs`, `fee_account.rs`, typed parser, amount/optional-fill functions and every admission fence remain byte-identical. This source is a natural contract, not proof of historical Rust spelling, exact layout or full code generation. Required host types/macros are those of the unaccepted composition; no successful compile is asserted.

The stored-bump and mandatory FeeConfig-tail obligations remain fixed even for a fee-exempt signer. There is no lazy parsing, account-owner relaxation or source-path fabrication. Source-origin diagnostics in the unchanged ordinary numeric selector adapter are **still incomplete**; preserving numeric codes does not prove original Anchor metadata. All data/calldata lifetimes beyond the immediate retained targets, allocator panic behavior and downstream quote/settlement semantics remain separately bounded.

All **117 historical rows (105 successes, 12 failures)** are retained and hash-checked, including every Token2022-base row. No row is called new coverage, no fixture is changed, and the inherited Tokenkeg-only source fence still excludes them. This package therefore cannot claim to preserve the runtime corpus or be promoted as complete BuyV3. Quote-vault and settlement closure are separate active assignments. Extension implementation, sell_v2 transfer-fee, incentives and Mayhem initializer work remain excluded. Full-original equality and audit completion remain false.

A packaging-only first attempt guessed `symbols.so`; it failed before copying that file. The actual immutable basename is `unstripped.so`. The failed preparation script and diagnostic are retained under `failures/`; no compiler or target ran. The final verifier imports only source with Python `-B`; there are no cache, generated keypair or telemetry files.

Verify from this directory or a separate copy with `python3 -B verify.py`; add `--repo /path/to/repository` to recheck the 37 current source inputs and exact selected upstream bindings. This is a saved/static verifier, not a runtime test.
