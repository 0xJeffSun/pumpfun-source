# Ordinary BuyV3 source composition

This is a concrete **uncompiled, unaccepted source proposal** against fixed checkpoint `476ecf0d31a8dae66dc6e2fb0a97f19d4f163e40`. `baseline.patch` changes only the BuyV3 wrapper context, the BuyV3 body, and adds its dedicated context and two private helpers. `proposed/programs/pump/src/` is an overlay on that checkpoint, not a replacement standalone repository. The unchanged dependency lock, account/event declarations and baseline files are in `baseline/`. Apply the patch to an isolated copy of that checkpoint for subsequent root review. No parent source, other handler, configuration, prior publication seal or completion count was changed.

The composition implements both pricing/event legs; separate typed account admission including early numeric FeeConfig decoding; volume creation and delayed key initialization; native whole-input funding and direct buyback debit; exact fee selection using real mint supply; and corrected event metadata and late errors. It additionally recovers curve rent preparation and existing token-quote vault/user admission. It does not claim historical Rust identity, binary reproduction, complete original account acceptance, or whole-program equivalence. No compilation, typechecking, target execution, transaction fixture, runtime probe or network operation was performed.

## Wrapper, account admission and successful exit

The inherited original wrapper window is [0x1286c8,0x128c28), parser [0x102578,0x105b78), body [0x147ba0,0x1489f8), common body return [0x148600,0x148620), and generated exit [0x107b38,0x107f78). Signed calls establish 0x128808 → 0x102578, 0x128930 → 0x147ba0, 0x128978 → 0x107b38. Exit follows successful body tag 2, never a failed body. These labels identify evidenced windows, not historical function names.

The wrapper retains its discriminator/argument machinery, two u64 arguments and OptionBool, and routes `Context<BuyV3>` to `trade::buy`. The ordinary branch does not use the optional-fill flag; no whitelist branch is implemented. Existing `pub use trade::*` exports the new Accounts context and generated client context alongside the existing types. SellV3 is not changed or reused.

Context slot order is Global +0, base mint +8, quote mint +0x10, base program +0x18, quote program +0x20, curve +0x28, base vault +0x30, quote vault +0x38, signer +0x40, base user +0x48, quote user +0x50, volume +0x58, FeeConfig +0x60, recipient +0x68, System +0x70; event authority and program follow. The declaration uses actual Anchor account types rather than late raw decode success stubs.

Both mints are boxed InterfaceAccount<Mint>. Both token programs are executable TokenInterface accounts. Native quotes still undergo typed mint admission. The curve constraint is precisely `supplied == stored || (stored == zero && supplied == WSOL)`. It is asymmetric: stored WSOL is a token quote, not native zero. The native path adds no mint-owner/supplied-program equality not present in its admission path.

Global and curve are owned checked Accounts with their PDA constraints. The base vault retains associated-token mint/authority/program constraints. **The base user has only mutability and token mint constraints**; the reused SellV3 declaration had added user-authority/program checks. Those are not imported. The unchecked quote vault nevertheless has canonical ATA seeds `(curve, supplied quote program, supplied quote mint)` under the associated-token program, including for native zero. Parser derivation is [0x104b60,0x104e48), call 0x104d58 → 0x1a7eb8. Quote-user and recipient mutability remain explicit.

FeeConfig is `Box<Account<buy_fee::BuyFeeConfig>>`, foreign owner FEE_PROGRAM, with a real AccountDeserialize implementation. Original parser call 0x103010 reaches reader 0x92d0 through its boxed wrappers, then decoder 0x1156f0/0x1159d8. This occurs **before volume initialization** (0x1038f8), not in the pricing body. Locked Accounts codegen deserializes non-init fields before running init constraints. Standard Account::try_from supplies System/zero-lamport 3012, wrong-owner 3007 with keys `(actual owner, FEE_PROGRAM)`, and borrow checking. The original reader's zero-owner and FEE owner constants plus 0x9480 → 0x1a29f0 resolve its formerly opaque initial predicate. Decode validates discriminator, prefix, both vectors and mandatory exotic tail. Trailing bytes remain permitted; no invented sorting, cap or rate validation is added.

Fee address validation uses the **decoded stored bump**, not a fresh canonical bump. At 0x1051f8 the decoded bump is loaded and supplied through 0x105248 to create_program_address at 0x105300 → 0x1a7ff0. The declaration uses `bump=fee_config.decoded.bump`. It does not claim that a noncanonical but valid stored bump is invalid. No body re-decode remains. Each fee selection still re-reads current AccountInfo length, as original, rather than caching the admission-time length.

Volume is `Box<Account<UserVolumeAccumulator>>`, `init_if_needed,payer=user,space=137`, canonical PDA `[user_volume_accumulator,user]`. Existing accounts must pass owned decode, exact allocation, rent and mutability checks; System-owned accounts use real create/transfer/allocate/assign processing from the locked macro. The 106-byte serialized prefix has two booleans, user and eight integer fields; the 31-byte allocation suffix is not reset. The user key is filled only if zero, **after base TransferChecked succeeds and before fee accrual**; a preexisting nonzero key is preserved without an invented equality check. No volume metadata is zeroed. Generated exit serializes curve and then volume after the complete successful body, including event CPIs. The appended event_cpi fields use the locked macro's authority PDA and AccountInfo program representation. System program and signer checks are standard typed checks. The proposal relies on actual generated deserialization, init, constraint and exit behavior; it does not skip malformed input admission. Cross-failure precedence and every diagnostic origin in the generated expansion are not certified identical to the original compiler expansion.

## Concrete body and new control-flow closure

The first `buy_domain` check marks the proposal boundary, **not an original business rule**. Within it the body starts with curve preparation: 0x147c08 → 0x3cd50, current data length at 0x3ce88 → 0x1a2a68, target `max(length,166)` at 0x3cf20, preparation call 0x3cf48 → 0x3d250. For length ≥166, 0x3cf70 branches to successful return 0x3d230 after preparation. The short-account growth branch is excluded, not replaced with success.

Preparation compares stored quote to zero at 0x3d2c0. Native reserved funds are `creator_fee + protocol_fees`, then `real_quote_reserves + fees`, with checked additions through 0xa2188 and its caller. Token quotes reserve zero lamports. Rent::get (0x3d4c8 → 0x1a0a20) and minimum_balance(target size) (0x3d598 → 0x1a0ae8) precede `available = lamports.saturating_sub(reserved)`. If minimum exceeds available, transfer exactly the difference from user to curve via System (0x3dc50 → 0x19e090). Otherwise no transfer. Mode checks occur after this preparation: complete first, cashback second in [0x7e0b0,0x7e490). Earlier proposals omitted this preparation or reversed those checks.

Let request A, pretrade virtual base X, virtual quote Y, real base R, real quote Q. First quantity S=min(A,R); S=0 is BuyZeroAmount6020. D=A−S. Quote preflight runs before pricing: native stored-zero takes the 0x7f150 → 0x7f888 shortcut, checks the raw recipient key against Global buyback recipients, and returns the native adapter. Token quotes call 0x7f600 → 0x14910 for vault admission and 0x7f868 → 0x160d0 for user admission, then recipient checks through 0x7f908 → 0x7e490. Existing token-vault owner/mint checks are implemented; the context has already proven the identical immutable ATA keys. The vault helper imposes no extra decoded-authority equality. User token admission checks program owner, mint, and token authority=user, with actual/expected keys. Recipient checks program/mint, nonzero authorized decoded owner, and its ATA. Native membership never decodes the recipient as a token account.

First quote is `q1=floor(S*Y/(X−S))+1`. F1 uses **base_mint.supply**, X, Y, stored quote, creator and configuration captured before any reserve stores. Residual pricing for D>0 uses `B=actual_base_vault.amount−S`, `T=Q+q1−migration_fee` for native (no migration subtraction for token quotes). B=0 gives6021; T=0 gives6024; B≤D gives6021 with `(B,D)`. Then `q2=ceil(D*T/(B−D))`. F2 independently selects and rounds fees with the same pretrade inputs, not post-first-leg reserves.

Exact selector: compute `threshold=floor(actual_mint_supply*Y/X)` before checking serialized length. X=0 gives6026; narrowing fees gives6025. L<2512 gives6097. Stored zero, QUOTE_1 and QUOTE_2 select table one. QUOTE_SECOND requires L>4072 and selects table two; otherwise6096. Other quote keys select exotic iff L>4096 and any exotic word is nonzero, otherwise flat. Empty selected table gives6096. Below first threshold choose first; otherwise search backward for the first qualifying tier, preserving original unsorted-vector behavior. Apply the global-enabled, nonzero curve creator override once. Compute protocol ceil fee before creator ceil fee, independently for each leg. Zero creator suppresses **amount only**, preserving its selected rate in events. LP rates participate in exotic nonzero selection but are not charged in ordinary buy fees.

Per-leg buyback is floor(protocol_fee*buyback_bps/10000), summed only afterwards. P is combined gross less Bk (combined buyback); user obligation is P+Bk. Max error6002 carries `(max_sol_cost, user_output)`, the order evidenced at 0x1487e0. Then store first-leg virtual base, real base, virtual quote, real quote; transfer S+D base tokens once using curve PDA signer; fill the volume key if zero; accrue retained protocol then creator for F1, overwrite residual counters, accrue retained protocol then creator for F2.

Token settlement transfers P and Bk separately from the user quote account, skipping each zero amount. Native settlement System-transfers **all P+Bk from user to curve** once (unless zero), then directly debits Bk from curve lamports and credits recipient. It does not split native System transfers or subtract Bk before user funding. Release the source mutable borrow before reading recipient balance, preserving aliases. Checked debit/credit use actual ProgramError::ArithmeticOverflow, borrow failures propagate; no post-CPI account reload is invented.

TradeEvent uses q1,S,F1 and the first-leg reserve snapshots. Metadata comes from the four volume fields; current creator accrual includes both F1 and F2. Creator rate survives creator-zero amount suppression. Holder reward rate/amount are independently masked by holder flag. Native SOL aliases are zeroed only for nonnative quotes; stored quote, quote fields, empty shareholders, track=false and adapter trailing zero retain the ordinary contract. Both original per-leg rates are retained independently rather than re-derived from rounded amounts.

Emit Trade log/self-CPI; if first real base is zero mark complete and emit Complete log/self-CPI; for residual D>0 then check **B≥D**, then checked **T+q2**, both error6024, before PostCompleteBuy event construction/log/self-CPI. These late checks remain after Complete CPI even though the early pricing inequality constrains B. PostCompleteBuy carries F2 rates/amounts and pool before/after values. A late failure is not silently promoted to instruction success; standard rollback is required.

## Rich errors and supported interfaces

Numeric codes alone are not claimed to reproduce error objects. The implementation converts the existing PumpError or Anchor ErrorCode enum to `anchor_lang::error::Error`, obtaining AnchorError with real name, code and message through the locked 0.31.2 error macro. Fee decode uses these variants for3001/3002/3003, selection6096/6097, math6025/6026. It does not collapse them into ProgramError::Custom. Account-name decoration comes from the typed field reader; FeeConfig mismatch first carries `FeeConfig` and field expansion attaches `fee_config` as actual Anchor supports.

Explicit comparisons use supported `.with_values` and `.with_pubkeys` APIs: zero amount `(0,0)`, residual zero B/T `(0,0)`, B≤D `(B,D)`, max `(max,actual)`, and owner/mint/address comparisons `(actual,expected)`. Calls 0x148078,0x82800,0x82ab8 all reach0x340; the retained prefix shows the zero first-value storage and r4 second-value formatting. Late residual6024 has no fabricated compared pair. The fee6097 direct constructor has no numeric comparison decoration added. No historical file path or source line is invented. Existing baseline account macros may produce their natural current-source diagnostic locations; those are not historical origins. Complete original diagnostic object identity, including original source origins and heap allocation, remains unproven.

Cargo pins Anchor lang/spl0.31.1, while Cargo.lock resolves anchor-syn/derive/error macros0.31.2, solana-program/account-info2.3.0 and program-error2.2.2. `dependencies/` contains published same-checkpoint sources for the concrete APIs used. Account requires Clone+AccountSerialize+AccountDeserialize+Owner; the foreign wrapper implements all four, and Discriminator. Error converts Borsh/std IO and ProgramError; AccountInfo cloned values retain shared RefCell lifetimes. TransferChecked takes the actual four typed AccountInfos and CpiContext signer seeds with statement-bounded temporary lifetimes. The locked emit_cpi expansion directly reborrows `ctx.accounts`; keeping `a=&mut *ctx.accounts` alive across that macro and subsequent completion work would conflict. This proposal instead supplies `buy_emit_cpi` with the same Event serialization, EVENT_IX_TAG_LE, signer authority, seed/bump and invoke_signed error mapping, passing `a.event_authority` through its existing borrow. This is a concrete interface correction, not a success shim. Includes are private children of trade, so super::FEE_PROGRAM and crate::PumpError resolve without changing parent configuration. No new crate, speculative dependency version, undefined helper or error-name invention is required. Static inspection is not a substitute for root's future compile/typecheck.

## Bounded premises versus remaining application work

Bounded framework/runtime premises: the locked Anchor Accounts/event macros and ordinary Borsh field decoding; ordinary Tokenkeg 82-byte mint/165-byte token-account decoding and identity amount adapter; PDA derivation, Rent, Clock, System/SPL transfer processing, self-event CPI, shared AccountInfo borrow semantics, successful bounded allocations/formatting and transaction rollback. These are delegated to concrete linked APIs, not modeled as always-success functions. Each fallible API propagates its actual error. The proposal does not need allocator panic equivalence to express its business logic.

The source domain is explicitly nonwhitelisted, nonMayhem, noncashback; legacy Tokenkeg base mint/program and ordinary account lengths, legacy quote mint; full curve allocation at least166; buyback bps≤10000. For nonnative quotes it additionally requires Tokenkeg quote program and already allocated ordinary quote vault/user/recipient accounts. Native supplied quote-program admission remains the original two-program interface; no extension handling is entered. Nonzero creator/holder configuration is supported, including creator-zero amount suppression. Unsupported domain returns the existing ReconstructionBranchUnsupported marker, which is **proposal policy, not recovered historical rejection**. Cashback still reaches its original post-preparation check. These bounds intentionally do not broaden acceptance to unimplemented modes.

Remaining application work is concrete: the short curve growth/old-layout reader behavior; token quote-vault creation/preparation arm of0x14910; whitelisted, Mayhem, cashback-enabled and extension domains. Those are outside this source domain, and this publication makes no completion claim for them. Native/token ordinary body logic is implemented, not gated on a fabricated success response. Under this domain the remaining uncertainty is generated parser/serializer behavior on jointly malformed accounts, original full diagnostic provenance, and historical Global/curve decoder acceptance versus the existing checkpoint declarations. Root must review these before asserting complete admission equivalence; the baseline declarations are concrete implementations, not proofs of every historical layout. No claim is made that source fences preserve original rejected-input error precedence outside the domain.

The inherited reports' earlier gaps in native funding, event metadata, volume key initialization, actual supply/fee interface and late residual checks are resolved in source here. Their old candidate snippets remain sealed evidence, not files to apply over this overlay. The new source is authoritative for this proposal; do not stack predecessor minimal diffs.
