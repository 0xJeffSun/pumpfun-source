# Ordinary BuyV3 event field reconciliation

**Three concrete findings:** the prior source proposal omits the global creator-fee override gate, emits the first-leg-only creator accrual snapshot on crossing, and hardcodes volume metadata that the original reads from the decoded volume account. `minimal.diff` corrects the first two only within the prior proposal's `normal` branch. `volume_event_fragment.rs` supplies the third correction as an implementable typed interface; its values must come from the separately owned volume parser. This package is not ready for unconditional application. It does not replace missing admission, volume or native settlement with success stubs.

Fixed source checkpoint: `476ecf0d31a8dae66dc6e2fb0a97f19d4f163e40`, read through `git show`. Baseline BuyV3 source excerpt and both boundary documents are retained in `checkpoint/`. The delta is against the separately sealed **proposed** trade.rs, not against a moving root source file. Only that proposal's buy function is changed. Other handlers are opaque preservation. The existing prior seals are copied unchanged and checked for each consumed member. No counts change, no builds/typechecks/fixtures/target execution/network operations were performed, and no parent source was changed.

## Admission, representations and timing

Original ELF SHA256 is `7a19affaa2c6187e04a5fe0ea298cee81fa5eb8c24cfcc30d85f615e89f7b02d`. The wrapper call at 0x128930 resolves by signed register-relative operand to body 0x147ba0. The prior identity chain binds this wrapper to BuyV3. Wrapper [0x1286c8,0x128c28), parser entry 0x102578, body [0x147ba0,0x1489f8), common body return [0x148600,0x148620). Parser/exit admission remains inherited, not newly certified. Ranges are half-open ELF offsets; inspected code virtual addresses equal file offsets. Inferred windows are not historical function identities. Displaced angle-bracket labels are not used for targets.

Let Ctx be the body context. The event helper 0x859b0 receives Ctx in r2, event-authority bump in r3, selected first base amount S in r4, and the caller frame in r5. Wrapper pointers are W=*(Ctx+0x28) for curve, G=*(Ctx+0), U=*(Ctx+0x58) for the volume record. The curve/global decoded payloads begin at wrapper+8; those are in-memory offsets, **not account-data offsets**. FeeConfig has its own layout; its wrapper must not be shifted the same way.

The ordinary path is non-Mayhem, non-whitelist, noncashback, admitted ordinary base/quote adapters. S=min(requested,real base), D=requested-S. q1 is the first quote, q2 the optional residual. First fee tuple F=(Fp1,Fc1,P1,C1); residual tuple has the same order. All tuple words are u64. All successful arithmetic, context identities, Clock/runtime/event invocation, ordinary transfer semantics and normal allocations/reference counts are explicit bounded premises.

The success sequence is: first reserves -> one base transfer S+D -> optional zero volume-user-key initialization -> first accrual -> optional residual counter writes and second accrual -> quote funding/buyback -> event helper -> Clock -> TradeEvent log -> TradeEvent self-CPI -> test real base==0 -> complete byte=1 -> CompleteEvent log/self-CPI -> residual presence test -> late residual-event arithmetic -> PostCompleteBuyEvent log/self-CPI. No second Clock is used. Failures propagate at each interface; emitted log data alone is not transaction success. Runtime rollback is a premise, not re-proved here.

## Actual caller arguments and fees

0x148308 calls 0x7fde8 before reserve mutation. Success fields at caller fp-0xa0,-0x98,-0x90,-0x88 are copied into fp-0x110,-0x108,-0x100,-0xf8 at 0x148350..0x148378. Thus F's order is **fee amounts first, then rates**, not event wire order. At 0x148988..0x148998 its address is passed in outgoing fp-0xff8. Event 0x85a70 receives that pointer and 0x85c70..0x85c98 loads +8,+24,+0,+16. Stores to E+0xc8,+0xd0,+0xf8,+0x100 yield P1,Fp1,C1,Fc1.

0x7fde8 excludes whitelist by comparing user with Global wrapper+0x288; equality returns a zero fee tuple at 0x800f0..0x80118. The assigned non-whitelist path takes the real selector: 0x80180 -> 0x89ec8. The inherited fee contract supplies FeeConfig length checks, ordered table selection, pretrade threshold, ceiling/narrowing and errors. The actual selector bytes at 0x8a378 load Global decoded+0x436 as a byte. Branch 0x8a380 skips the override if zero. Otherwise 0x8a390 loads curve decoded+0x68 as a **u64**, and 0x8a398 skips if that word is zero. Only then 0x8a3a0 replaces C. The source names are `creator_fee_configurable` and `creator_fee_bps` under the published layout correspondence. There is no new maximum-rate check here.

The candidate's unconditional nonzero curve override is wrong when global permission is false. The minimal delta adds this gate within `normal`. It preserves outside-scope candidate behavior rather than asserting those branches correct. Both legs must use the resulting pretrade rates. Protocol ceiling is calculated before the creator-zero comparison. A zero creator makes Fc=0 but **does not zero C** (0x8a438..0x8a4c8). Therefore `creator_fee_basis_points`, residual creator rate and holder rate can remain nonzero with zero creator and zero charged creator fee. Do not replace them with the candidate's effective charging `creator_bps=0`.

The fee interface must supply original-admissible F1/F2, using the published selector's actual serialized length/table/quote-key rules and threshold inputs. `selected(config,cap,!is_sol)` in the existing proposal is not newly certified by adding the override gate: its all-nonnative-to-stable shortcut and its use of curve token supply instead of the inherited mint-supply threshold require reconciliation or an admitted-equality premise. This report closes which tuple values go into events, not unrestricted selection equivalence.

## First TradeEvent: all fields

`fields.json` is the complete ordered 36-field ledger with source types, exact wire offsets/sizes, serializer load/store addresses, event-object offsets and BuyV3 producer stores. It replaces route-specific producer descriptions with this caller's values. The imported serializer is 0x1624b0..0x1639e8; both 0x86188 and 0x86360 resolve to it. Event object E is event-helper fp-0x560. In-memory Rust layout differs from declaration/wire order.

- Mint is the base-mint key loaded through Ctx+8, then wrapper+0x58, then AccountInfo key (0x85b10..0x85b60). User is the key through Ctx+0x40 (0x85ab8..0x85b00). `token_amount` is S, not S+D. `is_buy` is explicit byte1 at 0x85ea8.
- `quote_amount` is q1. `sol_amount` is q1 only when the **stored curve quote key** is all-zero. The compare is 0x85bc8..0x85c20; mask 0x85e70..0x85ea0. This is not an arbitrary external quote-account mint test. Virtual/real SOL reserves have the same mask (0x85ed0..0x85f20); virtual/real quote fields are unmasked (0x86148..0x86160). The curve loads at wrapper+0x48,+0x50,+0x58,+0x60 are post-first virtual base/virtual quote/real base/real quote. Residual pool quantities do not overwrite them.
- `fee_recipient` is 32 explicit zero bytes at 0x85f58..0x85f70, even though separate fee accounting and buyback recipient selection exist. `creator` is curve wrapper+8..+40, with no holder-based key substitution. P1,Fp1,C1,Fc1 are the first tuple values just traced.
- Clock call 0x859e8 -> 0x1a0938 precedes construction. Its successful unix_timestamp word is saved at 0x85a88..0x85a90, copied to E+0x80 at 0x85f28..0x85f30 and reused by both subsequent events. Clock failure skips construction and forwards the existing error result.
- **Volume metadata is not zero-defaulted.** At 0x85aa8, r6=U. Loads 0x85c30,+0x40,+0x50,+0x60 read U+0x40,+0x38,+0x30,+0x28 respectively. Their spill/reload chain 0x85fb8..0x85ff0 writes E+0x120,+0x118,+0x110,+0x108. Wire fields are total_unclaimed_tokens=U+0x28, total_claimed_tokens=U+0x30, current_sol_volume=U+0x38, last_update_timestamp=U+0x40. All are 64-bit loads; the last is interpreted as i64 by the schema. `track_volume` is independently explicit byte0 at 0x86058. False tracking does not imply empty metadata. There is no zero test or metadata mask in this producer.
- Name is exactly three bytes `buy`, not `buy_v3`: caller literal 0x1b6862 and length3 at 0x148958..0x1489a8, copied at 0x85db8. This fixes string wire size to seven bytes including u32 length. `mayhem_mode` is copied from W+0xa2; false under the scope premise. Cashback rate/amount are explicit zero words at 0x86068/0x86060.
- Buyback rate is G+0x420 gated by W+0xa2==0 (0x85dc8,0x85de0,0x86028..0x86080). Buyback amount is settlement return+8, passed at 0x148980, loaded 0x85a60 and stored 0x86078. Settlement 0x84858/0x848a0 adapts total/second buyback; checked subtraction 0x84950 returns first-only buyback. Identity adapters yield floor(Fp1*b/10000), not total buyback.
- Shareholder vector has cap0, pointer2, len0 at 0x860c8..0x860d8. Pointer2 is an alignment sentinel, not a count. The serializer writes u32 zero and no shareholder elements. A holder flag does not change that empty list in this helper.
- Holder selector is a **byte** from W+0xa5 at 0x85dd8. 0x86088..0x860c0 chooses C1 and Fc1 when nonzero, zero otherwise; stores 0x86140/0x86138. It neither replaces creator nor clears ordinary creator-fee fields. Holder rate/reward are u64 on wire. This recovers event selection, not validation of arbitrary holder-configured accounts.
- **creator_fee_unclaimed** is a **u64** loaded from W+0x78 at 0x85dd0, stored E+0x190 at 0x86130. This is decoded curve+0x70. Accrual 0xa1cf8..0xa1ff8 checked-adds Fc into decoded+0x70; settlement calls that helper at 0x840a0 and, if residual exists, again at 0x84138 before entering the event helper. The value is old accrued creator fees + Fc1 + Fc2, including pre-existing fees; it is not Fc1, old+Fc1, a holder default, or zero. The prior `first_creator` capture before residual accrual is therefore wrong for crossing with Fc2>0. The proposed correction reads the curve after settlement, where the original reads it.
- Final unnamed u64 is cost-helper return+0x18: 0x148630..0x148638 saves fp-0x218, 0x148970 passes it at -0xfe8, 0x85a50 loads it, 0x86128 stores E+0x198. The inherited cost-helper contract identifies curve-payment adapter difference; ordinary identity adapters make it zero. This is separate from both buyback return words. No historical name or extension interpretation is asserted.

TradeEvent wire length is **390 bytes**, discriminator `bddb7fd34ee661ee`; self-CPI data is eight-byte prefix `e445a52e51cb9a1d` followed by those 390 bytes, length398. Wire integer encodings are little-endian, booleans one byte, public keys32; no Rust-layout padding is serialized. The retained IDL has only35 TradeEvent fields; the serializer proves the extra final u64. Its BuyV3 wire offset is382, after creator_fee_unclaimed at374. The older route's 401-byte size must not be reused for the three-byte `buy` string.

## CompleteEvent and PostCompleteBuyEvent

After successful first self-CPI and cleanup, 0x86880..0x86890 tests W+0x58 (real base). The zero branch targets **0x86958** by encoded displacement, where complete is set at W+0xa1 before completion construction. No completion event on nonzero real base. Fields and widths, in actual wire order:

| Event | Wire offsets including discriminator | Values |
|---|---|---|
| CompleteEvent | 8 user32,40 mint32,72 curve32,104 timestamp8,112 quote32 | same user/base mint, curve AccountInfo key, first timestamp, stored curve quote key |
| PostCompleteBuyEvent | 8 user32,40 mint32,72 curve32,104 quote32,136 timestamp8 | same keys and timestamp |
| PostCompleteBuyEvent continuation | 144 D8,152 q2_8,160 P2_8,168 Fp2_8,176 C2_8,184 Fc2_8,192 b2_8,200 B8,208 T8,216 (B-D)8,224 (T+q2)8 | second-leg fee record and adapted second buyback; B/T are inferred residual-pool reserves before residual execution |

Complete construction uses Ctx+8/+0x40/+0x28 at 0x86960..0x86a98; direct serialization 0x86b90..0x86cb8 emits discriminator `5f72619cd42e9808`, then user, mint, curve, timestamp, quote. Log length144 at 0x86cc0, self-CPI length152. The curve account key is obtained through *(W+0), not the curve's creator or quote key. Key order and timestamp placement differ in PostCompleteBuyEvent and cannot be inferred from a generic tuple layout.

After completion CPI at 0x873b0, 0x87460..0x87468 checks residual option tag. None skips the third event; Some calls constructor 0x81aa0 at 0x87658 with residual record+8 and the current user/base/curve/quote keys. Outgoing -0xff0 carries the saved first timestamp (0x875c0); -0xfe8 carries settlement's second buyback (0x875d0). Constructor receives the residual tuple `(Fp2,Fc2,P2,C2,D,q2,B,T)` and maps its scalars to the wire schema via 0x81c58..0x81e70. It checks B>=D then checked T+q2 here, after completion CPI; the admitted residual pricing already required B>D. Late failures do not justify moving arithmetic before earlier event CPIs. Both late error branches encode numeric error6024 (0x1788 at 0x81f00 and 0x820a8); exceptional error-object construction remains an inherited boundary. The prior proposed source checks T+q2 before B-D, reversing these two original guards. The two-edit patch leaves this explicitly unresolved: root should guard B>=D before checking T+q2 at this same post-completion point. The admitted B>D pricing premise makes the first guard pass, but does not justify a broader error-order equivalence claim.

Serializer calls 0x876f0/0x87778 target 0x163bf0. It emits `6fb06d8b316cd5fb`, four keys, timestamp and eleven u64s, length232; self-CPI length240. Log 0x87730 precedes CPI 0x879f0. `fields.json` records every field. No holder, volume, accrued creator total or shareholder field exists in these two event schemas. PostComplete creator rate is retained even if creator key is zero; it is not a recomputed holder rate.

## Owner interfaces and remaining application boundaries

**Volume owner:** provide an admitted decoded volume account U, retaining validation and exit behavior. After base CPI and before first accrual, the original compares U+8..+40 (user key) against zero and conditionally copies user at 0x83fa8..0x84060. This package does not implement that write. At event construction expose four 64-bit values U+0x28,+0x30,+0x38,+0x40 after that initialization and all settlement succeeds. `volume_event_fragment.rs` assigns them before the first log/CPI. These decoded offsets are not permission to read guessed serialized offsets from `UncheckedAccount`. The existing full proposed file intentionally still shows the unresolved zero metadata until root integrates the actual volume interface; it is not a complete corrected implementation. Requiring merely an initialized user key does not make those zeros equivalent.

**Settlement owner:** supply first and second adapted buyback amounts, original curve-payment adaptation difference, and post-accrual decoded curve. First TradeEvent requires current creator accrual after both legs; reserve snapshots remain first-leg reserves. Native lamport reload/alias behavior, zero transfers and error order stay with the native owner. Scope assumes quote-key-zero masking agrees with the separately admitted native relation; the candidate `is_sol` predicate alone is insufficient evidence. No account reload or event must be inserted to conceal this boundary.

**Fee owner/imported contract:** preserve F1/F2 rates and per-leg fees, fee selection errors 6097/6096, fee narrowing6025, global override gate and creator-zero amount-only suppression. Returned rates are u64, flags are bytes; don't narrow to u16. The patch is two local corrections, not approval of the proposal's approximate selector. Root must reconcile the exact fee interface plus actual volume data and settlement before claiming complete first-event equivalence.

Context admission, arbitrary holder account acceptance, all excluded modes, full error diagnostics/allocator/drop behavior, original Rust identity, whole-program equivalence and runtime acceptance remain unclaimed. Bounded framework/runtime premises are allowed, but missing application checks are not presumed successful. No handler/completion count changes are proposed.
