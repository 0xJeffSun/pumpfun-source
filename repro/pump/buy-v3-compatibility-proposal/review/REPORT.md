# Independent BuyV3 composition review

**Build readiness: reject the sealed overlay as a replacement for accepted BuyV3.** Its ordinary body is a substantive, statically plausible proposal, but the unconditional context replacement and domain fence erase existing passing behavior. No build/typecheck, target execution, transaction construction, network request, source promotion or completion-count change was performed. This directory is a local sealed review, not a root publication or acceptance.

## Findings and concrete regression evidence

**R1 — blocking, confirmed source/receipt incompatibility.** `composition/proposed/programs/pump/src/lib.rs:100` routes every BuyV3 through `Context<BuyV3>`. `trade.rs:114–120` then invokes `buy_domain`; `buy_v3_admission.rs:5–35` rejects non-Tokenkeg base mints/programs and Mayhem. The accepted implementation uses `Context<SellV3>` and the complete `buy` function in `inputs/accepted/trade.rs:114–181`. Its interface transfer supports the accepted Token2022 base path; its Mayhem buyback rate is zero and holder fields are preserved. These are existing implementations, not newly unsupported domains.

The immutable `repro/pump/nested-ancestry-fortyeight/differential/v3_configured_fee.json.gz` contains 372 comparisons with no mismatches, including 117 BuyV3 rows, **105 successful original/candidate pairs**. Every BuyV3 row has the same Token2022 base mint owner; the successful receipt's base mint allocation is 370 bytes and token accounts are 170 bytes. The review uses ownership/length as evidence that the fence excludes these cases; it does not decode, change, or implement their extensions. The successful subset includes 37 SOL, 37 USDC/Tokenkeg quote, 31 USDC/Token2022 quote cases; overlapping subsets contain 36 Mayhem and 36 holder cases. `regressions.json` retains every BuyV3 index, original result and classification. Cases 0 (ordinary SOL), 2 (holder SOL), 3 (Mayhem SOL), 8 (Mayhem USDC), 10 (Token2022 quote) and 14 (Token2022 quote plus both flags) are concrete successful examples. All 105 must fail to reach successful body completion under the new fence, even if the new parser admits them. This is a static incompatibility conclusion, not a newly executed failing comparison.

The fixed-checkpoint harness `inputs/scripts/pump_v3_configured_fee_differential.py` builds those quote variants with ordinary 82-byte quote mints and 165-byte quote accounts, varies flags at serialized offsets81/124, and compares errors, account state, inner instructions, event payloads and return data. Its signature verification and historical-message machinery remain untouched. No harness is imported or executed. The 105 count is a reviewed subset of this suite, not a replacement for all Pump regression requirements. The original/candidate binary hashes remain in the unchanged receipt.

**R2 — blocking architectural defect: fallback inside the body is too late.** The new context (`trade.rs:408–444`) changes unchecked quote mint to typed Mint, adds quote-vault ATA seeds even for native quotes, replaces unchecked volume with `init_if_needed`137-byte owned state, and eagerly decodes a foreign FeeConfig using its stored bump. It also removes the accepted base-user authority/program constraints. The original parser `[0x102578,0x105b78)` supports several of these proposed changes, but applying them globally changes the accepted wrapper before `buy_domain` executes. Merely deleting the fence, converting BuyV3 to SellV3, or calling the old body after new-parser failure is not preservation. Failed parsing may already have created the volume account. A second parser/exit can also overwrite the updated curve with stale decoded state. Neither side may execute the other's exit.

The accepted quote helper treats supplied WSOL/zero with stored WSOL/zero as native; the proposal admits stored-zero plus WSOL asymmetrically and treats stored WSOL as token quote. That is a real source compatibility difference, not a claim that the broader accepted predicate is historically correct. Receipt evidence above establishes passing base/quote/Mayhem cases, not successful coverage of every zero-key or stored-WSOL variant.

**R3 — remaining error-object/precedence gate, not a proven Rust type error.** Numeric error conversion now constructs real AnchorError variants, but this alone does not reproduce original diagnostic objects. `dependencies/error.rs:337–382` shows account decoration replaces `error_origin`; the fee reader's `FeeConfig` origin becomes `fee_config` under generated field parsing. Source origins are absent for `PumpError::X.into()`, while original bodies contain location-bearing constructors. The raw quote relationship constraint also supplies a different construction route from explicit original key comparisons unless independently reconciled. Do not call numeric code equality full diagnostic equality. Joint malformed-account precedence must be checked at the selected parser boundary. The proposed pre-parser read-only selector below deliberately falls back on ambiguous/failed inspection; it does not assert original error precedence on every malformed input.

## Implementable preservation and integration design

`containment.patch` is an exact minimal *containment* delta against the sealed overlay: restore the original BuyV3 wrapper line; insert the entire accepted `buy(Context<SellV3>,...)` function verbatim; rename the unchanged new body to `buy_ordinary_candidate`. `source/lib.rs` and `source/trade.rs` are its exact output. Keep the overlay's two helper files unchanged. All other handler text and the appended context remain byte-preserved. The accepted nested37 trade/lib files were read from their frozen publication and compared byte-for-byte with **git show476ecf0**; both match. The patch is not against moving main and must not replace newer unrelated root files wholesale. No nested source is changed. The old and composed bodies are both real implementations; neither is a success stub.

Containment intentionally leaves ordinary recovery **unwired**. It is safe preservation source, not completion of composition. `source/dispatch_fragment.rs` provides the concrete next integration fragment: a read-only `choose_buy_lane`, followed by `run_selected_buy` that calls exactly one generated Accounts parser, one existing body, and that same context's exit only after success. It uses owned Global/curve readers solely for selection; never raw guessed offsets, fee decoding, initialization, CPI or writes. Nonlegacy base or quote, Mayhem, cashback, whitelist, short/ambiguous accounts and the other ordinary-domain exclusions select Accepted. Holder by itself does not exclude ordinary legacy source. Both lanes retain their real validations and errors. The ordinary parser still validates signer/PDA/mint/program/volume/FeeConfig/recipient relationships; classification is not account admission.

The remaining integration seam is precise: insert this decision at the BuyV3 generated-wrapper boundary **after the existing discriminator/argument decoder, before account parsing**, pass the original raw slice and post-discriminator argument bytes unchanged, and retain the existing client/IDL 17-account ABI. Preserve instruction logging and OptionBool decoding even though these bounded nonwhitelist bodies do not use the flag. Do not replace the public instruction with an empty Accounts context to obtain raw accounts: that alters generated client/IDL metadata. Do not run this fragment from inside an already parsed `Context<SellV3>` or `Context<BuyV3>`. A custom wrapper/dispatch hook or a properly generated composite Accounts implementation needs separate review; no macro-source or dependency edit is smuggled into this patch. Thus this report supplies implementable bodies, selection and one-exit sequencing, but explicitly does **not** claim a complete drop-in wrapper mux. This seam blocks enabling the ordinary lane, not preservation of accepted cases.

## Original control flow and interfaces reviewed

All locations below refer to signed instruction operands in the unchanged captured ELF (whole SHA256 `7a19affaa2c6187e04a5fe0ea298cee81fa5eb8c24cfcc30d85f615e89f7b02d`, 10,485,715 bytes). Annotated display names are not authority. `review-windows.json` binds the exact original windows consumed; the original packages retain their disassembly-source offsets. These remain inferred windows rather than proven historical function identities.

* Wrapper `[0x1286c8,0x128c28)`: call0x128808→0x102578 parser; 0x128930→0x147ba0 body; successful body tag2 at0x128940 gates exit0x128978→0x107b38. Parse, body and successful exit are distinct obligations. The mux fragment mirrors this single-lane sequencing, not original Rust identity.
* Body `[0x147ba0,0x1489f8)`: 0x147c08→0x3cd50 before mode checks. `curve_prepare_entry.asm` loads data length, chooses max(length,166) at0x3cf20, calls0x3d250 at0x3cf48, and branches to0x3d230 for length≥166 at0x3cf70. The skipped arm is growth, not permission to omit rent preparation for already large curves.
* `curve_rent.asm [0x3d250,0x3dd78)`: stored quote compared to zero; native reserved amount is real quote plus creator/protocol fees. The fee sum at0xa2188 and outer sum each reject overflow with error6024 constructors (0xa2378 and0x3dd00); formatting failure paths are not normal arithmetic panic semantics. Rent syscall0x3d4c8→0x1a0a20 and minimum_balance0x3d598→0x1a0ae8 precede saturating available-lamport calculation0x3d6d0–0x3d708, rent comparison0x3d798 and exact shortfall transfer0x3dc50→0x19e090. `buy_prepare_curve` is consistent under the full-allocation premise. Max trade cost does not absorb that separate rent shortfall. This newly recovered transfer was outside the prior native settlement interval; it can alter balances/inner instructions for underfunded curves even when later trade pricing is unchanged. Do not remove it to make an old receipt pass; retain accepted out-of-domain routing and validate new-domain behavior separately.
* Fee/volume: parser0x103010 reads boxed fee state before volume initialization call0x1038f8. Stored bump load0x1051f8, spill0x105248 and create_program_address0x105300→0x1a7ff0 support explicit bump, not canonical bump substitution. Decoder consumes both vectors and mandatory exotic tail; selection length gates do not permit truncated decoding. Locked `try_accounts.rs` extracts/deserializes non-init fields, executes init constraints, then access checks. Consequently fee decode precedes volume init, while the fee seeds constraint follows it; saying all FeeConfig validation precedes init would be wrong. Existing volume has exact-space/owner/rent checks. The post-base-transfer zero-user write and four metadata fields remain in the new body. Ordinary exit serializes curve and volume; foreign fee state is not written under Pump's ID.
* Pricing/settlement: min(request,real base), zero test, native/token preflight, two independent per-leg fees with actual mint supply and pretrade reserves, first reserve stores, one base transfer, volume user fill, retained protocol/creator accrual, then quote settlement. No fee re-decode or post-first reserve threshold is introduced. Empty tables and length gates remain failures. The selector gate for creator override includes Global permission; creator-zero suppresses charged amount but retains event rate. No new maximum creator-rate check is justified.
* Native settlement `[0x83c00,...]` and0x97930 helper: the input is curve payment plus combined buyback, funded once via System before direct curve debit/recipient credit. Source mutable lamport borrow ends before destination read, preserving alias behavior. ArithmeticOverflow is a genuine ProgramError here, not Pump6024. The rent transfer above is earlier and independent. CPI/borrow failures propagate. Event failure prevents successful exit, under normal transaction rollback semantics.
* Events: `859b0.asm`, `81aa0.asm` and inherited serializers bind first-leg Trade, Complete, then residual PostComplete. Same timestamp, first reserves, four volume metadata fields, creator accrual after both legs, creator rate and holder mask are retained. Complete flag follows Trade CPI. B≥D and T+q2 checks follow Complete CPI. Wire sizes in the ordinary empty-shareholder domain are390/144/232 bytes, with an extra eight-byte self-CPI prefix. No name is invented for the trailing ordinary zero.

## Locked API, borrow and serialization assessment

The immutable Cargo.lock resolves Anchor lang/spl0.31.1 with syn/event/error derivation0.31.2, AccountInfo2.3.0 and ProgramError2.2.2. Cargo.toml enables event-cpi and init-if-needed. The additional Anchor0.31.1 archive is SHA-bound to the lock; only context/lib members were opened for the dispatcher API. No installed cache or network dependency was consulted.

`BuyFeeConfig` satisfies Clone, Owner, AccountSerialize and AccountDeserialize for boxed Account. Explicit Discriminator is supplied. Its serializer writes real fields, despite readonly foreign exit not using it. Not advancing the deserialize input cursor does not invalidate Account::try_from, which does not consume another account from the same buffer. Unchecked deserialization deliberately retains validation and is not used for fee initialization. Cursor increments stay within the slice; table allocation failure remains a bounded runtime premise, not a recovered application success.

Disjoint `ctx.bumps` access while `a=&mut *ctx.accounts` is live is plausible; the typed curve borrows end before their conflicting mutations under normal Rust nonlexical lifetimes. TransferChecked's account clones and signer-seed arrays live through each immediate CPI call. No returned reference to a temporary is apparent. `buy_emit_cpi` accepts an AccountInfo reference; the locked event_cpi attribute actually appends AccountInfo fields. Its bytes equal EVENT_IX_TAG_LE followed by Event::data; program ID, one readonly signer meta, account slice and PDA seeds agree with the locked emit_cpi expansion. The helper clones the authority later than the macro (after serialization), so only under successful bounded reference-count/serialization premises is that rearrangement equivalent. It is not a raw call-tree or exceptional allocation identity claim. The log still serializes a clone and self-CPI serializes the event again, matching two separate serializations; no required program account was accidentally omitted from the CPI relative to the locked macro.

The new dispatcher fragment explicitly imports `anchor_lang::Bumps`, which is not in this version's prelude. `Accounts::try_accounts` requires the raw slice lifetime `'info`; Context::new separately permits a short mutable borrow of the local admitted structure. Bumps move into Context after parsing, then the same structure exits after the body releases its borrow. This avoids simultaneously retained old/new curve snapshots. These are source/API checks only: macro expansion, compiler acceptance, stack/code generation and runtime behavior have not been tested. I found no defensible definite compile error in the original composed files from this static review; that is not a passing compile.
