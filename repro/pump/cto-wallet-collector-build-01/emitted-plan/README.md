It is a plan, not a completed emitted-code review. No candidate analysis, original read, compiler, runtime, target, VM or rerun was performed while preparing it. ## Frozen methods and exact delta

`method-bindings.json` pins every copied prior method and admitted control. The prior `elf_reader.py`, `layer_inventory.py`, reference Elf class and renderer are exact copies. The historical `full_inventory.py` is retained solely as an audit witness: **do not execute it**. It opens the original ELF and would decode original bodies, contrary to this plan's bounds. Historical emitted analyze/verify drivers are also audit witnesses and retain old fixed addresses; do not run them against the new candidate.

`metadata_join.py` adapts the old inventory driver to join the newly parsed candidate against the saved **1,035 original metadata windows**. Original window hashes, normalized hashes, sizes, relocation patterns, call and branch records come only from the retained old gzip inventory. Candidate Elf/windows/enrich/coverage methods remain unchanged. Size + normalized-hash + relocation-pattern matching stays the same; the call-consistency fixed-point loop is copied byte-for-byte. `verify_plan.py` checks that loop's exact inclusion, plus seals and syntax, without running an analysis.

The adaptation intentionally does not compute new original positional differences, near-pattern hypotheses, original pointee previews or section byte differences. Those require original bytes absent from the retained metadata. Raw-body hash equality is labeled separately from a fresh direct byte comparison. Original bytes remain unread. Whole-file equality is false if the recorded original size differs; otherwise it remains unknown. Normalized/call-pattern relationships remain structural hypotheses, with semantic equivalence and transitive data equality unset.

`candidate_bodies.py` replaces the prior emitted driver's 23 fixed addresses and hard-coded anchors with the same 23 logical symbol names, normalizing only the Rust symbol hash suffix, plus the optional new `collect_wallet_creator_fee` symbol. It uses the exact old reference Elf/renderer. It annotates actual candidate callee names from the symbol table but performs no recursive callee expansion. Missing/renamed/inlined helper symbols are reported, not silently accepted. Only complete candidate bodies are rendered. The 35 previously admitted original text bodies are copied exactly for manual comparison; no original body or callee is extracted.
