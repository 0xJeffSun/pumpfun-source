## R1 — Missing checked call before direction selection

Affected proposal location: `sources/proposed.rs:265`, between `admit_vaults(&h)?` and `let buy = ...`. The original ordinary route has this additional operation:

* `0x5c480..0x5c498` loads the fee flag, masks bit 0 and saves it. The `jeq` at `0x5c498` has signed instruction displacement `0x25`; its actual destination is **0x5c5c8**, not the annotation's `.text+0x5c4a8`.
* With bit 0 set, `0x5c4a0` loads `r3=*(A+0x38)` — the raw writable buyback slot. `0x5c4a8` loads the Global wrapper through A+0, and `0x5c580` advances that pointer by 8 to decoded Global. A is restored from `F-0xa48` on both quote-vault continuations at `0x5c0c8` and `0x5c460`.
* `0x5c4b0..0x5c500` copies the quote-mint key into `F-0x260`; `0x5c508..0x5c548` copies the selected quote-program key into `F-0x6d0`. The latter is not a threshold: the preceding program-selector result is saved into `F-0xac8` at `0x5bd10`; that slot becomes arithmetic data only later.
* Outgoing stack `-0x1000` points to the quote key, `-0xff8` to the program key. `r4=0` at `0x5c5a0`. `r1` points to `F-0x888`; r5 is the caller frame.
* Call bytes at `0x5c5a8` are `85 10 00 00 dc 43 00 00`. Signed relative decoding gives `0x5c5a8 + 8 + 8*0x43dc =` **0x7e490**.
* `0x5c5b0` reads the result tag. `0x5c5b8` branches on tag !=2 to **0x5cc50**, which forwards the error payload into the existing error-return path. Only successful completion continues into quote-first direction comparison at `0x5c5c8`.

The proposed file has no operation at this point other than vault admission and direction choice. Its later buyback transfer cannot replace the omitted call: it runs after arithmetic, input, reserve stores, optional final output and accrual, and it skips zero buyback. The original call is controlled by flag bit 0 even before the fee amount is known. Neither `UncheckedAccount` nor an eventual Tokenkeg CPI proves that it succeeds or is effect-free.

The callee's body is **absent from the retained route instruction ledgers**. I did not widen the allowed windows to read it. Its argument pattern suggests a recipient-related operation, but no owner, mint, membership, creation or token-account predicate is asserted here. Slot 7 remains only present+writable at context admission. In particular, root review's qualification of the older native report does not authorize deleting later body operations.

**Required correction:** recover or explicitly import the exact checked dependency at this source position, preserving bit-0 gating, argument identities, successful tag and early error propagation. A success-only ordinary theorem may instead state the explicit premise that this call succeeds with no relevant effects, but that premise is currently unproved and cannot justify a complete implementation/build recommendation. Do not silently implement it as `Ok(())`, insert a guessed token constraint, or reject all bit-0 flags. `preflight-fragment.rs` supplies only the supported control-flow composition; it is not a drop-in route replacement. No defensible complete source correction patch for the callee can be derived from the available windows.

## APIs, types and lifetimes

No concrete Rust type error is established by this review; no compiler was invoked. `RouteFeeConfig` has Clone, Owner, AccountDeserialize and a read-only AccountSerialize implementation, wrapping the frozen AnchorDeserialize FeeConfig with the exact field order. `AccountSerialize`'s default behavior is acceptable only because this foreign-owned account is read-only and not a route output. This is a dependency-interface premise, not an assertion that macro expansion was inspected from cache. The proposal retains Box<Account<...>> and InterfaceAccount APIs already used by frozen source. Field `.0` uses autoderef to the wrapper; it is not a serialized byte offset.

The explicit `Context<'_, '_, 'info, 'info, ...>` allows each five-account parser to borrow the remaining slice for `'info`. `PreviousHop` stores owned AccountInfo clones and Pubkey/u8 values, not references to the local `h`, mint key or bump arrays. Seed slices are consumed synchronously by invoke; no temporary seed reference escapes. The temporary BTreeSet is scoped to try_accounts, consistent with the frozen parser use. The immutable curve borrow ends before reserve mutation; the mutable borrow ends before subsequent to_account_info calls under nonlexical lifetimes. Each lamport RefMut temporary drops at its statement before the next read. These observations support plausibility, not compiled acceptance or framework byte identity.

Use of raw invoke instead of Anchor CPI wrappers matches the recovered info counts and metas. System has two metas (source signer+writable, destination writable), Tokenkeg transfer has source writable/mint readonly/destination writable/authority signer readonly, self buyback has event signer readonly plus curve and raw buyback writable, and event has only the event signer readonly. Program AccountInfos need not be appended merely because the builder's program ID is present; the original interfaces do not append them. Runtime executable lookup, privilege enforcement, ownership rules, PDA signing and external processor semantics are explicit imported premises.

## Build decision and retained limitations

Resolve R1 before recommending the single fixed build. Do not spend that build discovering a known missing application call. The required follow-up is bounded source/control-flow recovery of its already identified dependency, with a legitimate admission decision for any additional body window, not compiler variation or runtime probing. Its body may impose meaningful checks; this review cannot specify them.

The remaining uncertainties are not all build blockers of the same kind. Anchor/Borsh serialization and account API behavior, arithmetic runtime implementations, successful allocation, PDA derivation, Rent float behavior and runtime rollback can be explicit bounded premises of a natural source hypothesis. Exact allocator failure, formatting/diagnostics, clone/drop and serialized error ABI remain necessary for stronger all-input/byte claims. No need to prove every allocator to write a meaningful route hypothesis. R1 differs: a whole application-level checked operation was removed without a stated contract.

The ordinary successful domain requires pre-existing ordinary Tokenkeg mint/account layouts, supported curve decode/length, disabled excluded modes, positive reserves/divisors and strictly noncompleting buys. Alias/repeated-curve success, mixed direction, arbitrary interior native transitions, short layout resizing, completion, holder/cashback/Mayhem and Token2022/extensions remain outside certified behavior. Native endpoints and explicitly stored WSOL remain distinct. The loop has no recovered two-hop maximum, but removing the maximum does not prove every structurally valid route is executable within account/compute/runtime limits.

`FUTURE_VALIDATION.md` supplies prose-only normal-operation cases and exact existing harness integration points. Genuine captured AMM invocation must supply the global_config PDA signature; no direct PDA signer or patched caller is a substitute. No tests, runtime transactions, fixtures, SBF, build or typecheck were executed or generated. No parent source/configuration or old seal changed. No completion counts change: 140/150 bounded handlers and 0/4 whole-original equality remain historical checkpoint measures, not results of this review.
