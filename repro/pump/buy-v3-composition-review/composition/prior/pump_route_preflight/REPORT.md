## Recovered contract and integration

`0x7e490` takes an out-result pointer, decoded Global, raw buyback AccountInfo, a bypass scalar, and a frame whose -4096/-4088 slots point to quote mint and selected token-program keys. The only call to this helper in the admitted route body is `0x5c5a8`, with bypass scalar r4=0. The source specializes this path; it does not expose a guessed runtime mode switch. On the helper's other scalar branch, the same membership helper is applied directly to the account key; no claim about callers of that branch is needed here.

At `0x5c480..0x5c498`, bit0 alone gates the preflight. The skip destination is `0x5c5c8`. The Global wrapper is advanced by eight; slot A+0x38 supplies the raw writable recipient; the quote key and selected program key are copied to caller stack locals. `0x5c5a8` is a signed register-relative call to `0x7e490`. Neither direction, protocol amount nor buyback amount exists yet. The correction is immediately after `admit_vaults(&h)?`, before `let buy`. The preceding ordinary mint fences identify the selected key as `a.token_program.key()`; this is not a claim about Token-2022 selection.

ATA membership is of the decoded **token authority**, not the account address, user or curve. Native stored-zero routes still pass the quote mint key (WSOL) and scalar zero, so they use this token-account path too.

## Data identity and complete error propagation

Membership reads decoded Global bytes [0,256), eight 32-byte keys; it reads no fee basis points. The allowed Global serializer passes wrapper+8 at 0x7570–0x7590 to the eight-key serializer 0xf6c0. This follows cashback and precedes buyback_basis_points; the wire array occupies bytes [741,997), including the account discriminator offset convention in the retained wire ledger. This binds the field to `Global.buyback_fee_recipients`, rather than assuming Rust field declaration order equals in-memory order.

The raw165 decoder loads mint from serialized [0,32) and authority from [32,64). It also consumes the ordinary 165-byte token state for validity; amount and optional fields are decoded, but the preflight imposes no additional business conditions on them. At 0x7ecf0–0x7ed28 the four authority words are copied to F-0x208. The ordinary decoder's result tag at +0x88 uses 2 for error, unlike the enclosing Result<(),Error> tag2 success; these discriminants must not be conflated.

Borrow failure at 0x7e880 goes to 0x7eac0, which converts ProgramError through 0x19bbb8. Decoder error goes from 0x7e900 to 0x7ecc0, drops the successful data borrow and forwards its existing error pair. Mint mismatch joins the same borrow cleanup. Membership failure at 0x7ed88/0x7ed90 goes to 0x7eff0, taking the payload at F-0x260. Owner mismatch and ATA mismatch also join the shared return at 0x7eb10. The out pair is written at +0/+8 and exits at 0x7eb28; success writes tag2, with payload irrelevant. All branches, including diagnostic construction and the scalar bypass, are present in the complete local CFG ledger.

The route reads this tag at 0x5c5b0. Tag!=2 jumps to 0x5cc50, loads payload F-0x880, and jumps to 0x5c1f0. It writes the unchanged error pair into the route result at +0/+8, marks route result byte +0x5a=2, releases owned references, and exits at 0x5b768 (the cold cleanup at 0x5f678 joins that exit). No direction/arithmetic/input transfer follows that error. Rust `?` implements this composition; framework wrapper propagation/transaction rollback remain explicit premises, not a new execution claim. Earlier route preparation can already have effects; this helper's failure does not locally undo them.

## Source API review and premises

The original proposal imports `AccountInfo`, `AccountDeserialize`, `require_keys_eq!`, `require!`, and `Global` through existing imports. Anchor 0.31.1 is pinned; anchor-spl includes associated_token and token_2022. The correction uses the same `TokenAccount::try_deserialize` and ATA API as `admit_vaults`, and adds `require_keys_neq!` from Anchor's prelude. `TokenAccount.owner` denotes token authority; `AccountInfo.owner` denotes owning program. `&a.global` dereferences Box<Account<Global>> to Global. The AccountInfo temporary and temporary Pubkeys live through the synchronous helper call. The data Ref is confined to a block, remains live through the mint comparison, and drops before membership/ATA. No Ref survives into later CPIs. No mutation of Global or the raw account is needed.

All ordinary helper callsites in the proposed route were reviewed for interaction: preparation and vault admission precede preflight; direction/fee arithmetic and `route_input` follow it; reserve stores and optional final `checked_transfer` remain later; native_buyback or quote checked_transfer still uses the same raw recipient and retains its zero-amount behavior. That later transfer is not substituted for validation. Event emission and curve exit still follow settlement. All new symbols already exist in the bounded Global/error declaration or pinned framework API. This is a source review, not typechecking or compiler acceptance.

The natural hypothesis is restricted to ordinary 165-byte Tokenkeg recipient accounts. Its explicit length fence is a reconstruction boundary and can change errors outside that domain; it is not recovered original policy. Token-2022/extensions, short curve layouts, completion and excluded modes/handlers remain outside scope. Framework ordinary token decode, deterministic PDA derivation, normal allocation, borrowed-account API semantics and runtime rollback are imported. Exact historical names, diagnostic source coordinates, serialized error ABI equality, compute cost, resource exhaustion and whole-program identity remain unproved. Existing route proposal obligations beyond R1 are inherited unchanged. The next authorized build must still validate compilation and normal routes; no builds, typechecks, target code, fixtures, transactions, probes, networks, signatures or parent edits occurred here.
