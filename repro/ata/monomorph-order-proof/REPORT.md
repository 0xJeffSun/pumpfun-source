# ATA RawVec order: static provenance proof

The exchanged functions are `alloc::raw_vec::RawVec<u8, alloc::alloc::Global>::reserve_for_push` (352 bytes) and `RawVec<solana_program::instruction::AccountMeta, Global>::reserve_for_push` (440 bytes). This identifies a concrete metadata-sensitive ordering dependency; it does not recover the uploader's unit graph, compiler metadata argument, or mangled symbols.

## What survives and what is missing

Both stripped files contain `.text`, `.rodata`, `.data.rel.ro`, `.dynamic`, `.dynsym`, `.dynstr`, `.rel.dyn`, `.shstrtab`, with no `.symtab`, `.strtab`, `.rustc` or debug sections. All eleven nonempty dynamic names agree and are external Solana/abort entries or entrypoint/custom_panic. Neither the mangled reserve names nor literal RawVec/reserve_for_push/AccountMeta/spl_token_2022/metadata= occur as strings. Machine code, body ordering, addresses, calls and relocation positions survive; historical mangled suffixes and Cargo/rustc metadata arguments are not retained as named symbol/debug metadata. This inventory does not establish source absence.

Missing discriminating inputs are an authentic uploader rustc invocation/unit graph or corresponding unstripped object/rmeta from the actual build, plus complete tool/link provenance. Current archive controls prove the mechanism and types without supplying those historical inputs. Native fingerprint JSON is retained as a cautionary negative witness: its `metadata` integer hashes manifest descriptive fields (Cargo fingerprint.rs540–544,1320–1321), **not** compiler `-Cmetadata`. Do not reinterpret it as the unit disambiguator.
