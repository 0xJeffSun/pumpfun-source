# Contracts and compatibility evidence

`developer.openapi.json` is the original public specification. Generated TS types live in `packages/backend/src/generated/`. The 67 public developer operations do not cover the website API.

`internal-operations.json` contains 330 strict static operation candidates with provenance; `internal-route-candidates.json` retains broader regex leads and false positives. Neither is a runtime capture or complete API specification. Many operations are privileged, excluded or shared. Do not probe them automatically.

`public-fixtures.json` contains a dated public price response for an explicit local test path (`/services/frontend/sol-price`). It is historical data, not a live quote. Registration accepts GET/HEAD records with a local absolute path, a separate plain query object containing only string values, an HTTP status from 100 through 599, a non-empty provenance source and an optional plain response-header object containing valid HTTP field names and string values. Invalid records and duplicate canonical method/path/query keys fail before the server is constructed. Fixtures for the built-in `/health`, `/__reconstruction/status` and `/__reconstruction/openapi.json` paths are also rejected, regardless of method casing or query parameters, because Fastify's GET and automatic HEAD handlers make those recorded responses unreachable. Replay preserves valid headers and JSON scalar bodies; duplicate incoming query keys and unmatched requests return 501. This fixture mode does not implement authentication or writes and is not native API compatibility.

Every fixture must explicitly provide `body`; use `null` for a JSON null body. Missing or `undefined` bodies fail registration instead of silently replaying an empty successful response. Fixtures for statuses that cannot carry a body (1xx, 204, 304) must use a `null` body; any other body fails registration because replay could never deliver it.

`developer-bindings.json` binds documented developer operations, one scope at a time, to the captured site's `publicRead` route-contract literals. It currently covers the 11 `leaderboards.read` operations. Each entry cites a spec JSON pointer, the captured object's manifest SHA-256 and the UTF-16 range of its `publicRead` literal, plus any `internal-operations.json` client call sites. One captured `leaderboards.read` route missing from spec 0.294.0 is listed under `observedNotDeclared` and stays outside the 67-operation denominator. Contract-bound does not mean implemented or qualified. It does not bind the origin of website calls or earn feature-milestone credit, and no network request was made. Verify with `python3 scripts/verify-bindings.py`.

`routes.json` defines product scope; `coverage.json` records implementation status. Native API operations and visual/behavior-qualified frontend routes remain zero.
