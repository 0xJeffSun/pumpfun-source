# Mayhem same-IR host LLVM comparison

Mac and Linux v1.54 LLVM 20.1.7 generated identical 1,096,664-byte relocatable objects from one saved compiler-emitted IR input. Both object hashes are `5a933121645fcb08c822bde8dce55051ea803e75af5287ec2b5afb3be354f544`; input SHA-256 is `ca8cc7e10774da9acb15ef872539b54dc121ed502b23eaf7b949e283643f9347`. One compressed object is retained because the outputs are equal.

This result rules out host backend lowering as the explanation for this particular IR. It does not compare Rust frontend execution, reproduce a linked program, recover an original function, or improve original ELF identity. The initializer remains unresolved. The IR comes from the earlier initializer key-snapshot control whose linked candidate hash is `0580f26842755b8466cfa2c3e8b60ccdaca29e2c9b4e847b8381cdadd567c268`; it is not relabeled as IR from the current provider-sharing checkpoint. The `-O2 -filetype=obj` diagnostic is not the release Rust build pipeline.

`artifacts/input.ll.gz` preserves the complete unchanged input; `artifacts/object.o.gz` preserves the common output. Captured commands, status, compiler hashes, target versions, guest-library hashes, and memory/disk observations are in `captured`. The 66-input source archive and the earlier compiler-emission receipt provide the recorded origin of the IR; this read-only packet does not rerun that compiler. Source and compiler license notices are retained in `licenses`. No compiler binaries are redistributed.

Only the dedicated task VM `mayhem-accounts-linux154` was created, started and stopped, with the task work directory as its sole configured shared mount. Minimal amd64 dynamic libraries and the pinned Linux `llc` were used under Rosetta. Shared VMs and global toolchains were untouched. The guest is stopped. Peak observed task VM disk allocation including shutdown was 1,410,994,176 bytes (the earlier comparison receipt reports the 1,269,321,728-byte pre-shutdown peak); minimum observed free space was 22,582,726,656 bytes, above the 2GiB floor. Failed first extraction and apt-lock attempts and successful retries remain distinct in the captured records.

Run `python3 -B verify.py` and `python3 -B test_scope.py` from this folder. The six mutation controls include changed IR, object bytes, command input, source input, identity claim and an unlisted nested manifest. Verification reads compressed evidence and validates hashes, source inputs, commands and receipt boundaries; it does not compile, execute a target or contact a VM. To repeat lowering with separately verified tools, decompress the same IR and run each recorded LLVM executable with `-O2 -filetype=obj INPUT -o OUTPUT`, then compare the complete output bytes.
