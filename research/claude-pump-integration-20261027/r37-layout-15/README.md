Composition was a per-file three-way merge (`git merge-file`) of each delivery's crate snapshot against the base it was made on, followed by explicit conflict resolutions (scripts in `tools/`):

- `r5-z00-03` and `r5-z09-01` are contained in `r5-z07-03` (identical files / strict superset).
- `r5-libinst-06` and `r5-z08-03` both moved the Token-2022 `Fee` helpers into a separate dependency crate (the original links such a crate between pump's allocator shim and anchor_spl). The package keeps one crate, `programs/pump/pump-token-ext` (relative path dependency inside the crate dir): libinst's `Fee` + `quote_extensions_supported` with z08's `TransferFeeConfig` / `get_transfer_fee_config` (the `Result<Option<..>,()>` shape z08's `get_transfer_fee` needs).

## SYNTHETIC LINE POSITIONING (read this first)

Like L12, this is a **layout composite**: `// layout-pad` blank-line blocks hold each `error!`/`require!` Source site on the line the original binary records, and the round-5 / mega deliveries were made with line-neutral editing on that layout. Deliveries marked "yes" above added or re-laid pad lines (or placed helper functions inside pad blocks / after an end-of-file pad block) to put their own sites on the original lines. **0x178e0** (buy_v2.rs:983, r5-coord-03) is a *placement-only* match: the creator-fee ceil fee's error closure is emitted from an `#[inline(always)]` nested fn on line 983, where the original has the closure of a different op (a second `u64::try_from(tokens_for_quote(..))` that this source does not implement); values and error codes are unchanged, only the reported Source line of that (unreachable for bps <= 10000) Truncation error moves. Treat it like the other synthetic positions.
