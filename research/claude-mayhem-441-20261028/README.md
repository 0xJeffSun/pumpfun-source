# claude-mayhem-441-20261028

This packet reaches **441/441 normalized and 441/441 raw-local windows** for the captured Mayhem image. It closes **O0083**, the `BuyV2` handler (original start 140512, 18,648 bytes), and **O0084**, the `SellV2` handler (original start 159160, 18,096 bytes). A target-derived generated link script then puts the matched functions and data objects at their original addresses. These are candidate code/window-coverage results, not proof of the historical source or build recipe.

**The whole ELF is not yet identical.** The stripped candidate is 775,416 bytes; the deployed program image is 777,408 bytes, of which the last 1,992 are zero. The candidate matches those first 775,416 bytes except for **30 bytes**, which are all the dynamic-symbol order of `sol_log_data` and `sol_memcpy_`:
- `.dynsym`: 1 byte;
- `.dynstr`: 20 bytes;
- `.rel.dyn`: 9 bytes.

Everything else is byte-identical:
- the ELF header and program headers;
- all 9 section headers;
- `.text`, `.rodata` and `.data.rel.ro`;
- `.dynamic` and `.shstrtab`.

## Source changes
Changes are Rust source in six files, plus a target-derived linker script; executable bytes are not patched after linking. Existing inferred inline attributes and deliberate blank-line/source-coordinate budgets remain in the source. The finite runtime matrices below match the original under their stated comparisons. They do not establish exhaustive behavioral equivalence or authenticate the historical source layout.

### O0083 and O0084, the v2 trade handlers (lanes mg-M-o83b, mg-M-o84b, mg-M-o84c, mg-M-o83c)
- **`state.rs`:** the trade-size cap moves behind a small `TradeCap` trait.
  - `&u64` keeps the legacy late `min`, so O0081 and O0082 are unchanged.
  - `QuoteCap { global_params, quote_mint }` applies the v2 cap early. It compares `quote_mint` against `native_mint::id()`.
  - `initial_trade_output` reads `real_sol_reserves` before the early cap. It recomputes the retained basis points after it.
  - `buy_amounts` and `sell_amounts` become generic over the cap.
- **`pump_interface_v2.rs`:**
  - `buy_v2_handler` now lives next to `sell_v2_handler`, and `lib.rs` routes `buy_v2` to it.
  - In both handlers the event values use **deferred initialization in one `if native { … } else { … }`**: the `let x;` declarations come first and the arms assign them.
  - Why this closes them: rustc then emits the event-join phis in reverse declaration order, which is the original's order. The IR proof is in `notes/mg-M-o83c-BEST-NOTES.md`: rustc's IR with only the phi order changed gives an exact `llc` result.
  - In `buy_v2_handler`, the event literal lists `end_timestamp` before `virtual_tokens`.
  - The file goes from 605 to 600 lines. The Source-pinned lines stay at their original numbers: `buy_v2` at 393:25 and 394:26, `sell_v2` at 591 and 592.
- **`buy_v2.rs`:** the old `handler` and its `math` helper (27 lines) are removed, because `lib.rs` now routes to `buy_v2_handler`. The file keeps its 119-line length as blank lines. No code follows them, so they do not affect the build.

### Raw layout (lane mg-M-raw)
- **`builds/ordered.ld` (1,276 lines):** the build's linker script. It lists:
  - `.text` input sections in the original window order (27 windows had fallen into the qualified438 script's `*(.text*)` catch-all);
  - explicit `.rodata` and `.data.rel.ro` lists in original object order, including the merged constant sections at their original positions.
  - It was generated by `layout/tools/gen_ordered.py` and `datamap.py` from a first build of this source. Both are kept here for provenance.
  - On its own it gives raw 434. The rest is the order of merged constants, which only source order controls, so three line-neutral edits follow.
- **`lib.rs`:** `pub mod instructions;` is declared before `pub mod state;`, which is the original's codegen order.
- **`extend_account.rs`:** `handler` moves into the blank lines above `account_size`. `account_size`'s line-dependent sites keep their lines.
- **`burn.rs:78`:** `require!(end_timestamp <= now, MayhemModeNotEnded)` becomes `if end_timestamp > now { return Err(error!(MayhemModeNotEnded)); }`. The line, check and error are the same; only the constant emission order changes.

### Remaining 30 bytes
lld names syscalls in first-reference order. In this link, both syscalls are first referenced by the `anchor_lang` rlib member, and that member's symbol table lists `sol_memcpy_` before `sol_log_data`. The original has the opposite order. Every `anchor_lang` build checked so far has the same order. The fix needs the original's dependency object or reference order, not a change to `.text` or data layout.

## Build
`builds/crecipe.py` (clean build) and `builds/rbuild.py` (repeat) replay the qualified438 root recipe:
- a root-only `rustc` compile against the hash-pinned qualified434 dependency rlibs;
- only paths differ, and the command is checked argument for argument;
- the link swaps in `builds/ordered.ld`.

Two builds give the same stripped `380157fa…` and symbols `5fda6745…`. One used the shared dependency cache. The other used a fresh source copy and a separate cache clone. Like the parent's builds, these are not fresh dependency builds. The lane's own build of the same tree gave the same bytes.

    python -B research/claude-mayhem-441-20261028/verify.py
    python -B research/claude-mayhem-441-20261028/test_verify.py

What the scripts cover:
- **`verify.py`**:
  - It rebuilds the parent tree from the qualified438 archive plus the 439 packet's files, and checks it against the parent inventory.
  - It checks `source.patch` and `sources/source.tar.gz`.
  - It checks the build records against the qualified438 recipe and `builds/ordered.ld`.
  - It recomputes the full 441-window census, the O0083 and O0084 bodies, and the per-section whole-ELF comparison from ELF bytes.
  - It recomputes every runtime count from the saved per-case outputs.
- **`test_verify.py`:** counterexample tests that must be rejected.
- Inventory validation rejects symlinks and special files before reading even `SHA256SUMS.txt`; root-manifest symlink/FIFO controls assert that no file contents were read.
