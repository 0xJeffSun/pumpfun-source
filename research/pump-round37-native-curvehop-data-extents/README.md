# CurveHop argument extents on PR345's 752-window native composition

Binds all twelve relocated operands of the 3,512-byte matched CurveHop body to their explicit finite argument extents on the exact PR345 symbol ELF. Ten `Error::with_account_name` calls receive r4 pointer / r5 counted length; the first PDA seed descriptor stores `bonding-curve` / length 13 in a two-element seed slice; `memcmp` receives the same 32 literal bytes through r2 / r3. Original/candidate complete normalized bodies and all 33 same-offset immediate callee bodies are independently rechecked using the unchanged normalizer. No body gain, source/build change or new VM execution.

PR342 already qualified the analogous twelve extents on its separate ordinary SBF artifact. Credit stays there and with PR323; this is qualification of PR345's separately compiled native SBPF composition. The complete input ELF bytes are preserved in gzip and authenticated. Both symbol files in PR345's repeated builds were already byte equal; this audit uses that exact one identity, not a new build.

The checks establish the explicit instruction-level counted arguments and descriptor bytes, under the existing ABI interpretation. They do not prove arbitrary callee read semantics, dynamic second-seed contents, transitive/indirect/data closure, reachable execution of every error branch, historical spelling, or whole-program identity. Adjacent bytes beyond the declared extents are deliberately excluded. No source-coordinate or module-path recovery is performed.

Run `python -I -B verify.py` and `python -I -B test_scope.py`. This self-contained stdlib packet needs no Git, network, SDK, VM or outside fixture. Twelve actual in-extent mutations, four explicit length/slice mutations and a wrong-pointer mutation are rejected; a byte immediately outside the mint extent is accepted by the bounded comparison while changing the whole hash. Optimized Python is rejected. Whole core identity remains 0/4. Existing runtime claims belong only to PR345's original 199 pairs and are not rerun or enlarged here.

Preparation: an initially transcribed mint hex literal had one extra zero; the guard rejected it before any accepted report. The literal was corrected to the actual full 32-byte original/candidate extent. No captured byte, source, normalizer or acceptance rule was changed.
